# BUG-0012: どこからも飛ばれない合流ブロックの引数が LLVM IR で未定義になる

- 状態: done
- 重大度: major
- 発見箇所: BUG-0011 (Core 簡約器の変更後、`tests/achc/run/h2/ffi.hs` と `prelude.hs` の `-O2` ビルド)
- 関連: BUG-0011

## 現象

MIR の合流ブロック (引数を持つブロック) に、どこからもジャンプしないもの (`panic` の後の合流など) があると、
LLVM バックエンドがその引数を定義しない。ブロックの中で引数を使う命令 (Perceus が入れた `drop` など) があると、
clang が `use of undefined value '%vN'` で失敗する。

## 再現手順

```
fn main() -> i64 {
entry:
  ret 0
dead(x: i64):
  ret x
}
```

## 期待される動作

到達しないブロックはそのままコンパイルされ、実行に影響しない。

## 原因

`cirka-codegen-llvm` は合流ブロックの引数を、そのブロックへのジャンプから集めた phi で定義する。ジャンプが 1 つもないと
phi が出力されず、引数が未定義のまま使われていた。

## 修正

- [x] 回帰テストを追加 (`tests/mir/run/dead_join.mir`)
- [x] 修正: 引数を持ち、どこからもジャンプされないブロックは本体を出力せず `unreachable` にする

## メモ

BUG-0011 で 1 回だけ使われるラムダをラムダの中へ移すようにした結果、`panic` の後の合流ブロックが残る形が現れて発覚した。
