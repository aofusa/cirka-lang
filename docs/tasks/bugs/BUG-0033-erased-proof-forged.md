# BUG-0033: 消去される位置の証明を `panic` や全域でない関数で作れ、型の変換でメモリ安全を破れる

- 状態: done
- 重大度: critical
- 発見箇所: FEAT-0260 (能力を偽造できないことの確認)
- 関連: FEAT-0231, FEAT-0260

## 現象

多重度 0 の位置 (消去される引数・`let 0`) に書いた式は実行されないので、`panic` や止まらない関数で偽の命題の「証明」を作れる。
`primRewrite` (`rewrite`) に渡すと型を変換でき、`Int` を `String` として読んでメモリを読み出す。

```
coerce : Int -> String
coerce n = primRewrite (\t => t) String Int (panic "forged") n

main : IO ()
main = putStrLn (coerce 42)      -- 42 番地からの「文字列」を表示する
```

`let 0 p : (String = Int) = panic "no"` も同じ。spec-v0.0.4.md §2.4 は「証明は全域でなければならない」とするが、
検査は結果が等式か `Void` の **定義** (E0506) だけで、式の中に直接書いた証明・全域でない多相な関数 (`partial` の `head` を
`{a = String = Int}` で使う)・実行時の関数の値 (`f ()`) の適用・トレイトの引数のメソッドは検査されない。

能力 (FEAT-0260) も `primRewrite` で `()` から作れてしまう。

## 再現手順

```sh
cirka run forge.cirka     # 上のプログラム。cirka check はエラーを出さない
```

## 期待される動作

消去される位置の値の式が全域でなければ、コンパイル時のエラーにする。実行時の `let` (多重度 1・ω) の値は実行されるので
(`panic` なら変換の前に止まる)、従来どおり許す。

## 原因

消去される位置の式は実行されないのに、全域性を問うのは型の中の関数 (E0505) と証明の定義 (E0506) だけだった。

## 修正

- [x] 回帰テストを追加 (`tests/cirkalang/fail/proof/erased_*.cirka`、`--contracts` によらない)
- [x] 定義の本体の消去される値の位置 (型ではない位置) で使う大域の関数・`panic` を記録し、`cirkalang-check` で全域性を問う (E0507)
- [x] 消去される値の位置での実行時の関数 (外側で多重度 1・ω で束縛した局所変数) の適用と、トレイトの引数 (辞書の引数) のメソッドを E0507 にする
- [x] spec-v0.0.4.md §2.4 と 13-verification.md に規則を書く (ADR-102)

## メモ

- 判定: エラボレータが **消去される値** の範囲 (多重度 0 の位置のうち、期待する型が宇宙でも宇宙を返す関数でもないもの) を追う。
  `let 0` の値は外側の多重度で検査して使用量を 0 倍するので、明示的に範囲に入れる。型を推論する位置 (`rewrite` の証明など) は、
  結果の型が宇宙なら記録を取り消す。型の中の関数は E0505 が全域性を問うので、記録するのは定義の本体だけである。
- 全域性の判定は E0506 (証明)・E0504 (`total`) と共有し、それらで報告した関数は重ねて報告しない。
- 既存のテスト・ベンチ・ライブラリには E0507 は出なかった (偽の証明に頼るコードはなかった)。
- 検査の時間 (`cirka check`、release、ホスト): vulkan_compute 3.74 s → 3.71 s、proof_erased 0.076 s → 0.074 s (差は誤差の範囲)。
- 能力 (FEAT-0260) も、消去される位置ではこの規則で偽造を防ぐ (spec-v0.0.7.md §1.5)。
