# BUG-0041: テストハーネスにケースごとの時間とメモリの上限がなく、終わらない 1 ケースがホストのメモリを使い切る

- 状態: done
- 重大度: major
- 発見箇所: FEAT-0097 (`cargo test --test cirkalang` の実行中、BUG-0039)
- 関連: BUG-0039, FEAT-0004

## 現象

BUG-0039 (Core の最適化が終わらない) のとき、`cargo test --test cirkalang` の `cirkalang_run` は 1 ケース (`strings`) のワーカーが
12 時間止まらず、テストのプロセスがメモリを 24 GB (実メモリ 10 GB + スワップ 14 GB) まで使い続けた。ホストの空きメモリが 300 MB まで減り、
同じホストの他の作業も止まった。テストは失敗も報告せず、どのケースが原因かは成果物の時刻から推測するしかなかった。

## 再現手順

コンパイラ (または MIR インタプリタ、燃料は `u64::MAX`) が終わらないケースを 1 つ置いて `cargo test` を走らせる。

## 期待される動作

1 ケースが上限の時間を超えるか、テストのプロセスのメモリが上限を超えたら、走っているケースの名前を出してプロセスを失敗で終える。

## 原因

`cirka-testkit` の `run_cases` はケースを作業スレッドで順に実行するだけで、時間もメモリも見ていない (コンパイラとインタプリタは
プロセス内で動くので、ネイティブの実行と違って子プロセスを止めることもできない)。

## 修正

- [x] `run_cases` に見張りのスレッドを置く: ケースごとの実行時間が `CIRKA_TEST_CASE_TIMEOUT` 秒 (既定 1800)、テストのプロセスの
  実メモリ (`/proc/self/status` の `VmRSS`) が `CIRKA_TEST_MAX_RSS_MB` (既定は機械のメモリ (コンテナでは cgroup の上限が小さければそれ) の 4 分の 3) を超えたら、走っているケースの名前と上限を
  標準エラーに書いて `exit(1)` する (`.env.sample` に追記)
- [x] `scripts/memcheck.sh` は valgrind で遅くなるので時間の上限を 10 倍にする
- [x] 回帰テスト (`tests/harness_selftest.rs` の `run_limits_stop_runaway_cases`): 終わらないケース (眠り続ける・メモリを確保し続ける) を子プロセスで走らせ、上限で失敗してケースの名前が出ること
- [x] 10-testing.md に記載

## メモ

- 見張りは 250 ms ごとに、各作業スレッドが走らせているケースとその開始時刻、`/proc/self/status` の `VmRSS` を見る。作業スレッドは
  終わるとき (巻き戻しでも) チャネルの送り手を手放し、すべてなくなると見張りも終わる (ケースのない実行も待たない)。
- 上限を超えたときの出力は、テストのハーネスが溜める `eprintln!` ではなく標準エラーへ直接書く (プロセスを `exit(1)` で終えるので、
  溜めた出力は捨てられる)。
- 既定のメモリの上限を固定の値にしなかったのは、ケースを並列に走らせる数 (`CIRKA_TEST_JOBS`、既定は CPU の数) でテストのプロセスの
  メモリが変わるため: 4 並列の `cargo test --test cirkalang` で最大 2.0 GB だった。
