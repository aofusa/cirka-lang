# BUG-0040: 検証の反例が Z3 の実行時間で変わり、負荷が高いと `verify/fail/overflow` の期待出力と食い違う

- 状態: todo
- 重大度: minor
- 発見箇所: BUG-0038 (`scripts/memcheck.sh` の実行中。valgrind のテストでホストの負荷が高く、検証のキャッシュが空だった)
- 関連: BUG-0018, BUG-0038, FEAT-0005

## 現象

`tests/cirkalang/verify/fail/overflow.cirka` の `gcd` の停止性の反例が、期待出力の `a = 9223372036854775807, b = -9223372036854775808`
ではなく `a = -9223372036854775808, b = -9223372036854775808` になり、テストが失敗した。どちらも正しい反例
(`abs b` は `b` が最小の `Int` のとき負)。通常の負荷では期待どおりになる。

## 再現手順

ホストの CPU を飽和させた状態で、検証のキャッシュ (`_build/test-work/*/verify`) を消して `cargo test --test cirkalang cirkalang_verify`。

## 期待される動作

同じ問い合わせには、負荷によらず同じ反例を報告する。

## 原因

問い合わせは `-t:<CIRKA_VERIFY_TIMEOUT>` (壁時計の時間) だけで制限して Z3 に渡している。非線形の整数算術 (`abs`, `%`, `*`) の問い合わせに
Z3 が選ぶ戦略 (QF_NIA) は、SMT ソルバを壁時計の時間で区切って (`try_for`) 試し、間に合わなければ nlsat に切り替える。負荷が高いと
切り替わり、別のモデル (反例) を返す。

## 修正

- [ ] 回帰テスト
- [ ] 戦略の切り替えを時間に依存させない (資源の上限 `rlimit` で区切る、または反例を決まった手順で選び直す) 案を比べて直す

## メモ

- キャッシュに答えがあれば Z3 を呼ばないので、CI (キャッシュが温まっている) では起きにくい。
- 2 回目: BUG-0039 の確認で、新しい作業ツリー (キャッシュが空) の `cargo test` を 4 コアのホストで並列に走らせたときにも同じ反例になった。
  同じ問い合わせを負荷のない状態で 1 つだけ走らせると (キャッシュを外して `CIRKA_TEST_FILTER=overflow`)、期待どおりの反例に戻る。
