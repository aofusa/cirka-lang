# BUG-0030: 型が後で宣言する関数を使うと、診断なしに誤りの項になる

- 状態: done
- 重大度: minor
- 発見箇所: FEAT-0254 (`Data.String.toStr` の `ensures \r => length r == strLength s`)
- 関連: FEAT-0233, FEAT-0254

## 現象

関数の型シグネチャ (契約を含む) が、シグネチャがファイルの後にある関数を使うと、その関数の参照が誤りの項 (`<error>`) になり、
診断が出ない。型が他から決まる場合 (`length r == strLength s` の `==` は `Int`) はコンパイルが通り、検証で
`cannot prove the refinement `<error> == (strLength s)`` (反例 `<error> = 1`) と分かりにくい形で失敗する。
型が決まらない場合は、原因と関係のない E1254 (インスタンスが決まらない) になる。

## 再現手順

```
f : (x : Int) -> Int
  ensures \r => g r == g x
f x = x

g : Int -> Int
g y = y + 1
```

## 期待される動作

後で宣言する関数を型の中で使ったことを、その位置で知らせる。

## 原因

エラボレータはトップレベルの定義のシグネチャをファイルの順に検査する。まだシグネチャを検査していない大域の名前は型が分からず、
`infer` は誤りの項を返していた (誤りの項は、既に診断を出した印として、それ以上の診断を出さない)。
構成子の型 (不変条件) は、シグネチャの後でもう一度検査されるので後の関数を使える (spec-v0.0.4.md §4.2)。

## 修正

- [x] 回帰テストを追加 (`tests/cirkalang/fail/refine/used_before_signature.cirka`: 契約の中の後の関数は E1121、構成子の不変条件の中の後の関数は誤りでない)
- [x] 修正: 型の分からない大域の名前を E1121 (`` `g` is used before its signature ``) として知らせる。構成子の型の最初の検査では、
      不変条件を持つ構成子の E1121 を捨てる (もう一度検査するので)。Idris 2 と同じく、型の中では前に宣言したものだけを使える
      (関数の本体はどの関数でも使える)

## メモ

- `Data.String` は `length` を `toStr` の前に移した (FEAT-0254)。
