# BUG-0027: 残りの引数が 8 個を超える部分適用が C0200 になる

- 状態: done
- 重大度: major
- 発見箇所: FEAT-0251 (`Vulkan` の `cirka check`)
- 関連: FEAT-0251, FEAT-0250, FEAT-0255

## 現象

Core → MIR の変換で、既知関数の部分適用のうち残りの引数が 8 個 (クロージャがとれる引数の上限 `MAX_CLOSURE_ARITY`) を超えるものが
`error[C0200]: partial application of `f` leaves more than 8 parameters` になり、コンパイルできない。

- extern の関数で結果が `IO` のもの (`vkCmdPipelineBarrier` は引数 10 個) は、表現の関数 `f$rep` の部分適用を包む定義になるので、
  Core を最適化しない `-O0` と `cirka check` (FEAT-0255 以降は `-O` なしでは最適化しない) で必ず当たる。
- 利用者の関数でも、引数 11 個の関数を 1 個だけ適用した値をリストに入れるなどすると `-O0` で当たる (`-O2` では簡約で消えることが多い)。

## 再現手順

```sh
cirka run -O0 -L<dir> -lmany_params tests/cirkalang/run/v006/many_params.cirka
```

## 期待される動作

残りの引数がいくつでも部分適用をクロージャにでき、全部の引数を与えたときに元の関数と同じ結果になる。

## 原因

`cirka-mir` の `lower.rs` の `pap` は、`mkclosure` で関数と与えた引数を包むだけで、残りが 8 個を超えると誤りにしていた。
ラムダ (`lambda_closure`) は 8 個ずつのラムダに分けていたが、既知関数の部分適用には同じ扱いがなかった。

## 修正

- [x] 回帰テストを追加 (`tests/cirkalang/run/v006/many_params.cirka` と C ヘルパー: 引数 10 個の `IO ()` の extern 関数、
      引数 9 個・11 個の関数の部分適用をリストに入れて呼ぶ。`-O0` / `-O2`、インタプリタとネイティブ。修正前は `-O0` で C0200 になることを確かめた)
- [x] 修正: 残りが 8 個を超える部分適用は、次の 8 個の引数を受け取って残りのクロージャを返す関数 `f$cur<k>` のクロージャにする
      (それでも残りが多ければ同じことを繰り返す)。06-ir.md §2 に追記

## メモ

- `apply` は 8 個ずつに分けて呼ぶので、カリー化したクロージャもそのまま呼べる。`-O2` の結果は変わらない (簡約が部分適用を消すため)。
