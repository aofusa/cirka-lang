## 概要

`if a && b then X else Y` は `&&` をインライン化すると、条件が入れ子の `case` になる:

```text
let! s = case a of True -> case b' of {1 -> True; _ -> False}; False -> False
in case s of True -> X; False -> Y
```

Core の case-of-case は、内側の選択肢の返り値がどれも構築子 (let の下も含む)・リテラル・panic のときか、外側の選択肢が小さいときに
限って外側の `case` を内側の各選択肢に押し込んでいた。返り値が入れ子の `case` の中にあると「既知」とみなされず、`X` が大きいと
変換されない。MIR では `s` が静的な `True` / `False` のオブジェクトの選択になり、そのタグを読んでもう一度分岐する
(HTTP サーバの `startsWith buf "GET "`: `cmov` で 2 つの静的なオブジェクトの一方を選び、タグを読み取り専用のデータの行から読む)。

内側の返り値が入れ子の `case` の中まで含めてすべて既知の構築子 (か panic) なら、case-of-case の後は返り値ごとに外側の選択肢が
1 つだけ残る (case-of-known-constructor)。複製されるのは 2 つ以上の返り値が選ぶ選択肢だけなので、その大きさ
(Σ (選ぶ返り値の数 − 1) × 大きさ) が `INLINE_SIZE` 以下なら変換する。上の例では `Y` が `False` の数だけ (3 つ) 複製され、`X` は 1 つ。
入れ子の `case` の選択肢が線形のフィールドを束縛するときは行わない (既存の条件と同じ)。
