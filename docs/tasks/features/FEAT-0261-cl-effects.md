## メモ

- 設計 (spec-v0.0.7.md §2、ADR-104): 効果は `Eff es a` (型レベルのリスト `es` を行とするモナド) と末尾再開形のハンドラ。
  効果はハンドラ (操作の実装の組) の型で、`effect E ps where op : A -> R` が `data E ps = MkE (A -> IO R) ..` と
  操作 `op : Has (E ps) es => A -> Eff es R` に展開される (`cirkalang-syntax::effect`、名前解決の前)。
  ハンドラは `handle` / `handleWith` (`runIn` で外側の効果を使う) で置き、`runEff` で行が空の計算を実行する。
  標準の効果 `State` `Reader` `Writer` は `Std.Effect` にあり、`State` と `Writer` の状態はランタイムの可変のセルに置く。
- 推論: 所属 `Has e es` はコンパイラが解く。行の先頭が `e` なら `here`、別の効果なら `there` (効果の比較は同じ/違う/未定の三値で、
  剛な型変数を含むと未定)。`Has (State ?s) es` のように効果の引数が決まらないときは、行の中で同じ頭の最も内側の効果
  (または行の剛な末尾についての局所の `Has`) と単一化する (改善)。改善はリテラルの既定化の前に行い、未定から同じに変わったときだけ進んだとする
  (最初は改善が同じ制約を繰り返し単一化して、`runReader` の推論が止まらなかった)。
- 新しい診断: E1262 (行にない効果の操作)。E1122 を `effect` の誤り (操作の型注釈以外・同じ名前の操作・普通の矢印でない引数) に、
  E1259 を `Has` の実装に、E1254 を行の先に型変数の効果があって使うハンドラが決まらない場合に広げた (加えるべき制約をヘルプに出す)。
  診断の型の表示で、二項の演算子の適用を中置で書くようにした (行が `(:: f es)` でなく `f :: es` と出る)。
- 共通 Core の変換 (06-ir.md): ハンドラの選択は効果専用のパスでなく、フロントエンドに依らない一般の最適化で消す。
  aCHC の `Eff` (FEAT-0161) も、ハンドラのリストを受け取る `IO` の newtype にすれば同じ変換が効く。
  1. io-arity が `IO` の上の入れ子の newtype (`Eff`) を一度に展開する (`f$io x̄ ev w`)。
  2. 型の引数だけを取る多相な定数の辞書 `d @τ̄` (`Has` の `here`) も辞書の特殊化の対象にする。
  3. 静的な引数の特殊化 (FEAT-0061) を、呼び出し側で値が分かる構成子の引数 (ハンドラのリスト・辞書) に広げる。
     コードを含まない値 (`I# x` など) は対象にしない (既存の worker/wrapper のテストが壊れた)。
  4. `Any` に詰めた構成子 (存在型のフィールドに入ったハンドラ) を既知の構成子として扱い、λ に束縛した変数を評価済みとする。
     これで、操作の位置でハンドラの λ がβ簡約され、使われなくなったハンドラの確保が消える。
     特殊化で写しが増えたときは λ 持ち上げをもう一度行い、インライン化されない大きなハンドラを大域関数にする。
- コスト: `run/v007/effect_loop.cirka` は、ハンドラを名前で呼ぶ `effect_direct.cirka` と `-O2` の MIR が型の宣言と関数名を除いて同一で、
  確保・参照カウント・実行した命令・MIR の大きさが同じ (`same-cost-as`)。
  `bench/effects` (2 つの効果の操作を 1 億回、Docker、hyperfine 15 回): 効果 549.6 ± 12.4 ms、ハンドラを名前で呼ぶ版 668.9 ± 15.0 ms、
  Rust 674.9 ± 90.6 ms (ホストの別の負荷で Rust の揺らぎが大きい)。
  命令数 (callgrind、1000 万回): 効果 260.2 M、名前で呼ぶ版 330.2 M、Rust 250.3 M (効果の版は Rust の 1.04 倍)。
  名前で呼ぶ版が最初は 7 倍遅く、`do` の途中の `if` が動作をクロージャとして作る共通 Core の問題 (BUG-0034) が見つかったので直した。
  名前で呼ぶ版に残る差 (結合点で `()` を `drop` する) は FEAT-0089、aCHC で同じ形が遅い別の原因は BUG-0035 に分けた。
  BUG-0034 の修正で `linalg.cirka` の配列のコピーが増えた Perceus の問題 (読むだけのフィールドの借用がマッチしたオブジェクトを生かす) は BUG-0036 で直した。
  記録は bench-report.md の「効果のハンドラ」。
- テスト: `run/v007/effects.cirka` (State・Reader・Writer・ユーザーの効果・行の多相・`handleWith` で外側の効果を使うハンドラ・
  同じ型の State が二つあるときの内側・1 万回の操作)、`effect_files.cirka` (能力から作る本物のハンドラと、メモリ上の偽のハンドラ)、
  `effect_loop.cirka` / `effect_direct.cirka` (同じコスト)、`fail/effect/` (E1262・E1122・E1259)、`parse/effect.cirka`、
  `test/effects.cirka` (偽のタイマーのハンドラでテストする)、`fail/effect/ambiguous.cirka` (E1254)、
  `cirka-core` の単体テスト 5 本 (入れ子の newtype・多相な定数の辞書・既知の構成子の値の特殊化とその対象外・`Any` に詰めた構成子)。
- 対象外 (spec-v0.0.7.md §4): 継続を捕らえるハンドラ (例外・非決定性)、線形な値を取る操作・`IO1` の上の効果、純粋な実行、
  名前で操作の実装を書くハンドラの構文、関数の型ごとの効果の行の推論。
