## 概要

トップレベルの箱の値は CAF (初回の `force` で評価する静的なサンク) になる。FEAT-1004 はリテラルの定数を使う箇所で値に置き換えるが、
構築子の定数 (`noTimeout = 0 - 1` は `I# -1`) は分解される位置でだけ置き換える (写すと使うたびに箱を確保し、辞書のフィールドでは
原子でなくなるため)。引数として渡される位置では CAF のまま残り、受け取った側が `force` するたびに `cirka_force` を呼んで
間接参照をたどる。HTTP サーバでは `Std.Net.recv` の待ちの継続が `ms` (`noTimeout`) を毎回 `force` する (要求ごとに 1 回)。

初期化の関数が構築子を 1 つ作って返すだけで、その引数が定数 (整数・浮動小数点数・文字列)・ほかの大域変数・フィールドのない構築子
だけの大域変数は、CAF ではなく、その構築子の **静的なオブジェクト** (RC 0 の不死) にする。値そのものなので `force` は呼ばれず
(インラインの種類の検査を通り抜ける)、確保も数えない (ネイティブとインタプリタで同じ)。CAF の根にも入れない。
指すものはすべて不死 (静的なオブジェクト・文字列定数・CAF のサンク) なので、「不死のオブジェクトが指すものは共有か不死」という
ランタイムの不変条件 (共有の印付け・循環の回収はそれを辿らない) を保つ。

あわせて、`global` の結果 (CAF のサンクか静的なオブジェクト。どちらも不死) を MIR の静的な変数 (FEAT-0089) に加え、
`dup` / `drop` を生成しない。
