## 概要

Core のインライン化は「呼び出しの閉路に入らない」関数だけを対象にしている。互いに呼び合う関数の組はどちらもインライン化されず、
小さい方の関数を介してループが回る。fannkuch-redux `own.chs` の `next` と `nextIf` がこの形で、

- `nextIf` は `Bool` を箱のまま受け取るので、`next` は比較の結果を `Bool` に作ってから末尾呼び出しし、`nextIf` はそれを `switch` する。
- どちらにも自己末尾呼び出しがないので、一意性の特殊化 (FEAT-0067) と境界検査の移動 (FEAT-0069) の対象にならない。

GHC の **ループ破り** (loop breaker) と同じく、再帰のグループごとに呼び出しのまま残す関数を選べば、残りはインライン化しても停止する。

- 呼び出しの閉路をすべて切るように選ぶ: 自己再帰の関数はそれ自身。相互再帰のグループ (強連結成分) では **最も大きい関数** を選び、それを除いて繰り返す。
- ループ破りでない関数は、これまでの条件 (小さい、または呼び出しが 1 か所) でインライン化する。
- worker/wrapper の wrapper は常にインライン化するので、呼び出しのグラフでは wrapper を通り抜けて辿る (`f$w → f → f$w` は `f$w` の自己再帰)。

インライン化は意味を変えない (遅延は `let` の束縛のまま)。
