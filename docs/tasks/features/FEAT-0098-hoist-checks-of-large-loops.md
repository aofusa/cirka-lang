# FEAT-0098: 大きなループの本体の境界検査も入口へ移す

- 状態: in-progress
- トラック: 共通基盤
- マイルストーン: SX 共通基盤の拡張 (各トラックの必要に応じて)
- 優先度: P1

- 設計: [06-ir.md](../../design/06-ir.md) §3, [16-performance.md](../../design/16-performance.md)

## 概要

`bench/n-body` は Rust の 1.16 倍かかる (FEAT-0097 の計測)。1 ステップのループ (`pairs`) は、回数の決まったループの展開
(FEAT-0094) で 5 体の 10 組の相互作用と移動が直線のコードになり、一意な配列への特殊化 (`pairs$io$w$kx_0_1$u`) は MIR で 530 命令ある。
ループの境界検査の入口への移動 (FEAT-0069) は 500 命令を超える関数を解析しないので、35 個の要素への 245 回の読み書きの検査が残る。
LLVM は検査の大半を消すが、ループの中に 8 つの分岐が残り、ループの本体が複数の基本ブロックに分かれる。SLP ベクトル化は
基本ブロックの中でしか命令を組にしないので、Rust では 2 組ずつまとめて計算される平方根と割り算 (`sqrtpd`・`divpd` 各 5 回) が、
1 つずつ (`sqrtsd`・`divsd` 各 10 回) になる。

解析の上限を、関数の命令数ではなく、解析が訪れる命令の総数 (本体の命令数 × 解析の回数) で決める。大きな関数は前提条件の候補を
試す回数が減るだけで、解析そのものは行う。

## 作業内容

- [x] `bounds.rs`: 解析する関数の上限を 4000 命令に上げ、候補の探索を「本体の命令数 × 解析の回数」が 500,000 に達したところで
  打ち切る (これまでの上限 500 命令 × 1000 回と同じ手間)
- [x] テスト: 直線の本体が 600 命令のループの検査が入口へ移る (前提条件 `words(a) >= 35`、写しの読み書きはすべて検査なし、
  長さが足りなければ元どおり検査しながら回って同じ位置で panic する)
- [x] n-body の機械語で、ループの中の検査の分岐がなくなり、平方根と割り算が組になることを確かめる
- [ ] 全ベンチを計測して記録する

- [ ] 全ベンチの出力が変わらない

## メモ

- 原因の確認 (LLVM IR を手で直した実験): `Main.pairs$io$w$kx_0_1$u` の 245 個の検査の分岐を検査なしにすると、ステップのループの
  平方根は `sqrtsd` 2 + `sqrtpd` 4、割り算は `divsd` 2 + `divpd` 4 になる (Rust は `sqrtpd` 5・`divpd` 5)。出力は同じ。
- 解析の手間: 解析 1 回は本体の命令を 1 度ずつ訪れる (命令ごとに差分制約の行列の更新が最大で節点の数の 2 乗)。n-body の `pairs` は
  節点が 3 つ (0・ステップ数・配列の語数) で、前提条件の探索は数十回で終わる。
- 機械語 (確認済み): ステップのループの分岐は 9 → 1、命令は 440 → 388、平方根は `sqrtsd` 2 + `sqrtpd` 4、割り算は `divsd` 2 + `divpd` 4。
  cachegrind (20 万ステップ): 命令 88.2M → 77.8M、分岐 1.84M → 0.24M。
- 計測 (2026-11-25、i5-3320M (Ivy Bridge)・1.2 GHz 固定、21 回の交互実行の中央値): n-body は FEAT-0097 の 1.216 s → 1.248 s
  (1.026 倍、遅くなった)、Rust は 1.068 s (1.17 倍)。他のベンチの LLVM IR は変わらない。SLP ベクトル化を切ると
  1.590 s → 1.514 s と速くなるので、検査の除去そのものは効いているが、SLP の組み方が変わって遅くなる。
- 原因: Rust 1.99.1 は LLVM 23.1.1、こちらは clang 18.1.3。Rust の n-body の最適化前の IR を clang 18 でコンパイルすると、
  こちらと同じ `sqrtsd` 2 + `sqrtpd` 4・`divsd` 2 + `divpd` 4 になる (LLVM 23 では `sqrtpd` 5・`divpd` 5)。Ivy Bridge の除算器は
  パイプライン化されておらず、平方根と割り算の命令の数がステップの時間を決める。残る差は LLVM の版の差。
  → バックエンドの LLVM を Rust と同じ 23 に上げる別チケットで扱う (apt.llvm.org に noble 向けの clang-23 23.1.6 がある)。
- 受け入れ条件「n-body が速くなる」は満たしていないので in-progress のまま。
