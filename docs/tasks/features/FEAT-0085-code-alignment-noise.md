## 概要

FEAT-0045 の計測で、生成コードもランタイムも同じまま、関数の番地を 16 バイトずらすだけで cli-grep CirkaLang の時間が
±8% 変わった (ホストの Ivy Bridge)。ランタイムに `#[cold]` の関数を足すと、リンカが `.text.unlikely` を先頭に置くため
生成コードの番地がずれ、関係のない変更で数 % 速くも遅くもなる。最適化の効果 (数 %) が配置の揺らぎに埋もれる。

ループの先頭や関数を 32/64 バイトに揃える (`-mllvm -align-loops=32`・`-falign-functions=32`)、生成コードをリンクの先頭に置くなどで
揺らぎを小さくし、既定の性能を揃えた側 (速い側) に寄せられるか調べる。

## 作業内容

- [ ] 詰め物 (0/16/32/48 バイト) を置いた 4 通りのリンクで全ベンチの揺らぎを測り、影響の大きいベンチと関数を特定する
- [ ] 関数・ループの整列とリンクの順序を試し、4 通りの平均と幅、コードの大きさを比べる
- [ ] 効果があれば既定にし、16-performance.md §4 に記録する
