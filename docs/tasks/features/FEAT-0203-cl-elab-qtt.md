## 概要

双方向型検査による依存型 + 多重度 (0/1/ω) + 宇宙 Type/LType の型検査と、内部表現 TT への elaboration。トップレベルは型注釈必須。

## メモ

- 実装: `crates/cirkalang-elab` — `tt.rs` (TT・値・プログラム)、`eval.rs` (NbE・大域定義の遅延展開と燃料・メタ変数のパターン単一化)、
  `elab.rs` (双方向検査・多重度・宇宙・データ型・case tree へのコンパイル)、`lint.rs` (TT Lint)。入口は `elaborate(&rast::Program)`。
- 多重度は「rig」(現在の使用倍率) と変数ごとの使用量で数える。ラムダ・let の右辺はスコープごとに数えて倍率を掛けて合流させる
  (ω で使われるクロージャに線形変数 → E0305)。分岐は各枝の使用量を合流し、異なる線形変数は Drop がなければ E0306。
- コンストラクタの引数は「構築した値の使用回数」で数える (フィールド ω でも結果が線形なら 1。§4.5 の `1·ω = 1` の構築側)。
- 分解した変数を枝の中でも使う場合は、フィールドを使ってはならない (どちらか一方で消費する)。使わない場合は照合が変数を 1 回消費する。
- 依存パターンマッチの精密化は、文脈の環境の変数の値を置き換えることで行い (型は項で持ち、使うたびに評価し直す)、
  TT の `Alt::Con.refine` に記録する。TT Lint は記録された精密化を適用したうえで添字の定義的等価性を再検査する。
- 宣言の処理順: 型のプリミティブ → データ型のシグネチャ → その他のプリミティブ → コンストラクタ (宇宙・Drop の推論) → 定義のシグネチャ → 本体 (出現順)。
  本体の中で後に定義される関数は型検査中に展開されない (不透明)。
- デバッグビルドでは elaboration の後に必ず TT Lint を実行する (失敗は ICE)。
