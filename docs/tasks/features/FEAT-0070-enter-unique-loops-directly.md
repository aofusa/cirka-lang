## 概要

FEAT-0069 の後でも n-body `own.chs` は Rust の 1.65 倍、fannkuch-redux `own.chs` は 1.55 倍で G3 (1.5 倍以内) に届かない。
callgrind で内訳を見ると、n-body の内側のループ (`steps$pairs$w$u$b`) は 1 組あたり約 49 命令まで減っており (Rust は全体で 1 組あたり約 45 命令)、
差はループに入るまでの経路に集まっている。

- 1 回の呼び出しは `f` → (`P` を確かめて) `f$b` → (1 反復目で一意性検査) → `f$u` → (`P` をもう一度確かめて) `f$u$b` と進む。
  最初の反復だけが一意性検査のある経路を通り、`P` を 2 度確かめる。
- n-body の `steps$move$w` は最初の反復が `f$u` への末尾呼び出しになるので自己末尾呼び出しがなく、FEAT-0069 の対象にならない。
  1 ステップごとに 9 か所の境界検査を払う (`steps$move$w` だけで 23.5 M 命令、`steps$pairs$w` と `steps$pairs$w$b` で 48 M 命令)。
- fannkuch-redux の `rev` は 1 回の呼び出しの反復が少ないので、この入口の経路の割合が大きい。

`f$u` が仮定するのは「引数が値で参照カウントが 1」だけなので、これを入口で確かめれば最初の反復から `f$u` で回せる。MIR に次の変更を加える。

- `f$u` を作ったループの入口に、`f$u` が仮定する引数について `is_unique` (と、本体が `force` する引数なら `is_value`) を確かめる検査を置き、
  成り立てば `f$u` へ末尾呼び出しする。成り立たなければ今までどおりの経路 (FEAT-0069 の `P` の検査から) を進む。
- 境界検査の入口への移動 (FEAT-0069) の後に実行する。先に実行すると `f` の `P` の検査が前に来て、`P` を 2 度確かめることが残る。

入口の検査は評価も書き込みもしないので、意味は変わらない。`rc == 1` かつ値なら、元の経路の `force` と一意性検査は引数そのものを返す。

- 全ベンチの出力は前と同じ。実行テスト `unique_entry.hs` の配列のコピーは 1 回 (共有された配列の最初の書き込みの分) で、リークはない。
- fannkuch-redux の `rev` は 190 万回呼ばれる。入口の検査だけでは冷たい経路のために 5 回の push/pop が残り、本体を別の関数にして初めて消えた。
- 変異テスト: 入口の検査を 6 通り壊す変異 (`is_value` を除く、最初の引数だけ調べる、一意性を調べない、2 つの経路を入れ替える、

- ホストの負荷が高く、この段階の実行時間は計測しなかった (負荷平均が 7〜10 の状態で測った値は採用しない)。
  時間は後続の変更 (`internal` 化、`-O3`) と合わせて計測し、`bench-report.md` に記録する。
