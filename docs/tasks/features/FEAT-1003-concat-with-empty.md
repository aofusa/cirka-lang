## 概要

CirkaLang の `++` (`cirka$bytes_concat`) は、片方が空でも両方の長さの新しい文字列を確保し (ゼロ埋めしてから) 両方をコピーする。
HTTP サーバは要求ごとに、まだ完結していない要求のバイト (ふつうは空) に受け取ったバイトを足し (`buf ++ d`)、空の答えの列に答えを
足す (`out ++ hello`)。どちらも確保とコピーが要らない。片方が空なら他方をそのまま返す (結果は新しくなくてよい: その場の書き込みは
`bytes_unique` を通る)。`Data.String.fromStr` の空のビューが使う `cirka$bytes_slice` も、空の範囲なら静的な空文字列を返す。

## メモ

- テスト `tests/cirkalang/run/v007/concat_empty.cirka` は確保の回数の上限 (`max-allocs: 8`、-O2 のネイティブの実行) も確かめる。
- 結果は新しいオブジェクトとは限らない (他方の側を共有する)。CirkaLang からその場で書き込める文字列は Builder のバッファ
  (`primStrNew` で作る一意の文字列) だけで、連結の結果には書き込めない。MIR のその場の更新は `bytes_unique` を通り、共有なら
  コピーする。
- HTTP サーバは要求ごとに `buf ++ d` (前の要求の残り `buf` は空) と `out ++ hello` (`out` は空) をコピーしていた。どちらも他方を返す。
  命令数と CPU 時間は FEAT-1001 のメモ (FEAT-1001〜1005 を合わせた計測)。全ベンチの出力は main と同じ (FEAT-1005 のメモの計測)。
