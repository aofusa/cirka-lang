## 概要

関数でないトップレベルの値は CAF (初回の参照で評価する静的サンク) になる。本体がリテラルの定義 (HTTP サーバの
`hello = "HTTP/1.1 200 OK..."`) や、リテラルの構築子 (`Std.Net` の `noTimeout = 0 - 1` を畳み込んだ `I# -1`) も CAF になり、
使うたびに静的サンクを読み、評価済みの印を辿る `cirka_force` を呼ぶ (HTTP サーバで要求ごとに 2〜3 回)。

Core の簡約で、本体が定数 (リテラル、または文字列以外のリテラルだけを受け取る構築子。`cast` の下でもよい) のトップレベルの定義を
値に置き換える。リテラルは別名と同じく出現するすべての位置で置き換える (文字列は MIR の静的なオブジェクトになり、RC の操作もない)。
構築子は分解される位置 (`case` の対象、正格な `let!` の値) でだけ置き換え、既知の構築子として箱を消す。ほかの位置では共有の CAF を残す:
写すと使うたびに箱を確保し (遅延の位置・データ構造のフィールド)、辞書のフィールドに戻すと原子でなくなり、特殊化の後の辞書の
フィールドの浮上が同じ名前の大域変数をもう一度作る (Core Lint の「defined twice」。CirkaLang の `Storable` の `zeroed` で起きた)。

## メモ

- HTTP サーバの CAF の根 (`@cirka_caf_roots`) は、main の 4 つ (`Std.Net.noTimeout`・`Std.Env.args`・`Main.hello`・`Main.badRequest`)
  から 2 つ (`noTimeout`・`args`) になった。`noTimeout` (`I# -1`) は `recvOn` の引数として渡る位置で使われるので CAF のまま残り、
  待ちの継続が要求ごとに 1 回 `cirka_force` を呼ぶ (callgrind で要求ごとに 21 命令)。これは FEAT-1006 で静的なオブジェクトにした。
  命令数と CPU 時間は FEAT-1001 のメモ (FEAT-1001〜1005 を合わせた計測)。全ベンチの出力は main と同じ (FEAT-1005 のメモ)。
