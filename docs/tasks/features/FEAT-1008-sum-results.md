## 概要

bench/string-split は Rust の 1.06〜1.07 倍の時間がかかる。1 行ごとに 2 番目の単語を `S.toInt` で数にする。`toInt` は数字のループ
`digitsFrom` (`Just acc` か `Nothing` で終わる末尾再帰) の結果を返す。ループはインライン化で消えないので、`Just` と `I#` を確保して
返し、呼び出し側 (`fromMaybe 0`) がそれを開いて解放する (1 行に確保 2 回と解放 2 回。生成した機械語の単語のループに `cirka_alloc` の
呼び出しがある)。組の CPR (FEAT-0065) は構築子 1 つの型だけを扱う。

和型の CPR: 結果の型が構築子 2 つ以上の和型で、すべての返却がその構築子 (または発散・対象の関数の末尾呼び出し) なら、worker は
構築子の番号と、構築子ごとの平坦化したフィールドを箱なしの組で返し、wrapper が番号で構築子を作り直す。呼び出し側の `case` は
インライン化した wrapper の構築子に case-of-case で出会って消える (GHC の和の CPR と同じ)。葉が unboxed の値のときだけ扱い
(返却が作らない構築子の葉には 0 を置く)、葉はどの返却でも原子か副作用のないプリミティブ演算に限る (返す位置で計算しても、遅延の
フィールドが計算しなかったものを計算しない)。

あわせて `Data.String.toInt` の負の数は `mapMaybe negate` をやめて `case` にする (呼び出しごとに `negate` のクロージャを確保していた)。
