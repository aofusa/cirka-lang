## 概要

HTTP サーバの 1 要求の命令数は 1,352 (Rust 669) で、その約 6 割がランタイムにある (callgrind、FEAT-1009 のビルド)。
要求ごとに次の処理がある。

- イベントループがコールバックを呼ぶたびに、IO の継続に渡すトークン (箱の `Unit#`) を確保し (`io_token`)、継続がすぐ解放する
  (確保 23 命令・解放 67 命令)。トークンの値は読まれない。
- 受信したバイト列 (ポインタのフィールドを持たないオブジェクト) の解放は、死んだオブジェクトを辿る一般の処理を通る
  (1 回 65 命令。うち 17 命令は退避するレジスタの保存と復元、14 命令はヘッダを使った連結)。
- 継続が同じ記述子をまた待つ `watch` は、システムコールの要らない場合も、`epoll_ctl` や時限の処理のためにレジスタを退避する
  (70 命令)。

トークンは静的な不死のオブジェクト 1 つにする (`rc` 0。静的な空文字列と同じく、`dup` / `drop` は何もせず、再利用もされない)。
ポインタのフィールドを持たないオブジェクトの解放はすぐ解放し、辿る処理を関数の外に出す。`watch` は登録済みで準備できて
いない記述子を待つ場合 (コールバックも時限もない) を短い経路にし、ほかを関数の外に出す。
