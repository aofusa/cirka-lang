# FEAT-0063: 数値ループの生成コード (libm の組み込み関数・一意性検査のインライン化・要素の TBAA・冗長な一意性検査の除去)

- 状態: done

- マイルストーン: M2
- 優先度: P1
- 依存: FEAT-0058
- 設計: [16-performance.md](../../design/16-performance.md) §3, §4

## 概要

n-body `own.chs` が Rust の約 6 倍遅い原因を IR で調べ、配列を破壊的に更新する数値ループの生成コードを改善する。

- libm の `sqrt` `fabs` `floor` `ceil` `trunc` (double → double) を LLVM の組み込み関数 (`llvm.sqrt.f64` など) で呼ぶ。
  `sqrt` が 1 命令になり、`errno` を書く関数呼び出しがなくなるので、ループの最適化を妨げない。
- `bytes_unique` / `array_unique` の高速経路 (RC == 1 なら自分自身) をインラインで出す。写す遅い経路はランタイム呼び出しのまま
  `!prof` で稀とする。デバッグ用ランタイムでは写した回数を数えるため、従来どおり呼び出す。
- 配列の要素の load/store に、ヘッダ・フィールドと別の TBAA タグ (`cirka.elem`) を付ける。
  要素への書き込みが RC やフィールドの読み込みを無効にしなくなる。
- Core に冗長な一意性検査の除去 (`crates/cirka-core/src/uniq.rs`) を追加する。一意性検査の結果 (または新しく作った配列) が、
  その場の読み書きだけに使われた後で再び検査されるとき、2 度目の検査は同じ値を返すので取り除く。
  検査の後に元の名前がまだ使われる場合 (検査は写しを返す) や、間に共有されうる使い方 (関数・C 関数への引数、構築子、
  λ・thunk による捕捉) がある場合は残す。

## 計測 (2026-11-06、ホスト、3 回の最良値)

| ベンチ | 前 | 生成コードの改善後 | 検査の除去後 | Rust |
|--------|---:|---:|---:|---:|
| n-body `own.chs` (5,000,000) | 2.29 s | 0.98 s | **0.91 s** | 0.385 s |
| array-sort `own.chs` | 0.54 s | 0.47 s | 0.46 s | 0.088 s |

- n-body の一意性検査は 15 → 8 か所。残りは各反復の入口の検査 (引数として受け取った配列が一意かは関数の外の事実で、
  Core の局所的な解析では分からない)。関数の引数が一意であることを型から運ぶのは FEAT-0062。
- mandelbrot・spectral-norm・binary-trees は変化なし (出力は同一)。
- n-body に残る差: 境界検査 (19 か所) と、配列の要素を毎回 load/store すること (レジスタに置けない)。
  境界検査の除去は FEAT-0234 (証明に基づく除去) で扱う。
