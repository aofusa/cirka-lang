# FEAT-1002: ランタイムの I/O の固定費を減らす (受信バッファ・空の結果)

## 概要

HTTP サーバのプロファイル (callgrind、要求ごとの命令数) で、ランタイムの読み込みに固定費があった。

- `cirka_sock_recv` は 64 KiB の配列をスタックに取って読み、関数の入口のスタックプローブが読み込みのたびに 16 ページを 1 つずつ触る
  (約 64 命令と 16 ページ)。スレッドごとの受信バッファ (最初の読み込みで確保し、スレッドの終わりに解放) に読む。
- 空の結果 (`EAGAIN`・終わり) も新しい空の BYTES を確保して返していた。ランタイムに静的な空文字列 (不死、`rc` 0) を置き、
  `cirka_bytes_from` は長さ 0 ならそれを返す。

## 作業内容

- [x] `net.rs`: スレッドごとの受信バッファ (`Tls::recv_buf`)、スレッドの終わりに解放
- [x] `lib.rs`: 静的な空文字列、`cirka_bytes_from` の長さ 0
- [x] MIR インタプリタ: ランタイムが `cirka_bytes_from` で作る外部関数の結果 (読み込み・行・環境変数・引数・ファイル) は、空なら数えない静的な文字列にする (実行テストはインタプリタとネイティブの確保の回数が一致することを確かめる)
- [x] HTTP サーバの命令数を計測して記録する

## 受け入れ条件

- [x] 受信の関数からスタックプローブがなくなる
- [x] 既存のテストが通る (空の結果の数え方を含む)
- [x] テストを追加し `scripts/ci.sh` が通る

## メモ

- `cirka_sock_recv` の機械語から、main にあったスタックプローブ (`sub $0x1000,%rsp` のループ) がなくなった。HTTP サーバの要求ごとの
  命令数と CPU 時間は FEAT-1001 のメモ (FEAT-1001〜1005 を合わせた計測)。答えを送った後の空振りの読み込みの結果 (要求ごとに 1 つ) は
  静的な空文字列で、確保しない。
