## 概要

HTTP サーバ (bench/http-server) は Rust の 0.81〜0.88 倍のスループットだった。要求ごとのシステムコールが Rust の 2 つ
(読み込み・書き込み。`epoll_wait` は複数の接続でまとめて 1 回) に対して 4 つある。答えを送った後の `recv` は次の要求がまだ
来ていないので `EAGAIN` で空振りし、待ちは `EPOLLONESHOT` の登録を `epoll_ctl(EPOLL_CTL_MOD)` で張り直す。

待った記述子は epoll にエッジトリガーで登録したままにし、ループが記述子ごとに準備の状態を覚える (ADR-111。mio・nginx と同じ方式)。
ソケットの操作は `EAGAIN` か少ない読み込み (受信バッファを空にした) で準備ができていないと分かればループに知らせ、次の操作は
システムコールなしで `EAGAIN` を返し、待ちは `epoll_ctl` なしで次のエッジを待つ。登録は記述子オブジェクトの通し番号で見分け、
番号が再利用された記述子の古い登録と混ざらないようにする。API の意味 (待ちは 1 度だけコールバックを呼ぶ) は変えない。
