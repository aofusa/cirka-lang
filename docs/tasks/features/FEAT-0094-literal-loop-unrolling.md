## 概要

`bench/n-body` は Rust の 1.44 倍かかる。Rust 版は 5 天体の二重ループ (`for i in 0..5 { for j in i+1..5 { … } }`) を
LLVM が完全に展開し、天体の配列の添字がすべて定数になる。CirkaLang 版の同じループは、`Int#` の添字を引数にとる末尾再帰の関数
(`pairs$io$w … 0 1 …`) で、Core → MIR → LLVM では 1 回ごとに添字の比較と分岐、添字からのアドレス計算が残る。

Core で、`Int#` の引数がリテラルから始まり、リテラルの歩幅で動き、分岐がリテラルで決まる末尾再帰の関数 (相互再帰のグループも)
を、呼び出し箇所から末尾呼び出しで到達するリテラルの組ごとに写す (リテラルを代入し、決まる分岐を選び、定数を畳む)。
1 つの末尾呼び出しからしか到達しない写しはその場にインライン化するので、固定の回数のループは添字が定数の直線のコードになる。

- 呼び出し箇所ごとに写しは 64 個・合計 8,000 ノード (およそ 2,000 命令)、プログラム全体で 40,000 ノードまで。
  上限を超える場合は、リテラルの一部 (外側のループの回数など) を引数に戻して試す。変数で終わるループは新しいリテラルに際限なく到達するので展開しない。
- 末尾呼び出しだけを辿るので、ループでない再帰 (`fib 30`) は展開しない。写しは引数を少なくとも 1 つ残す (ループを定数にはしない)。

## メモ

- 計測 (FEAT-0093 との比較。FEAT-0095 と同じビルドで計測した。展開の写しができるのは n-body・spectral-norm・mandelbrot
  だけであることを LLVM IR で確かめた。11 回ずつ交互に実行した中央値の比、負荷 1.5 未満): n-body 0.778 (0.583 → 0.453 秒、
  Rust との比 1.47 → 1.14)、mandelbrot 0.971、spectral-norm 0.993。そのほかは変わらない (array-sort 0.991、binary-search 1.012、
  binary-trees 1.010、stencil 0.986、effects 0.998、session 0.982)。全ベンチの出力は変わらない。
- n-body の残りの差: 1 ステップの命令数は Rust と同程度 (440 と 455) だが、llvm-mca (ivybridge) の見積もりは 385 サイクルと
  335 サイクル (比 1.15 で、計測の 1.14 と合う)。律速は浮動小数点の除算器で、Rust は 10 組の `sqrt` と除算を SLP ベクトル化で
  5 つずつの `sqrtpd` / `divpd` にまとめるが、CirkaLang は `sqrtsd` 6・`sqrtpd` 2・`divsd` 6・`divpd` 2 になる。ループに残る
  境界検査 (8 か所。展開した関数は大きく、FEAT-0069 の巻き上げの対象外) を LLVM IR で手で消すと除算器の命令は 12 に減るが、
  速くはならなかった (0.465 秒と 0.449 秒)。Rust は天体の配列がスタックにあってレジスタに置かれ (SROA)、CirkaLang はヒープの
  配列を読み書きする。続きは FEAT-0091 で扱う。
