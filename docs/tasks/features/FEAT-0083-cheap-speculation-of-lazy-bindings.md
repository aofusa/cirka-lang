## 概要

遅延 `let` の右辺が **安価で、失敗も発散も副作用もない** 計算 (失敗しないプリミティブ演算・正格フィールドの構築子・評価済みの変数の
`case`・純粋な libm 関数) なら、サンクを作らずに先に評価する (GHC の `exprOkForSpeculation` に当たる投機的評価)。
評価しても意味は変わらず (値は同じで、失敗しない)、サンクの確保と `force` がなくなる。

FEAT-0061 の調査で、n-body `plain.hs` の `interactAll` が 1 組ごとに 3 つのサンク (自由変数 12 個) を作っていることが分かった:
`pairStep` の組の要素 (`B x y z (vx - dx * mj) …`) と共有の `mag = dt / (d2 * sqrt d2)` が遅延になる。
どれも浮動小数点の算術と `sqrt` だけで、7 フィールドの `B` を直接作る方がサンク (12 フィールド) より小さい。
aCHC `plain.hs` は GHC -O2 の 2.46 倍 (bench-report.md「遅延の意味論の修正」) で、この差の一因と見られる。

## 作業内容

      正格フィールドの構築子 (フィールドも同じ条件)、評価済みの変数の `case`、純粋と分かっている `extern` (libm の `sqrt` など)
