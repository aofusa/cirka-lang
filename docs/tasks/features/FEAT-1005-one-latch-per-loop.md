## 概要

bench/array-sort は Rust の 1.07 倍の時間がかかる。分割のループの機械語を比べると、こちらは 1 反復に分岐が 2 回成立する
(交換しない側: 増分の後のループの先頭への `jmp` と、末尾の比較からの `jg`) が、Rust は 1 回 (交換しない側は比較から増分のブロックへ、
交換する側は交換の後に増分のブロックへ)。乱数の入力では比較の半分を予測し損ねるので、1 反復は短く、余分な分岐が効く。

原因は LLVM IR の形にある。自己末尾呼び出しはそれぞれループの先頭 `tailrec` への後ろ向きの辺になり (FEAT-0066)、引数を変えずに渡す
呼び出しがあると (交換しない側の `i`)、先頭の phi が自分自身を受け取る。LLVM の LoopSimplify はこれを入れ子のループの印とみなし
(`separateNestedLoop`)、その呼び出しだけの内側のループを切り出す。C や Rust のループは本体の終わりで合流して 1 つの辺で戻るので、
この形にならない。

呼び出しが 2 つ以上の関数は、どの呼び出しも 1 つのラッチ `tailrec.latch` に飛び、ラッチの phi が引数を合わせて `tailrec` へ戻る形で生成する。
抽出した分割のループを LLVM 18 の `opt -O3`・`llc -O3` にかけると、増分が 1 つにまとまり、Rust と同じ配置 (1 反復に成立する分岐が 1 回) になる。
