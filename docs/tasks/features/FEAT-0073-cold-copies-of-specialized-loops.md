# FEAT-0073: 冷たい経路に特殊化した関数の写しを持たせ、ループの入口に定数を伝える

- 状態: done
- トラック: 共通基盤
- マイルストーン: M2
- 優先度: P1
- 依存: FEAT-0070, FEAT-0072
- 設計: [06-ir.md](../../design/06-ir.md) §3

## 概要

n-body の `pairs` は `steps` から `pairs a 0 1` と定数で呼ばれ、LLVM がこの定数を知ればループの回数が定まり、完全に展開できる (Rust はそうなっている)。
しかし特殊化した関数 `f$u` は入口の `f` のほかに、冷たい経路 `f$slow` と `f$b` からも呼ばれる。`f$slow` は 1 反復目のあとで `f$u` に移るので `j` が 2 で呼ばれ、
LLVM には `j` が定数に見えない。

手で `f$slow` の呼び出し先を別の写しに変えた結果 (n-body 500,000 ステップ、callgrind、`internal` 化の後):

| | 命令数 | 条件分岐 |
|---|---:|---:|
| 今 (`-O3`) | 300.9 M | 19.6 M |
| 写しを分ける (`-O3`) | **246.9 M** | 5.6 M |
| Rust | 227.8 M | 0.6 M |

MIR で次のようにする。

- `enter_specialized` で、冷たい経路に `f$u` と `f$u$b` の写し `f$slow$u`、`f$slow$u$b` を作り、`f$slow`・`f$b` と写しの末尾呼び出しをそちらへ向ける。
  `f$slow` の自己末尾呼び出し (元の `f` への末尾呼び出し) は `f$slow` に向ける。冷たい経路に入ったループは冷たい経路で終わる。
- ホットな `f$u`・`f$u$b` を呼ぶのは入口の `f` と、それ自身だけになる。

## メモ

callgrind の命令数 (n-body 500,000 / fannkuch-redux 9 / array-sort 1,000,000 / spectral-norm 300、`own.chs`):

| ベンチ | FEAT-0072 | FEAT-0073 | Rust | `.text` (byte) |
|--------|---:|---:|---:|---|
| n-body | 300.9 M | **232.4 M** | 227.8 M | 113,546 → 117,642 |
| fannkuch-redux | 189.9 M | **166.9 M** | 104.6 M | 82,522 → 83,882 |
| array-sort | 324.5 M | **308.9 M** | 286.8 M | 86,570 → 87,194 |
| spectral-norm | 84.5 M | 84.5 M | 61.8 M | 87,210 → 88,362 |

- n-body の条件分岐は 19.6 M → 2.6 M (Rust 0.6 M)。`pairs a 0 1` の定数が届き、ループが完全に展開された。
- 全ベンチの出力は変わらない (`own.chs` / `plain.hs` / `main.cirka` の 14 種)。`array-sort` の `plain.hs` は FEAT-0073 の前からビルドできない。
- 退行しうるのは冷たい経路に入ったループだけなので、共有された配列を `fill` する 200 万要素のループで前後を比べた。命令数は 11,397,723 → 11,397,743 で変わらない (`f$slow$u` の本体は `f$u` と同じ)。
- 実装の変異 8 件はテストで全部検出した (写しが冷たくない、`f$b` の付け替え漏れ、`f$slow` への付け替え漏れ、写しの片方だけ作る、など)。
