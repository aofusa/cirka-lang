## 概要

FEAT-0066 の後の array-sort `own.chs` に残る差を調べた。partition のループ (自己末尾呼び出し) は、swap のたびに
配列の一意性検査 (`bytes_unique`: RC の load と比較、写しの遅い経路との合流) をする。前の反復で検査した配列を
そのまま次の反復に渡しているので検査は常に成り立つが、関数は呼び出し元を区別できない (FEAT-0063 の Core の局所的な除去では
引数の一意性が分からない)。n-body・fannkuch-redux のループの入口にも同じ検査が残る (FEAT-0063 のメモ)。

MIR に、配列の引数が一意だと仮定した関数 `f$u` を加えるパスを作る。

- 各所有ポインタ引数について、その引数 (またはその `force`・一意性検査の結果) が「その場の読み書きだけに使われている」
  (clean) かをプログラム点ごとに求める (前向きのデータフロー解析。`dup`・他への受け渡し・格納・ブロック引数で dirty)。
- `f$u` では clean な値は引数そのもので一意なので、その `force` と一意性検査は恒等であり取り除く。
- `f` の自己末尾呼び出しのうち、**検査済み**の clean な値を渡すものを `f$u` へ向ける。`f$u` の自己末尾呼び出しのうち clean な値を
  渡すものは `f$u` へ、それ以外 (配列が共有されうる経路) は `f` へ向ける。
- 検査を前に移すのではないので、元のプログラムが写さない配列は写さない (書き込まない経路で共有の配列を写すことがない)。
  入口で検査してから回す案は、書き込まずに抜ける呼び出しで余計な写しが生じるので採らなかった。

## メモ

### 計測 (2026-11-06)

ホストの負荷が低いとき (load average 1 前後) に前後と Rust を交互に実行した。10 回の最良のユーザー CPU 時間の 3 組の最良。出力は同一。

| ベンチ | 前 | 後 | Rust |
|--------|---:|---:|---:|
| array-sort `own.chs` (1,000,000) | 0.11 s | **0.10 s** | 0.08 s |
| array-sort `own.chs` (4,000,000) | 0.48 s | **0.44 s** | 0.35 s |
| n-body `own.chs` (5,000,000) | 0.89 s | **0.70 s** | 0.38 s |
| fannkuch-redux `own.chs` (10) | 0.44 s | **0.40 s** | 0.22 s |
| spectral-norm `own.chs` (1000) | 0.17 s | 0.17 s | 0.17 s |

- 特殊化された関数の数: array-sort 3 (partition のループ、`main$fill`、`main$go`)、n-body 3、fannkuch-redux 7、
  spectral-norm 3 (`generate` のループ。時間は変わらない)。すべての `plain.hs` と `main.cirka`、binary-trees の `own.chs` には
  該当がなく、生成コードは変わらない (array-sort の `plain.hs` は `STUArray` を使うので aCHC ではビルドできない)。
- 一意性検査の分岐だけでなく、配列のポインタと長さがループ不変になることも効く。partition のループの最適化後の IR は次のとおり。

  | | 前 | 後 |
  |---|---:|---:|
  | 一意性検査の遅い経路 | 2 | 0 |
  | 境界検査の失敗ブロック | 8 | 4 |
  | ループ内のポインタの phi | 4 | 0 |

- array-sort の差の内訳 (400 万要素): 生成 IR の partition のループから手で検査を除いて計測した。一意性検査なしは 0.44 s で、
  このパスの結果と同じ。さらに残りの境界検査もなしは 0.40 s。Rust との差 0.09 s のうち、境界検査 (FEAT-0234) の分は 0.04 s で、
  **残りの 0.05 s は未調査**。

### テストの確かさ

パスの安全性の規則を 1 つずつわざと壊し、テストが失敗することを確かめた。

| 壊した規則 | 単体テスト | 実行テスト (`unique_loop_shared`) |
|------------|:---:|:---:|
| `dup` しても clean のまま | 失敗 | 失敗 (スナップショットが書き換わる) |
| 未検査の配列でも `f$u` へ入る | 失敗 | 失敗 |
| 合流で先の状態を残す | 失敗 | 通る |
| 合流で後の状態を残す | 失敗 | 通る |
| 末尾呼び出しの引数の位置を比べない | 失敗 | 通る |

後の 3 つは特定の形の MIR でしか現れないので、単体テスト (手書きの MIR) で確かめる。
