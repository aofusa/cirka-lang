## 概要

生成コードは文字列リテラル (`@str.N`)・引数のない構築子 (`@con.T.C`)・静的な大域変数 (FEAT-1006) を可変の大域変数
(`global`) として出力している。LLVM は中身を知らないので、HTTP サーバの `step` は `S.indexOf buf "\r\n\r\n"` の長さ・
最初のバイト・4 バイトの比較と、`S.startsWith buf "GET "` の長さ・バイトを毎回メモリから読む (要求ごとに静的な文字列の
キャッシュライン)。`startsWith` の結果の `Bool` は静的な構築子のどちらかを選んでからタグを読む。

RC 0 のオブジェクトはどこからも書き込まれない (`dup` / `drop` / 再利用 / 共有マーク / 循環の検査は RC 0 を飛ばす) ので、
これらを `constant` にして、LLVM が長さ・バイト・タグを即値に畳み込めるようにする。CAF (評価で書き換える) は `global` のまま。

## メモ

- HTTP サーバの `step` で、`"\r\n\r\n"` の最初のバイトと 4 バイトの比較、`"GET "` の比較が即値になった
  (`cmpl $0xa0d0a0d` / `cmpl $0x20544547`)。`startsWith` の結果の `Bool` は、2 つの静的な構築子の一方を選んでタグを読む形が残る
  (FEAT-1029 で分岐にする)。
- 計測 (Docker、FEAT-1019 との差。`docs/artifacts/f1022`): HTTP サーバの 1 要求の命令数 925 → 925 (読み出しが即値の比較に
  変わった)、スループット 1.009 倍 (16 接続、FEAT-1017 比)・1.002 倍 (64 接続)。binary-trees の命令数は変わらない。
  全ベンチは FEAT-1019 のメモ (まとめて計測)。
