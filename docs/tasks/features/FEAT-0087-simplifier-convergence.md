## 概要

FEAT-0255 の計測で、vulkan_core.h の構造体 (106 フィールドの `VkPhysicalDeviceLimits` を含む) を読み書きする `Main` を `-O2` でコンパイルすると、
Core の最適化に約 2.7 s かかった (ホストのリリースビルド)。単純化 (`opt::simplify_rounds`) は呼び出し 10 回で計 45 ラウンド回り、
そのほぼすべてで、`$peek` などを取り込んで大きくなった `Main.main` が変わり続ける (多くのラウンドで let の浮動化 `floated` だけが数十〜数百回起き、
ラウンドの上限 `MAX_ITERS` = 6 で止まる)。深く入れ子の束縛を浮動化が 1 ラウンドに少しずつしか動かさないためと見られる。
また、引数が原子の β 簡約は単純化済みの本体に `replace_var` をかけるので、入れ子の深さ n に対して 1 ラウンドが O(n²) になる。

## 作業内容

- [ ] 大きな構造体を読み書きするプログラムをベンチにし、ラウンド数と時間を記録する
- [ ] 浮動化が 1 ラウンドで止まるところまで動かす (または浮動化が往復していないかを確かめて直す)
- [ ] 原子の β 簡約を、本体を単純化する前の置換 (`sub`) で行い、二度の走査をなくす
- [ ] 生成するコードの性能が変わらないことを `bench/` と Core の比較テストで確かめる

- [ ] テストを追加し `scripts/ci.sh` が通る

  変わり続ける束縛自体には効かない。
