## 概要

純粋性から自由にできる Core の最適化のうち未実装のものを加える。あわせて、抽象版と手書き版の生成物が一致すること
(ゼロコスト抽象化) を確かめる回帰テストの仕組みをハーネスに入れる。

## 作業内容

- [ ] 共通部分式除去 (純粋な式。確保を伴う式は共有で RC が増えるので、大きさで判断する)
- [ ] ループ (再帰関数) の不変式の移動
- [ ] 構築子による特殊化 (SpecConstr): 再帰呼び出しの引数が既知の構築子のとき、その形に特殊化した版を作る
- [ ] ハーネス: 抽象版と手書き版の組で確保回数と最適化後の Core / IR の大きさを比べるヘッダ (例: `-- same-cost-as: x.hs`)
- [ ] ベンチで前後を計測する

## 受け入れ条件

- [ ] 各最適化のユニットテストと、ゼロコストの組のテスト (newtype・型クラス・高階関数・`Borrow`)
- [ ] テストを追加し `scripts/ci.sh` が通る
