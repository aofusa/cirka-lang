## 概要

インラインの `dup` / `drop` は、カウントを読んだ直後に静的なオブジェクト (RC 0) かを調べる (FEAT-1017)。この分岐には
「起こりにくい」重み (1 対 2000) を付けていた。静的なオブジェクト (空文字列・文字列リテラル・IO のトークン・`Nothing` のような
引数のない構築子・静的な大域変数) は多くのプログラムで珍しくなく、HTTP サーバでは要求ごとに何度も届く。起こりにくい辺にすると、
LLVM のブロックの配置と末尾の複製は、静的なオブジェクトの場合のためにその後のコードを複製して関数の離れた所に置き
(例: `out ++ hello` の `out` が空文字列のとき)、1 要求で実行するコードのキャッシュラインが増える。

この検査には重みを付けず、LLVM の既定の推定 (`x == 0` の比較の経験則) に任せる。速い経路の重み (`rc > 0` の増加、`rc > 1` の減算)
と、共有されたオブジェクトの冷たいブロックはそのまま。
