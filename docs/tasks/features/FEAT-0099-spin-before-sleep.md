## 概要

`bench/session` (2 つのスレッドがセッション型のチャネルで 10 万回往復する) は Rust の 1.12 倍かかる (FEAT-0096 の計測、
1 往復 11.5 µs と 10.2 µs)。ランタイムの同期オブジェクト (`MVar`・チャネル・スレッドの handle) は pthread の mutex と条件変数の箱で、
値がなければすぐに `pthread_cond_wait` で眠る。1 往復ごとに両側が眠り、起こす側と起きる側のシステムコールとスケジューラの
遅れが往復の時間のほとんどになる。さらに、起こす側は mutex を持ったまま `pthread_cond_broadcast` するので、起きたスレッドは
すぐに mutex で待たされる。

- 待つスレッドは、mutex を放してから箱の「変化の回数」(mutex の下で数える原子的な値) をしばらく見張り、変わったら mutex を
  取り直して条件を確かめ直す。変わらなければ (mutex の下で回数を確かめてから) 条件変数で眠る。見張りは初めの 5 µs は
  プロセッサの pause の合図で回り、20 µs までは見るたびにプロセッサを譲る (`sched_yield`: 同じプロセッサで値を作るスレッドが
  走れるように)。
- 起こす側は回数を mutex の下で増やし、mutex を放してから `pthread_cond_broadcast` する。

Rust の `std::sync::mpsc` も眠る前に短く回る (crossbeam の `Backoff`: pause を計 127 回、`yield_now` を 4 回)。
