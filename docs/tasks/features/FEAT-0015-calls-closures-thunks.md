## 概要

関数呼び出しの仕組み。サンクは aCHC の遅延評価と CirkaLang の `Lazy a` の両方で使う。

## 作業内容

- [x] `tailcc` + `musttail`
- [x] `FUN`/`PAP` と eval/apply
- [x] `THUNK`/`BLACKHOLE`/`IND` と `force`
- [x] 再帰クロージャグループの自己参照を RC 対象外に

## 受け入れ条件

- [x] 10^8 回の相互再帰ループがスタックを消費しない
- [x] 部分適用・過剰適用・サンク共有がインタプリタとネイティブで一致
- [x] リーク 0
- [x] テストを追加し `scripts/ci.sh` が通る

## メモ

- 未知関数の適用はモジュールごとに生成する `cirka_apply_1..8` (tailcc) で行う: FUN の引数数一致は `musttail` で直接、不足は PAP、過剰は分割。PAP は残りアリティで飽和させてから残りを適用するので、ヘルパは 8 引数までで足りる。THUNK/IND は force してから適用。
- クロージャのコードはキャプチャ変数を通常の引数として受け取り、生成するエントリスタブ (`f$clo`) が環境から取り出す (一意なら環境のメモリだけ解放し、共有なら dup して RC-1)。サンクのスタブ (`f$thk`) は C ABI で `cirka_force` から呼ばれる。
- 再帰クロージャの自己参照は、Core→MIR (FEAT-0031) でラムダ持ち上げにより既知関数の直接呼び出しにするため、環境に自分自身を捕捉しない (RC の循環が生じない)。
- インタプリタも `let r = call/apply ...; ret r` を末尾呼び出しとして扱い、ネイティブの `musttail` と同じくスタックを消費しない。
- テスト: `mutual_rec_big.mir` (10^8 回の相互再帰を 1MiB スタックで)、`cps_loop.mir` (クロージャ経由の末尾呼び出し)、`closures.mir` / `pap_over.mir` (部分適用・過剰適用・PAP の共有)、`thunks.mir` (共有・CAF)。いずれもインタプリタとネイティブで出力・確保/解放回数が一致し、リーク 0。
