# FEAT-1016: ソケットの受信の短い経路 (errno は空の結果だけ、空とわかっている受信は短い入口)

## 概要

HTTP サーバの 1 要求あたりのユーザー空間の命令は 1,078 (Rust は 668。FEAT-1012〜1015 の後)。うち `cirka_sock_recv` が 208、
Std.Net の `recvOn` が 192 で、`recvOn` は 1 要求に 2 回動く: データを読む回と、応答を送った後に次の要求を読もうとして、
イベントループが空と知っているソケット (短い読み込みの後、FEAT-1001) から `EAGAIN` を受け取る回である。

- `recvOn` はどちらの回も `cirka_errno` を読み、`cirka_sock_recv` はどちらの回も `errno` を書く (`__errno_location` を 1 要求に
  4 回呼ぶ)。データを受け取ったとき `errno` は要らない。
- 空とわかっているソケットの受信も、読み込みの経路と同じ関数の入口 (6 つのレジスタの退避)・バッファの大きさの計算を通る。
- 読み込みが短かったとき、イベントループのスロットを 2 回目に引く (`drained` の検査と `drain` の記録)。

受信の結果が空でないときは `errno` を書かず読まない約束にし (空のときだけ `errno` が意味を持つ: 0 = ストリームの終わりか
空のデータグラム、`EAGAIN`、エラー)、空とわかっている受信と予算切れは短い入口で返し、スロットは 1 回だけ引く。
