# 03. 型システム (aCHC)

本書は aCHC の型システム。CirkaLang の型システム (QTT 依存型) は [12-cirkalang.md](12-cirkalang.md) §4。
一意性 (U-Bind)・Drop/Release・借用の考え方は両者で共通で、CirkaLang は本書の規則を宇宙 `Type`/`LType` の上でそのまま使う。

aCHC の型システムは **Haskell 2010 の HM + 型クラス** に、
(1) Linear Haskell の **多重度**、(2) Clean 由来の **一意性** を種で表したもの、
(3) **アフィン化 (Drop/Release)**、(4) ランク2による **借用/リージョン** を加えたものである。
参考: Linear Haskell (Bernardy et al. 2018)、Clean、Alms / F° (線形性を種で区別する体系)、
Idris 2 の QTT、Perceus (Reinking et al. 2021)。

## 1. 種 (kind)

```
κ ::= Type | LType | Region | Multiplicity | κ → κ
```

- `Type`: 共有可能な値の型。`LType`: 線形専用の値の型。**部分種 `Type ⊑ LType`**。
- `Region`: 借用・リージョンのスコープ変数の種。値を持たない。
- `Multiplicity`: `One | Many | Zero` と多重度変数。

### 1.1 データ型の種推論 (一意性の伝播)

`data T a₁..aₙ = C₁ τ₁₁..τ₁ₖ | ...` の種は、全フィールド型の種の上限 (lub) とする。

```
kind(T τ̄) = ⊔ { kind(τᵢⱼ[τ̄/ā]) }     Type ⊔ LType = LType
```

これを型引数に対して多相に扱う(**種多相の線形性**)。例: `Maybe :: κ → κ`、`(,) :: κ₁ → κ₂ → κ₁ ⊔ κ₂`。
利用者は `type T :: LType` と注釈して、フィールドが `Type` だけでも線形専用にできる(`Socket` など資源の型)。
`newtype` も同じ規則。関数型 `a %m -> b` の種は常に `Type`
(ただし LType の変数を捕捉するクロージャは線形に束縛される: §2.2)。

### 1.2 型変数

- 型変数の既定の種は `Type`。`forall (a :: LType)` と書くと LType も具体化できる。
- 推論: 関数の本体で型変数 `a` の値がすべて多重度 1 で使われている場合、`a :: LType` に一般化してよい(FEAT-0128 で実装。初期実装は注釈必須)。
- **型クラスの辞書は常に `Type`**(何度でも使える)。クラスの引数は既定で `Type`。`class Drop (a :: LType)` のように明示すれば LType を取れる。

## 2. 多重度と使用量

### 2.1 判断の形

Linear Haskell と同様に、文脈の各変数に多重度を付ける。

```
Γ ::= · | Γ, x :π τ          π ∈ {0, 1, ω} ∪ 多重度変数
Γ ⊢ e : τ
```

使用量の演算は半環 `(0, 1, ω; +, ·)`: `1 + 1 = ω`、`0 · π = 0`、`ω · 1 = ω` 等。
規則は Linear Haskell 論文の λ^q_→ に従う(関数適用 `Γ + π·Δ`、`case` の分岐ごとの使用量の一致など)。

### 2.2 一意性の規則 (aCHC 追加)

**(U-Bind)** 変数を多重度 ω で束縛するとき、その型は `Type` でなければならない。

```
 x :ω τ ∈ Γ  ⟹  τ :: Type
```

すなわち `LType` の値は多重度 1(または 0)でしか束縛できない。これが「LType の値には常に参照が1つしかない」ことを保証する唯一の規則であり、以下はその帰結:

- `LType` の値を ω 引数の関数 (`a -> b`) に渡せない。
- `LType` の値を捕捉するクロージャは、それ自体を多重度 1 で扱う(Linear Haskell の規則で自動的に従う)。
- `forall (a :: Type)` の多相関数を LType で具体化できない(種検査で弾く)。例: `dup :: a -> (a, a)` に `Unique X` は渡せない。

**(U-Arg)** 型注釈のない関数で、引数の型が `LType` と分かる場合は、その矢印を自動的に `%1` とする
(GHC は注釈なしの矢印を常に ω とするが、それでは U-Bind に違反するだけなので推論で補う)。

### 2.3 let の多重度推論

`let x = e₁ in e₂` の多重度は、`e₂` での `x` の使用量から推論する。
`e₁` の型が LType なら 1、そうでなければ使用量に応じて 1 か ω(1 と推論できれば Core で線形情報として最適化に使える)。

## 3. アフィン化: Drop / Release

**(Weaken-Drop)** 多重度 1 の変数 `x : τ` を使わずにスコープを抜けることを、`Drop τ` が解決できる場合に限り許す。
エラボレーションで `drop x` を挿入する。

**(Weaken-Release)** 同様に `Release τ` が解決でき、かつ現在の文脈が `IO` の `do` ブロックの場合に限り許す。`release x` を挿入する。

**挿入位置**:

| 種類 | 位置 | 理由 |
|------|------|------|
| `Drop` | `x` を使わない **分岐の先頭** (最も早い時点) | 純粋なので観測できない。メモリを早く返せる (Perceus と同じ) |
| `Release` | `x` を束縛した `do` ブロックの **末尾**、および例外の巻き戻し経路 | 副作用の順序を Rust のスコープ規則と同じく決定的にする |

複数あれば束縛の逆順。挿入は型検査器が「どの経路で何を落とすか」を記録し、脱糖 (Core 生成) で実際の式を作る。

**(Drop の制約)** 利用者定義の `instance Drop T` の本体で呼べるのは、純粋な関数・他の `drop`・
`Cirka.Unsafe.freeOffHeap` 系の解放プリミティブのみとする(`unsafePerformIO` の使用は警告)。

## 4. 一意性と破壊的更新

`Unique :: Type → LType` は表現が中身と同一の型コンストラクタ。

- `Unique a` の値は U-Bind により唯一の参照なので、`Unique (Array e)` への `write` は in-place で行ってよい。
- `freeze :: Unique a %1 -> a` は恒等関数(実行時コストなし)。凍結後は通常の共有値として RC 管理される。
- `unique :: a -> Unique a` は実行時に RC を確認し、1 なら O(1)、そうでなければコピー(Perceus の `reuse` と同じ判定)。
- `Unique a` に対するパターンマッチ: `a` のデータ構築子でマッチすると、フィールドは `Unique` で包まれて多重度 1 で束縛される(Clean の一意性伝播)。ただし一意性が保証されるのはフィールドが RC==1 の場合のみなので、**フィールドの `Unique` 化は実行時に `unique` を通す**(多くの場合、再利用解析で O(1) になる)。

## 5. 借用とリージョン

`Ref`/`MutRef`/`In` の脱出防止は、ランク2型のパラメトリシティ(`runST` と同じ論法)による。
借用関連の検査で新しい規則は不要で、必要なのは:

- `borrow` 系関数がランク2型であることを型検査器が扱える(`RankNTypes`、注釈による検査モード)。
- `Borrow r` / `RIO r` がモナドとして逐次的に、`borrow`/`withRegion` の呼び出しで **正格に** 評価されること(脱糖・Core で保証)。
- `Ref r a` の中身へは `Borrow r` の操作でしかアクセスできない(抽象型としてエクスポート)。

## 6. 遅延評価との相互作用

**(Strict-Linear)** 次は Core 生成時に正格にする:

1. 型が `LType` の引数・フィールド・`let` 束縛。
2. 右辺が多重度 1 の変数を自由変数に含む `let`。

これにより「サンクが LType の値を捕捉する」ことがなくなり、線形資源の消費・解放の順序がプログラム順に決まる。

## 7. 型クラス

- 辞書渡しで実装。辞書は `Type`(ω)。
- メソッドの型に線形矢印を含めてよい(`class Consumable a where consume :: a %1 -> ()`)。
- 標準のクラス (`Eq`, `Ord`, `Show`, …) の引数は `Type`。LType の値を比較・表示したい場合は借用して中を読む。
- linear-base 互換のクラス `Consumable`, `Dupable`, `Movable` を `Cirka.Ownership` に用意する(FEAT-0121)。

## 8. 例外と線形性

- 例外の巻き戻し時、スコープ内の線形値は `Drop`/`Release` があれば landing pad で解放する。
- どちらも持たない線形値はリークする(メモリ安全性は保たれる)。巻き戻し経路でリークしうる場合は警告 `W0305`。

## 9. 健全性の要点 (非形式的)

1. **一意性**: U-Bind により LType の値への参照は常に 1 本。種検査により多相コード経由でも複製されない。⇒ LType の値に RC は不要で、破壊的更新は観測できない。
2. **借用の安全性**: 借用中は所有者が `borrow` に保持され、`r` のパラメトリシティにより借用は脱出しない。⇒ use-after-free なし。
3. **共有値**: Perceus の dup/drop は MIR 検証器で静的に整合性を検査する。⇒ 二重解放・解放後使用なし(循環時のリークを除く)。
4. **抜け穴**: `unsafeCoerce`、`Cirka.Unsafe.*`、FFI の型宣言の誤り。これらは `unsafe` 扱いとし、`--deny-unsafe` で禁止できる。

## 10. 検証機能・CirkaLang との関係

- aCHC の型システムは依存型を持たない。検証機能の本体は CirkaLang で扱う ([13-verification.md](13-verification.md))。
- aCHC で任意に行う Liquid 互換注釈の検証 (FEAT-0131) は、型検査が通った Core に対する独立パスで、型推論・型クラス解決には影響しない。
- 多重度 `%0` は aCHC では「実行時に消える引数」で、CirkaLang の QTT の 0 (型・証明) と同じ意味を持つ。共通 Core ではどちらも多重度 0 として消去される。

## 11. 診断コード

| コード | 意味 |
|--------|------|
| E0001 | サポートしていない言語拡張 |
| E0301 | LType の値を多重度 ω で束縛した |
| E0302 | 線形値を消費していない (Drop/Release なし) |
| E0303 | 線形値を2回以上使用した |
| E0304 | `Release` のみを持つ値を純粋な文脈で捨てた |
| E0310 | 種 `Type` の型変数を LType で具体化した |
| E0320 | 借用/リージョン変数の脱出 (rigid 型変数のエラーを言い換えて表示) |
| W0305 | 例外経路で線形値がリークしうる |
| W0401 | 再帰的な値束縛による循環 (RC で回収できない) |
| E0501 | 洗練型・契約の検証失敗 (反例を表示) |
| E0502 | 終了性を示せない (尺度の注釈を促す) |
| W0503 | 検証が SMT のタイムアウトで未決定 |

診断には「なぜ」と「どう直すか」を必ず含める(例: E0301 → 「`borrow` で借用する」「`freeze` で共有可能にする」)。
