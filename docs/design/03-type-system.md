# 03. 型システム (aCHC)

本書は aCHC の型システム。CirkaLang の型システム (QTT 依存型) は [12-cirkalang.md](12-cirkalang.md) §4。
一意性 (U-Bind)・Drop/Release・借用の考え方は両者で共通で、CirkaLang は本書の規則を宇宙 `Type`/`LType` の上でそのまま使う。

aCHC の型システムは **Haskell 2010 の HM + 型クラス** に、
(1) Linear Haskell の **多重度**、(2) Clean 由来の **一意性** を種で表したもの、
(3) **アフィン化 (Drop/Release)**、(4) ランク2による **借用/リージョン** を加えたものである。
参考: Linear Haskell (Bernardy et al. 2018)、Clean、Alms / F° (線形性を種で区別する体系)、
Idris 2 の QTT、Perceus (Reinking et al. 2021)。

## 1. 種 (kind)

```
κ ::= Type | LType | Region | Multiplicity | κ → κ
```

- `Type`: 共有可能な値の型。`LType`: 線形専用の値の型。**部分種 `Type ⊑ LType`**。
- `Region`: 借用・リージョンのスコープ変数の種。値を持たない。
- `Multiplicity`: `One | Many | Zero` と多重度変数。

### 1.1 データ型の種推論 (一意性の伝播)

`data T a₁..aₙ = C₁ τ₁₁..τ₁ₖ | ...` の種は、全フィールド型の種の上限 (lub) とする。

```
kind(T τ̄) = ⊔ { kind(τᵢⱼ[τ̄/ā]) }     Type ⊔ LType = LType
```

これを型引数に対して多相に扱う(**種多相の線形性**)。例: `Maybe :: κ → κ`、`(,) :: κ₁ → κ₂ → κ₁ ⊔ κ₂`。
利用者は `type T :: LType` と注釈して、フィールドが `Type` だけでも線形専用にできる(`Socket` など資源の型)。
`newtype` も同じ規則。関数型 `a %m -> b` の種は常に `Type`
(ただし LType の変数を捕捉するクロージャは線形に束縛される: §2.2)。

### 1.2 型変数

- 型変数の既定の種は `Type`。`forall (a :: LType)` と書くと LType も具体化できる。
- 推論: 関数の本体で型変数 `a` の値がすべて多重度 1 で使われている場合、`a :: LType` に一般化してよい(FEAT-0128 で実装。初期実装は注釈必須)。
- **型クラスの辞書は常に `Type`**(何度でも使える)。クラスの引数は既定で `Type`。`class Drop (a :: LType)` のように明示すれば LType を取れる。

## 2. 多重度と使用量

### 2.1 判断の形

Linear Haskell と同様に、文脈の各変数に多重度を付ける。

```
Γ ::= · | Γ, x :π τ          π ∈ {0, 1, ω} ∪ 多重度変数
Γ ⊢ e : τ
```

使用量の演算は半環 `(0, 1, ω; +, ·)`: `1 + 1 = ω`、`0 · π = 0`、`ω · 1 = ω` 等。
規則は Linear Haskell 論文の λ^q_→ に従う(関数適用 `Γ + π·Δ`、`case` の分岐ごとの使用量の一致など)。

### 2.2 一意性の規則 (aCHC 追加)

**(U-Bind)** 変数を多重度 ω で束縛するとき、その型は `Type` でなければならない。

```
 x :ω τ ∈ Γ  ⟹  τ :: Type
```

すなわち `LType` の値は多重度 1(または 0)でしか束縛できない。これが「LType の値には常に参照が1つしかない」ことを保証する唯一の規則であり、以下はその帰結:

- `LType` の値を ω 引数の関数 (`a -> b`) に渡せない。
- `LType` の値を捕捉するクロージャは、それ自体を多重度 1 で扱う(Linear Haskell の規則で自動的に従う)。
- `forall (a :: Type)` の多相関数を LType で具体化できない(種検査で弾く)。例: `dup :: a -> (a, a)` に `Unique X` は渡せない。

**(U-Arg)** 型注釈のない関数で、引数の型が `LType` と分かる場合は、その矢印を自動的に `%1` とする
(GHC は注釈なしの矢印を常に ω とするが、それでは U-Bind に違反するだけなので推論で補う)。

### 2.3 let の多重度推論

`let x = e₁ in e₂` の多重度は、`e₂` での `x` の使用量から推論する。
`e₁` の型が LType なら 1、そうでなければ使用量に応じて 1 か ω(1 と推論できれば Core で線形情報として最適化に使える)。

### 2.4 実装 (FEAT-0120)

多重度は **型** として表す (ADR-037)。`a %m -> b` は内部の型構築子 `#FUN m a b` で、`m` は型 `#One` / `#Many` / `#Zero`
か型変数。`a -> b` は従来どおり `Fun` (= `#FUN #Many a b`) で、単一化では `Fun` と `#FUN m` を `m := #Many` で一致させる。
HM の単一化・汎化・具体化はそのまま多重度変数も扱う。

- **部分型付けの代わり**: 期待する型が `a -> b` のところ (単一化の最上位) に `a %1 -> b` / `a %0 -> b` を渡してよい
  (線形関数は無制限の関数としても使える)。型構築子の下では行わない (変性を持ち込まない)。GHC 9.x は
  単純化された包摂のためこれを受理せず、η 展開 (`\x -> f x`) を求める。aCHC の受理範囲は GHC より広い (`.hs` の意味は変わらない)。
  逆向きは、データ構築子 (を頭に持つ部分適用) を引数に渡す場合だけ許す (構築子は線形関数)。
- **検査は推論の後の別パス** (`achc-typeck/src/linear.rs`)。推論は、`%1`/`%0` の矢印で束縛される仮引数パターン
  (関数の節・ラムダ・`\case`) と、各引数が渡される矢印の多重度を記録する。検査器は名前解決済みの AST を
  もう一度たどり、局所変数ごとの使用量を半環 `0, 1, ω` で数える:
  - 適用 `f a`: `f` の使用量 + 矢印の多重度 × `a` の使用量。構築子のフィールドは 1 (`Ur` は ω)。
  - `case`/`if`/ガードの分岐は結合する (分岐で使用量が違えば「すべての経路で消費していない」E0302)。
  - 線形に消費された値 (使用量 1 の線形変数を含む式) に対する `case` のパターン変数は線形。ワイルドカードで
    線形の値を捨てると E0302。
  - `let`/`where` の右辺は、束縛した名前の使用量で拡大する (§2.3 の推論)。局所関数は呼び出しごとに自由変数を使う。
    再帰する束縛・遅延パターン束縛・`do` (標準のモナドの `>>=` は無制限)・リスト内包表記・セクションは ω。
  - 多重度変数で束縛された変数は 1 として検査する (最も厳しい具体化)。制約の付かなかった多重度のメタ変数は ω
    (GHC の既定と同じ)。
- 検査は多重度注釈のある束縛だけが対象で、`LinearTypes` を使わないプログラムには影響しない。
- 脱糖で多重度は消える (Core の関数型はすべて `Many`、多重度の型はダミーの型)。Core Lint の多重度検査は
  CirkaLang のフロントエンド (QTT) と一意性 (FEAT-0121) の側で使う。

### 2.5 実装 (FEAT-0121): 種 LType と一意性

種推論 (`Kind`) は `Type` と `LType` を区別しない (`Type ⊑ LType` なので、種の一致だけを見るなら同じ `*` でよい)。
**線形専用かどうかは種とは別の述語 `is_ltype(τ)`** として、推論の後に具体化された型に対して計算する (ADR-038)。

- `is_ltype(τ)`: `type T :: … -> LType` と宣言された型 (`Cirka.Ownership.Unique` を含む) の飽和した適用、
  `forall (a :: LType)` やクラス引数 `(a :: LType)` で宣言された型変数、および **いずれかの構築子のフィールドが線形専用の
  データ型** (§1.1 の lub。再帰は訪問中の型を `Type` とみなして止める)。関数型は `Type`。
- 検査 (使用量の検査器 `linear.rs` と同じパス):
  - **U-Bind (E0301)**: 線形専用の型の値を ω で束縛する — 無制限の矢印 (`->`) の仮引数 (関数の節・ラムダ)、最上位の束縛。
    無制限の矢印への引数として線形専用の値を渡すことも E0301 (引数の側で報告)。
  - **E0310**: 名前の参照で、`LType` と宣言されていない型変数を線形専用の型で具体化した。データ構築子は
    種多相 (§1.1) なので対象外。`>>=`・`>>` など構文から作る参照も対象外 (`do` の束縛は下記)。
    具体化から来た引数の型には E0310 だけを出す (E0301 と重複させない)。
  - 線形専用の型を持つ変数 (パターン・`let`・`do` の `<-`) は、矢印の多重度によらず線形 (ちょうど 1 回) として数える。
    線形専用の値をワイルドカードで捨てると E0302。
- **U-Arg**: シグネチャのない関数の矢印は多重度のメタ変数で作り、本体の推論後に引数の型が線形専用なら `%1`、
  そうでなければ ω に決める (利用側はその型で検査される)。
- **`IO` の `do`**: 文はそれぞれ 1 回、順に実行されるとして数える (他のモナドの `do` は ω)。資源を `IO` の中で
  使い、ブロックの終わりで解放する (FEAT-0122) ための規則で、Linear Haskell (`>>=` が ω) より緩い。
- **一階の引数**: 無制限の矢印への引数でも、引数の型が一階 (関数・`IO`・型変数を値の中に持たない) かつ線形専用でなければ、
  その式が使う線形専用の変数の使用量を ω に拡大しない (例: `print (freeze u)`)。遅延評価でもサンクは高々 1 回評価され、
  その結果は線形専用の値への参照を持てない (持てば型が線形専用になる) ためである。線形専用でない線形変数
  (`%1` で束縛された `Type` の値) は Linear Haskell どおり ω に拡大する。
- `Unique` は `Cirka.Ownership` の `newtype` (`type Unique :: Type -> LType`)。表現は中身と同じで、`freeze` は恒等関数。
  `unique` は FEAT-0123 で破壊的更新が入るまでは O(1) の包装だけで、共有された値のコピーは破壊的更新の側が
  参照カウントを見て行う。`Unique` の構築子はエクスポートしない。
- **RC**: 線形専用の値は 1 回だけ使われるので Perceus は `dup` を挿入せず、必ず消費されるので `drop` も挿入しない
  (`tests/achc/mir/unique.hs` で確認)。Core では多重度を消去したまま (§2.4) で、静的な RC==1 の保証を
  最適化 (再利用の実行時チェックの省略) に使うのは FEAT-0123 で行う。

## 3. アフィン化: Drop / Release

**(Weaken-Drop)** 多重度 1 の変数 `x : τ` を使わずにスコープを抜けることを、`Drop τ` が解決できる場合に限り許す。
エラボレーションで `drop x` を挿入する。

**(Weaken-Release)** 同様に `Release τ` が解決でき、かつ現在の文脈が `IO` の `do` ブロックの場合に限り許す。`release x` を挿入する。

**挿入位置**:

| 種類 | 位置 | 理由 |
|------|------|------|
| `Drop` | `x` を使わない **分岐の先頭** (最も早い時点) | 純粋なので観測できない。メモリを早く返せる (Perceus と同じ) |
| `Release` | `x` を束縛した `do` ブロックの **末尾**、および例外の巻き戻し経路 | 副作用の順序を Rust のスコープ規則と同じく決定的にする |

複数あれば束縛の逆順。挿入は型検査器が「どの経路で何を落とすか」を記録し、脱糖 (Core 生成) で実際の式を作る。

**(Drop の制約)** 利用者定義の `instance Drop T` の本体で呼べるのは、純粋な関数・他の `drop`・
`Cirka.Unsafe.freeOffHeap` 系の解放プリミティブのみとする(`unsafePerformIO` の使用は警告)。

### 3.1 実装 (FEAT-0122)

- 推論は挿入の候補になる式 (右辺の本体・ガードの本体・`if` の分岐・ラムダと `let` の本体・`do` の最後の文・引数) を
  ソース位置付きの印 `tast::Expr::Mark` で包む (線形専用の型を使うプログラムだけ)。使用量の検査器 (§2.4) が挿入を決め、
  型検査の最後のパス (`achc-typeck/src/raii.rs`) が印を外しながら挿入する (ADR-039)。
- 線形専用の変数がスコープで使われない: `Drop` のインスタンスがあればスコープの本体の先頭に
  `dropThen x e` (`case drop x of () -> e`)。`IO` の `do` ブロックで束縛した値はブロックの最後の文 `e` を
  `dropAfter e x` / `releaseAfter e x` で包む (`Drop` があれば `Drop` を優先)。内側 (後に束縛した値) から包むので、
  解放は束縛の逆順になる。
- 分岐の一部でだけ使われる: `Drop` があれば、使わない分岐の本体の先頭に `dropThen` を入れる (最も早い時点)。
  `Release` だけの値は分岐の途中では解放できないので E0302。
- `Release` だけの値を純粋な文脈で使わずに捨てると E0304。どちらのインスタンスもなければ E0302。
- インスタンスは閉じた型についてだけ探す (型変数の `Drop a` を文脈から取ることはしない。その場合は明示的に消費する)。
- **Strict-Linear (§6)**: 線形専用の型の `let` 束縛と、右辺が線形変数を使う `let` を正格にする。線形専用の型の引数で
  変数でないもの (構築子の引数・タプルの成分を含む。BUG-0009) は、呼び出しの前に正格な `let` で評価する。線形専用の型のフィールドは正格。
- `IO` から線形専用の値を返すには `returnL` (`Cirka.Ownership`) を使う (`return` の型変数は `Type`)。
- `Unsafe.*` のモジュールは線形性・一意性を検査しない (`Unsafe.Linear` の `toLinear` / `unsafeReturnIO` の実装のため)。
- 未対応: 例外の巻き戻し経路での解放 (§8、W0305)。aCHC の前期では `error` はプログラムを終了するので、巻き戻しはない。

## 4. 一意性と破壊的更新

`Unique :: Type → LType` は表現が中身と同一の型コンストラクタ。

- `Unique a` の値は U-Bind により唯一の参照なので、`Unique (Array e)` への `write` は in-place で行ってよい。
- `freeze :: Unique a %1 -> a` は恒等関数(実行時コストなし)。凍結後は通常の共有値として RC 管理される。
- `unique :: a -> Unique a` は実行時に RC を確認し、1 なら O(1)、そうでなければコピー(Perceus の `reuse` と同じ判定)。
- **実装 (FEAT-0123)**: 一意性は型で保証するが、in-place 更新の直前には実行時にも RC を確かめる
  (`array_unique` / `bytes_unique`: RC==1 ならそのまま、そうでなければコピー)。遅延評価では一意な値が評価中のサンクや
  未評価のサンクから参照されうるため、型だけに頼ると純粋性が壊れうる。確認は分岐 1 つで、コピーは
  `CIRKA_STATS=1` の `array_copies` で数える。サンクの捕捉変数の移動 (04-memory-model.md §4、ADR-040) と
  Strict-Linear により、通常の書き方ではコピーは起きない (`-- max-array-copies:` でテストする)。
- `Unique a` に対するパターンマッチ: `a` のデータ構築子でマッチすると、フィールドは `Unique` で包まれて多重度 1 で束縛される(Clean の一意性伝播)。ただし一意性が保証されるのはフィールドが RC==1 の場合のみなので、**フィールドの `Unique` 化は実行時に `unique` を通す**(多くの場合、再利用解析で O(1) になる)。

## 5. 借用とリージョン

`Ref`/`MutRef`/`In` の脱出防止は、ランク2型のパラメトリシティ(`runST` と同じ論法)による。
借用関連の検査で新しい規則は不要で、必要なのは:

- `borrow` 系関数がランク2型であることを型検査器が扱える(`RankNTypes`、注釈による検査モード)。
- `Borrow r` / `RIO r` がモナドとして逐次的に、`borrow`/`withRegion` の呼び出しで **正格に** 評価されること(脱糖・Core で保証)。
- `Ref r a` の中身へは `Borrow r` の操作でしかアクセスできない(抽象型としてエクスポート)。

**実装 (FEAT-0124)**: ランク N の引数の剛体変数 (`check_poly` が作るスコーレム) に作成時のレベルを記録し、
それより外側 (レベルの低い) のメタ変数に、そのスコーレムを含む型を代入しようとしたら脱出として拒否する
(GHC の skolem escape と同じ)。借用の型 (`Ref`/`MutRef`/`Borrow` の第 1 引数) のリージョン変数なら E0320、
それ以外は E0604 で報告する。
`Unsafe.*` のモジュールでは、線形専用のフィールドを持つデータ型を種注釈 `... -> Type` で共有可能と宣言できる
(`Ref :: Type -> LType -> Type`。借用は範囲内で何度でも使えるため)。

## 6. 遅延評価との相互作用

**(Strict-Linear)** 次は Core 生成時に正格にする:

1. 型が `LType` の引数・フィールド・`let` 束縛。
2. 右辺が多重度 1 の変数を自由変数に含む `let`。

これにより「サンクが LType の値を捕捉する」ことがなくなり、線形資源の消費・解放の順序がプログラム順に決まる。

## 7. 型クラス

- 辞書渡しで実装。辞書は `Type`(ω)。
- メソッドの型に線形矢印を含めてよい(`class Consumable a where consume :: a %1 -> ()`)。
- 標準のクラス (`Eq`, `Ord`, `Show`, …) の引数は `Type`。LType の値を比較・表示したい場合は借用して中を読む。
- linear-base 互換のクラス `Consumable`, `Dupable`, `Movable` を `Cirka.Ownership` に用意する(FEAT-0121)。

### 7.1 実装 (FEAT-0110)

- **辞書の表現**: クラス `C a` は Core のデータ型 `C a` (コンストラクタ `C$Dict`) になる。フィールドはスーパークラスの辞書、
  続いてメソッド。メソッド自身が型変数や制約を持つ場合 (`foldMap :: Monoid m => ...`) フィールドは多相型 (`forall`) になる。
  メソッド名の大域関数がセレクタ、`C$super{i}` がスーパークラスのセレクタ。
- **インスタンス**: 辞書関数 `$f{C}{n}` (文脈の辞書を引数に取る。文脈がなければ CAF)、各メソッドは `$c{C}{n}${m}`、
  デフォルトメソッドは `$dm{m}` (辞書を引数に取る)。インスタンスメソッドとデフォルトメソッドはクラスの型に具体化した
  型シグネチャで型検査する。重なるインスタンスは E0612、定義のないメソッド (デフォルトもない) は W0613 で実行時エラーになる。
- **制約の解決**: 推論中に必要な辞書は穴 (`Hole`) として記録し、束縛グループの汎化時に解く。制約は頭部正規形に簡約し
  (インスタンスを適用)、汎化する型変数の制約は辞書引数に、外側の型変数の制約は外側へ持ち越す。
  型シグネチャの文脈は与えられた辞書 (スーパークラスを辿って使う)。単相性制限は引数のない束縛とパターン束縛に適用する。
- **defaulting** (Haskell 2010 §4.3.4): 曖昧な型変数の制約に数値クラスが含まれ、制約がすべて `C a` の形のとき、
  `Integer`、`Double` の順に試す。解けなければ E0609。
- **数値リテラル**: `fromInteger n` / `fromRational (n :% d)`。型が `Int`/`Double` に決まれば単なるリテラルに戻す。
  リテラルパターンは型が決まれば通常のリテラル照合、多相なら `(== lit)` による照合 (`Eq` 制約を生む)。
- **do 記法**: `>>=`・`>>` (Monad)。失敗しうるパターンの束縛は `fail` (MonadFail) を呼ぶ。
- **deriving**: `Eq`・`Ord`・`Show`・`Read`・`Enum`・`Bounded`。型検査の前にインスタンス宣言 (改名済み AST) を生成する。
  `Show`/`Read` は GHC と同じ形式 (中置コンストラクタは結合性の優先度、レコード構文、負数の括弧) を出力・受理する。
  文脈は種 `*` の型引数ごとに付ける。それ以外のクラスは newtype なら §7.2 の GND、そうでなければ E0615。
- **レコード** (FEAT-0115): フィールドは選択関数になり、フィールドを持たない構築子には GHC と同じ実行時エラー
  (`No match in record selector f`) の節を足す。構築で省いたフィールドは W0617 (正格フィールドなら E0616) で、
  値は `<位置>: Missing field in record construction f` の実行時エラー。更新はフィールドをすべて持つ構築子ごとの
  `case` で、持たない構築子は `<位置>: Non-exhaustive patterns in record update`。どの構築子もすべてを持たなければ E0601。
  位置は GHC と同じ `file:行:列-列` の形式。
- **`IO`**: `Functor IO` などのため、Core では `IO a` を `Unit# -> a` の newtype とする。`IO` プリミティブは表現の型で書き、
  `foreign import prim` の束縛でキャストする。
- **構文に組み込まれた名前** (`negate`・`>>=`・`fromInteger`・`enumFromTo`・`==`…) は `Cirka.Base` に定義があればそれを、
  なければ `Prelude` のものを使う (テスト用の小さな Prelude のため)。

### 7.2 GHC 拡張の型 (FEAT-0118)

- **MultiParamTypeClasses / FlexibleInstances / FlexibleContexts**: 多引数の制約 `C a b` は、内部の型構築子
  `#MP2` で引数をまとめた 1 引数の制約 `C (#MP2 a b)` として扱い、解決器・汎化・defaulting をそのまま使う
  (ADR-036)。辞書の型は `C a b` (クラスのデータ型は引数を n 個取る)。インスタンスの頭部も同じ形で照合し、
  一致するインスタンスがなく引数に型変数・メタ変数が残る制約は、型変数の制約と同様に外側へ持ち越すか文脈にする。
  関数従属 (`FunctionalDependencies`) は H5。多引数クラスのスーパークラスは未対応 (E0001)。
  インスタンスの頭部は 1 引数クラスでは型構築子の適用でなければならない (FlexibleInstances として `[Char]`・`Maybe Int` は可)。
  文脈には任意の型の制約を書ける (`Show (f Int)`)。
- **GeneralizedNewtypeDeriving**: newtype の `deriving` に標準の導出対象 (`Eq` など) 以外の 1 引数クラスを書くと、
  表現型のインスタンスの辞書を **表現を変えないキャスト** (`tast::Expr::Coerce` → Core の `cast`) で newtype の辞書にする。
  クラス引数が高階の種 (`Functor`) なら newtype の末尾の型引数を両辺から落とす (η 簡約。落とせなければ E0615)。
  文脈は表現型の制約の頭部正規形 (`newtype C a = C a deriving Num` は `Num a =>`)。表現型にインスタンスがなければ E0608。
  newtype は Core で消去されるので、辞書のフィールド (`Int -> Int` と `Age -> Age`) は同じ表現になる。
- **ScopedTypeVariables**: 型シグネチャの **明示的な `forall`** が束縛した型変数は、その定義の本体
  (`where`・内側のシグネチャ・式とパターンの型注釈) で有効。内側のシグネチャはそれらを汎化せず、それらへの制約は外側の
  文脈から解く。`forall` のないシグネチャの型変数は GHC と同じくスコープを持たない。
- **RankNTypes (注釈必須)**: 入れ子の `forall` は `Ty::Forall` になる (引数・構築子のフィールド)。その型の引数は
  使うたびに新しいメタ変数で具体化し、`forall` 型に対して検査する式は型変数を固定 (skolem) して局所的な多相 `let` にする
  (クラス辞書の多相フィールドと同じ形)。型は注釈から決まるものに限り、推論しない。入れ子の `forall` の下の制約は
  未対応 (E0001)。

## 8. 例外と線形性

- 例外の巻き戻し時、スコープ内の線形値は `Drop`/`Release` があれば landing pad で解放する。
- どちらも持たない線形値はリークする(メモリ安全性は保たれる)。巻き戻し経路でリークしうる場合は警告 `W0305`。

## 9. 健全性の要点 (非形式的)

1. **一意性**: U-Bind により LType の値への参照は常に 1 本。種検査により多相コード経由でも複製されない。⇒ LType の値に RC は不要で、破壊的更新は観測できない。
2. **借用の安全性**: 借用中は所有者が `borrow` に保持され、`r` のパラメトリシティにより借用は脱出しない。⇒ use-after-free なし。
3. **共有値**: Perceus の dup/drop は MIR 検証器で静的に整合性を検査する。⇒ 二重解放・解放後使用なし(循環時のリークを除く)。
4. **抜け穴**: `unsafeCoerce`、`Cirka.Unsafe.*`、FFI の型宣言の誤り。これらは `unsafe` 扱いとし、`--deny-unsafe` で禁止できる。

## 10. 検証機能・CirkaLang との関係

- 本書が定める前期 (H1–H4) の aCHC の型システムは依存型を持たない。検証機能はまず CirkaLang で評価する ([13-verification.md](13-verification.md))。
- 後期には GADTs・型族・DataKinds (H5)、Haskell 流の依存型 (`foreach` をシングルトンへ脱糖)・洗練型・契約・全域性 (H6)、ケイパビリティ・効果 (H7) を追加する。
  型規則の追加分は [14-achc-advanced.md](14-achc-advanced.md) に記す。洗練型の検証 (FEAT-0151) は型検査が通った Core に対する独立パスで、型推論・型クラス解決には影響しない。
- 多重度 `%0` は aCHC では「実行時に消える引数」で、CirkaLang の QTT の 0 (型・証明) と同じ意味を持つ。共通 Core ではどちらも多重度 0 として消去される。
