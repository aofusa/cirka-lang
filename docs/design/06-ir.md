# 06. 中間表現 (Core / MIR)

## 1. 共通 Core

aCHC と CirkaLang の合流点となる **消去後の Core** (ADR-021)。GHC Core を簡略化し多重度を加えた、明示的に型付けされたラムダ計算。
型クラス/トレイトは辞書として、暗黙の型適用は明示的な型適用として現れる。

- aCHC: 型推論後の Typed AST を脱糖して生成する (System F + 多重度の範囲に収まる)。
- CirkaLang: 依存型付きの TT ([12-cirkalang.md](12-cirkalang.md) §6) から、多重度 0 の項 (型・証明) を消去して生成する。
  値に依存した型は Core の型では表せないため **`Any` 型と `cast`** に落とす (Agda / Idris の型消去と同様)。
  CirkaLang の `let` はすべて `let!` (正格) になり、`Lazy` だけがサンクになる。

```
Expr e ::= x                                  変数
         | lit                                リテラル (Int#, Double#, Char#, String リテラル)
         | K                                  データ構築子
         | e₁ e₂ | e @τ                       適用 / 型適用
         | λ(x :π τ). e | Λ(a :: κ). e        ラムダ (多重度付き) / 型抽象
         | let bind in e                      let (非再帰 / letrec)
         | let! x :π τ = e₁ in e₂             正格 let (評価してから束縛)
         | case e as x :τ of { alt* }         case (WHNF に評価、x は評価結果)
         | cast e τ                           newtype の変換、Any との変換 (実行時コストなし)
         | prim op(e*)                        プリミティブ演算
alt    ::= K (x :π τ)* → e | lit → e | _ → e
bind   ::= x :π τ = e | rec { (x :π τ = e)* }
```

型には通常の型に加えて `Any` (任意の boxed 値。表現は `ptr`) がある。`cast` は `Any` と boxed 型の間でのみ許し、unboxed 型との `cast` は禁止する。

- **Core Lint** (`cirka-core::lint`): 型・種・多重度(Linear Haskell の Core Lint 相当)・U-Bind 規則・スコープを検査する。`Any`/`cast` は上記の制約の範囲で受け入れる。
  デバッグビルドでは各最適化パスの後に実行し、失敗したらパス名とともに ICE として報告する。
- 最適化パス (`cirka-core::opt`): 簡約 (β・case-of-known-constructor・let 浮動)・インライン・
  **辞書の特殊化** (型クラス/トレイトのメソッドを型ごとに単相化)・正格性/需要解析 (aCHC のみ)・worker/wrapper (unbox)・case-of-case・DCE。
  多重度 1 の情報は「この値は1回しか使われない」として、インラインの安全性判定などに使う。

### 1.1 テキスト形式 (`.core`)

テスト・ダンプ用に S 式のテキスト形式を持つ (`cirka-core::parse` / `print`)。印字結果は再び読み込める。

```
(data List (a) (Nil) (Cons a (List a)))          ; 型引数は a または (a Kind)。(! T) は正格フィールド
(data Handle () :linear (MkHandle Int#))         ; :linear = LType、:newtype = newtype
(extern cirka_write_i64 (Int#) Unit#)            ; C 関数 (ランタイムの規約)
(extern abs (Int#) Int# (c (i32) i32))           ; C シグネチャ付き (FFI、08-ffi.md §7.1)
(def main Int# <expr>)                           ; トップレベル定義 (main : Int# は終了コード)
```

| 形 | 意味 |
|----|------|
| 型 | `Int#` `Double#` `Unit#` (非ボックス)、`Bytes` `(Array a)` `Any`、`(T a ..)`、`(f a)` (型変数の適用)、`(-> [m] A .. R)`、`(forall (a (f (-> Type Type))) T)` |
| 種 | `Type` `LType` `#` `(-> k k)` |
| 多重度 | `0` `1` `ω` (または `w`)。省略時は ω |
| 式 | `x` `42` `1.5` `"str"` `unit`、`(f a b)`、`(@ e T ..)`、`(lam ((x [m] T) ..) e)`、`(tlam (a ..) e)`、`(let ((x [m] T rhs) ..) e)` (遅延)、`(letrec ((f T rhs) ..) e)`、`(let! (x [m] T rhs) e)`、`(case e (b [m] T) Res ((K x (y 1)) e) (0 e) (_ e))`、`(con K (Targs) args..)`、`(prim op [(Targs)] args..)`、`(extern f args..)`、`(cast e T)`、`(panic "msg" T)` |

同じ名前の別の変数は `name~番号` と印字する。

### 1.2 Core Lint の規則 (FEAT-0030)

- 型: System F + 多重度。`Any`/`cast` はボックス値どうしで、種 (Type/LType) を変えない場合のみ。関数型どうしの `cast` は非ボックス位置が一致すること。
- 多重度: Linear Haskell の λ^q と同じ使用量計算。`case` の分岐の使用量は一致しなければならない (`panic` の分岐は任意)。
  `let!` と `case` の束縛は、値が線形資源を持ちえない型 (非ボックス・クロージャを含まないデータ) なら ω で束縛しても評価対象を 1 回の使用と数える。
- U-Bind: ω で束縛する変数の型は種 `Type`。トップレベル定義は ω。
- Strict-Linear: 値でない右辺の遅延 `let` が線形変数を使う、または型が LType ならエラー。非ボックス型の遅延 `let` もエラー。
- `letrec` の束縛は ω。線形変数を捕捉できない。

### 1.3 Core 簡約器 (FEAT-0033)

`cirka-core::opt::optimize` は `-O1` 以上で実行される。パスの順序:

1. **uniquify**: すべての項の束縛子に program 全体で一意な番号を、すべての `Λ` に新しい型変数を振る。以降の代入は捕獲を起こさない。
   続けて **unpack** (FEAT-0041、1.4): 正格な箱型フィールドを unboxed で格納する。
2. **simplify** (不動点まで、最大 6 回): 束縛ごとに出現解析 (出現回数と「束縛子との間にラムダがあるか」) をしてから次を行う。
   - β 簡約 (項と型)。引数がアトムなら代入、unboxed なら `let!`、ω または値なら遅延 `let`、それ以外 (多重度 1 の非値) は唯一の出現位置に代入する (Strict-Linear を守る)。できない場合は元のまま。
   - 小さい (`INLINE_SIZE` = 60 ノード以下) または 1 か所からしか呼ばれないトップレベル関数を、**適用位置でだけ** インライン化する (値として使う位置ではクロージャが増えるのでしない)。再帰する関数は **ループ破り** (FEAT-0071) を除いて対象にする: 呼び出しの閉路をすべて切るように、自己再帰の関数と、相互再帰のグループ (強連結成分) で最も大きい関数を呼び出しのまま残す (残りのグループは同じ規則で繰り返す)。これでグループの小さい関数は大きい関数に溶け、グループは自己末尾呼び出しのループになる。worker/wrapper の wrapper は常にインライン化するので、グラフでは通り抜けて辿る。
   - 遅延 `let` の右辺がアトムなら代入。ラムダの外で 1 回だけ使われるなら、その出現位置に移す (thunk が評価される場所と同じなので意味は変わらない)。ただしコンストラクタ値は束縛したまま残す (確保は同じで、case-of-known に使える)。
   - case-of-known-constructor: 被検査式がコンストラクタ適用、コンストラクタに束縛された変数、コンストラクタを値とするトップレベル束縛 (型クラス辞書)、または外側の `case` の選択肢で形が分かっている変数のとき、選択肢を選んでフィールドを束縛する (正格フィールドは `let!` で評価を保つ)。整数リテラルの `case` も同様。
   - let 浮動: 適用の頭部・`let`/`let!` の右辺・`case` の被検査式にある `let`/`let!` を外へ出す。
   - 定数畳み込み (`add` `sub` `mul` `neg` ビット演算・比較・浮動小数の四則と比較・`int_to_double`。`quot`/`rem` など効果のある演算は畳まない)。
   - 不要束縛の除去: 未使用の遅延 `let`/`letrec`、右辺が全域かつ効果なしの未使用 `let!`。
   - case-of-case (FEAT-0041): `case (case s of p → e) of alts` を `case s of p → case e of alts` にする。内側の選択肢が 1 つ、内側の結果がすべてコンストラクタ/リテラル/panic (外側が既知の形で簡約される)、または外側の選択肢が小さいときに限る。線形の束縛子を含む場合と、外側の選択肢に未消費の 1 回代入が残っている場合はしない。
   - `let!` と `case` の連結 (FEAT-0074): `let! b = (case s of p → e) in case b of alts` は、`b` の使用が scrutinee だけで、上の条件で case-of-case ができるときに `case (case s of p → e) of alts` にする
     (評価の順序は同じ)。CirkaLang の `if` は比較の結果をいったん `scrut$` に束縛してから分岐するので、これで `Bool` を作らなくなる。
   - 正格フィールドの ANF: `let! b = K e` と、全域な `e` についての `let b = K e` を `let! u = e in let b = K u` にして、`b` を既知のコンストラクタにする。
   - 線形性: 線形変数を含む式を ω の束縛へ移さない、線形の case 束縛子を含む case は変換しない、などの条件で Lint 規則 (1.2) を保つ。
   simplify の前に **辞書フィールドの大域化** (FEAT-0112、1.5): トップレベルのコンストラクタ値 (型クラス辞書) の非アトムなフィールドを
   別の大域束縛 `d$fN` にし、全フィールドをアトムにする。これでメソッド選択が case-of-known で解決される。
3. **λ持ち上げ** (FEAT-0112、1.5) の後、もう一度 simplify。
4. **特殊化** (FEAT-0112、1.5) と simplify を最大 2 回。
5. **worker/wrapper** (FEAT-0041、1.4) の後、もう一度 simplify。
6. **strictify** (FEAT-0112、1.5) の後、もう一度 simplify。続けて **float-in**。
7. **dce**: `main` から到達できないトップレベル束縛を削除する。

各パスの後に Core Lint を実行する。simplify は変更した束縛ごとに `lint::lint_bind` で検査し、デバッグビルドでは失敗をパス名付きの ICE とする (リリースビルドではその束縛を変換前に戻す)。
計測 (MIR インタプリタの確保回数、`_build/core-opt-allocs.txt`): `opt_inline` 10001 → 4001、`closures` 10 → 3、`haskell_style` 101 → 99、他は不変。

### 1.4 unboxing: worker/wrapper と正格フィールドの展開 (FEAT-0041)

数値は Core で箱型 (`data Int = I# !Int#`、`Float = F# !Double#` など。**箱型** = 型引数なし・コンストラクタ 1 つ・正格な unboxed フィールド 1 つ・線形でも newtype でもない) なので、
そのままだと演算の結果ごとに割り当てが起きる。次の 2 つで箱を消す。

- **正格性解析** (`cirka-core::ww::strictness`): 式を WHNF まで評価したときに必ず WHNF まで評価される変数の集合を、トップレベル関数について大域的な不動点 (最大不動点) で求める。
  `case` の被検査式・`let!` の右辺・正格フィールド・newtype のコンストラクタのフィールド (表現がフィールドそのものなので。FEAT-0077)・プリミティブ演算の引数・正格な関数の引数は正格。`case` の選択肢は共通部分 (発散する選択肢 `panic` は単位元)、遅延 `let` の右辺は数えない。
  CirkaLang の Core はほぼ `let!` と正格フィールドなので、この解析は CirkaLang では自明に近く、aCHC (遅延) で効く。
- **worker/wrapper** (`ww::worker_wrapper`): 箱型の引数のうち正格なものを unboxed で受け取る worker `f$w` を作り、`f` は箱を開けて `f$w` を呼ぶ wrapper にする。
  すべての戻り値が同じ箱型のコンストラクタ (または発散・自己呼び出し・unboxed で受け取った引数) なら、戻り値も unboxed にする (CPR)。
  wrapper は常にインライン化され、simplify の case-of-known と case-of-case で呼び出し側の箱も消える。
- **評価済みの引数** (FEAT-0056、`ww::evaluated_params`): 正格でない箱型の引数も、**すべての呼び出し** がその位置に評価済みの値
  (`let!`・`case` の束縛・コンストラクタや定数を遅延 `let` で束縛した変数・同じ性質を持つ仮引数) か、先に評価しても安全な式
  (失敗も副作用もないプリミティブ演算・コンストラクタ・評価済みの変数に対する `case` だけでできた小さな式) を渡すなら unboxing する。
  呼び出し前に評価しても意味が変わらないためで、関数全体についての最大不動点で求める。値として使われる (部分適用・引数として渡す) 関数は対象外。
  値渡しの CirkaLang ではほぼすべての箱型の引数がこれに当たる (例: mandelbrot の `go k zr zi cr ci` は `k >= 50` の枝で `zr` を使わないので
  正格ではないが、unboxing される)。aCHC では遅延束縛の変数 (失敗しうる計算のサンク) を渡す呼び出しがあると対象にならない。
  遅延束縛の変数は `strictify` や `float_in` の後で値になることがあるので、worker/wrapper はそれらの後にも走り、`$w` の関数も分割する
  (FEAT-0068。`f$w` は `f$w$w` の wrapper になる。分割のたびに箱の引数が減るので止まる)。
- **正格フィールドの展開** (`cirka-core::unpack`、GHC の `-funbox-strict-fields` 相当): 正格フィールドの型が箱型なら、データ宣言のフィールド型を unboxed に書き換える。
  構築 `K e` は `case e of I# u → K u` に、パターン `K x` は `K u` と `let x = I# u` (遅延・既知のコンストラクタ) に書き換える。`let rec` の右辺で直接使われるコンストラクタは対象外。
  遅延フィールド (aCHC の `!` なしのフィールド) はそのまま。

型クラス/トレイトの **辞書の特殊化** は 1.5 (FEAT-0112) で行う。

計測 (FEAT-0041、確保回数は `CIRKA_STATS=1`): binary-trees (深さ 14) 9,688,585 → 3,222,349、n-body (100,000 ステップ) 19.3M → 13.2M、aCHC の `fib.hs` 88,739 → 728。
時間は [bench-report.md](bench-report.md) を参照。

### 1.5 サンクを減らすパス (FEAT-0112)

遅延評価 (aCHC) で作られるサンクと箱を減らすパス (`cirka-core::strict`、`cirka-core::spec`)。いずれもフロントエンドに依存しない。

- **辞書フィールドの大域化** (`strict::float_dict_fields`): 1.3 の 2 の前に行う。
- **λ持ち上げ** (`strict::lambda_lift`): `let`/`letrec` で束縛された局所関数で、すべての出現が引数の足りた呼び出しの頭部であるものを、
  自由変数 (5 個まで、ω のもの) を引数に、外側の `Λ` の型変数を型引数にとるトップレベル関数 `外側$名前` にする。
  `where` の `go` ループに正格性解析と worker/wrapper が届くようになる。値として渡される関数は (呼び出しのたびに部分適用を作ることになるので) 持ち上げない。
  持ち上げた関数の形は `Λ外側. Λ自身. λ辞書. λ自由変数. λ残りの引数` で (FEAT-0056)、呼び出しが特殊化の対象の形 `f @τ̄ d… e…` のまま残る
  (局所的に一般化された `Num a` のループも特殊化される)。束縛群は本体より先に持ち上げる (外側から): 内側の局所関数が外側の局所関数を
  自由変数 (値) として受け取ると、外側の関数が値として使われることになり持ち上げられなくなるため。
- **特殊化** (`spec::specialize`、GHC の `SPECIALISE` を自動で行うもの): トップレベル関数 `f` の呼び出し `f @τ̄ d₁ … dₖ e…` で、
  型引数がすべて閉じていて、先頭の値引数が辞書 (コンストラクタ名が `$Dict` で終わる値に束縛された大域変数) のとき、
  型と辞書を代入した複製 `f$sN` を作って呼び出しを置き換える。複製の中の再帰呼び出しも同じ複製になる。
  1 プログラムあたり 400 個、関数の大きさ 4000 ノードまで。型シグネチャのない局所関数は一般化されて辞書を受け取るので、λ持ち上げの後の特殊化が効く。
- **strictify** (`strict::strictify`): 1.4 の正格性解析の結果を使い、
  - 本体が変数について正格な遅延 `let` (右辺が値でなく、束縛が ω) を `let!` にする。
  - 既知のトップレベル関数の正格な引数位置にある非アトムな引数を、`let!` で先に評価してから渡す (サンクを作らない)。
- **float-in** (`strict::float_in`): 遅延 `let` を `let!` の後ろへ、さらにそれを使う唯一の `case` の選択肢の中へ移す。
  worker/wrapper が worker の先頭に作る箱 (`let x = I# u`) を、ループの出口でだけ確保するようにする。

**意味**: 正格性解析は発散 (`panic`) をすべての変数について正格とみなす (GHC の最適化と同じ「不正確な例外」)。
そのため、2 つのエラーが競合するとき (`let x = error "a" in error "b"`)、どちらが報告されるかは `-O0` と変わりうる。
値を返すプログラムの結果は変わらない。

計測 (`CIRKA_STATS=1`): `sum [1 .. 10^7]` 相当で、累積値のサンクは 0 (評価されたサンクはリストの遅延した尾の 10^7 個だけ)。
`where` の `go` ループ・型シグネチャのない多相な局所ループ (bang パターン付き) は確保 0 回 (`tests/achc/run/h2/strictness.hs`)。
リストの尾のサンクを消すにはリスト融合 (foldr/build) が要る (FEAT-0055)。

### 1.6 IO の状態トークン (BUG-0011)

`IO a` は `Unit# -> a` の newtype で、`Borrow r a` などはさらにその newtype である。これらを返す関数は、呼び出し側が実行する
アクションをクロージャとして作る。そのため、モナドのループは 1 回ごとにクロージャの木を確保し、それを実行していた。
次のパスと簡約規則で、IO のコードを状態トークンを受け渡す直接の呼び出しにする。

- **辞書の解決** (`strict::float_dict_fields` と既知コンストラクタ表): 型構築子のインスタンス `$fMonad = Λr. Monad$Dict …` の
  非原子フィールドを `name$fN = Λr. field` に出し、`case ($fMonad @τ) of …` を型を代入して解決する。
- **`cast` を通した簡約**:
  - `primBindIO = cast prim$io_bind` のような `cast` の別名をインライン化する。
  - `(cast (λb. e) (t1 -> t2)) a` を `cast (e[b := a]) t2` にする。
  - 入れ子の `cast` はまとめる。`cast` は `let` の本体と `case` の選択肢へ押し込む。
  - `case (cast x N) of K g -> e` (N は newtype) を `e[g := cast x F]` にする。
  - `(case s of p -> e) a` (a はアトム) を `case s of p -> e a` にする。
- **状態トークンの引数** (`io::io_arity`、GHC の「state hack」): 結果が IO 的な型 R (結果の型 a) で、引数がすべて ω の関数 `f = λx̄. e` を、
  worker `f$io = λx̄ w. run(e, w)` (`run` は `let` と選択肢へ押し込み、newtype の構築子と `cast` を剥がし、
  残りを `(cast e (Unit# -> a)) w` にする) と wrapper `f = λx̄. cast (λw. f$io x̄ w) R` に分ける。
  wrapper は常にインライン化される。トップレベル関数と局所 `letrec` の両方が対象で、局所では引数の足りた呼び出しを直接置き換える。
- **ラムダの移動**: 1 回だけ使われる `let` 束縛のラムダは、ラムダの中の出現にも移す (値なので仕事は繰り返さない。bind の継続が対象)。

**意味**: `f x̄` が返すアクションを共有して何度も実行すると、`f` がアクションを返すまでの純粋な計算が実行のたびに繰り返される (GHC と同じ)。
結果は変わらない。

計測 (n-body の借用版、`-O2`):

| | 時間 | 確保回数 |
|---|---|---|
| 修正前 (20 万ステップ) | 28.6 s | — |
| 修正後 (20 万ステップ) | 0.91 s | 38.0M |
| 線形な版 (20 万ステップ) | 0.13 s | 760 |

残りの差は、bind を通る `Double` の箱 (1 ステップ約 190 回の確保) による。

### 1.7 複数の値の返却 (組の結果の CPR、FEAT-0065)

1.4 の CPR は、結果が箱型 (フィールド 1 つ) の関数だけを unboxing する。一意な値の API は `(Unique a, Ur b)` のような組を返し、
再帰関数ではインライン化で消えないので、呼び出しごとに組 (と中の `Ur`・`I#`) を確保する (fannkuch-redux `own.chs` で 1 順列あたり約 9 回)。
これを **箱なしの組** で返す。

- **箱なしの組** `(#n ...#)`: 組み込みのデータ型 `UTup<n>` (n ≥ 2、構築子 `UTup<n>`、フィールドは任意の型) として Core に置く。
  式 `con UTup2 (τ1 τ2) a b`、パターン `case e of (UTup2 x y) -> …`。実行時の表現を持たない (確保しない) ので、Core Lint が次を守らせる。
  - 箱なしの組の値は **関数本体の返却位置** (`case` の選択肢・`let`/`let!` の本体を通した末尾) で構築するか、
    **既知関数の飽和した呼び出しを被検査式とする `case`** でだけ分解する。変数に束縛しない・引数やフィールドに渡さない・クロージャやサンクに入れない
    (`case` の束縛子は使われない場合だけ許す)。
  - `UTup<n>` を返す関数は、トップレベルの関数で、型引数を除いて飽和した呼び出しだけで使われる (部分適用・値としての使用は不可)。
- **組の CPR** (`ww::worker_wrapper` の拡張): 結果の型が「構築子 1 つ・存在型なし・newtype でない・線形でない」データ型 `T` で、
  本体のすべての返却が `K e1 … en` (または発散・worker の自己呼び出し) なら、worker は `(#n e1 … en #)` を返し、wrapper は
  `case f$w x̄ of (UTup<n> y1 … yn) -> K y1 … yn` になる。wrapper は常にインライン化され、呼び出し側の `case` が既知の構築子で消える。
  - **入れ子の平坦化**: あるフィールドがすべての返却で箱型の構築子 (`I# u`) か、そう束縛された変数なら、そのフィールドは unboxed で返す。
    `Ur` のような遅延フィールドも、すべての返却で構築済みの値なら同じく平坦化できる (評価済みの値を返すだけで、意味は変わらない)。
    `(Unique a, Ur Int)` は `(#2 a, Int# #)` で返る。
  - newtype (`Unique` など) は透過なので、`Unique (UArray e)` のフィールドはそのまま `ptr` になる。
  - フィールドが 1 つになった場合は 1.4 の箱型の CPR と同じ (組を使わない)。

MIR では、関数は **複数の結果** を持てる (2.2)。Core の `case f x̄ of (UTup<n> y1 … yn) -> e` は `let (y1, …, yn) = call f(x̄)` に、
返却位置の `con UTup<n> … a1 … an` は `ret (a1, …, an)` になる。

## 2. MIR

Core から次を行った後の、**一階・A正規形・正格・所有権明示** の表現。

- クロージャ変換とラムダ持ち上げ: すべての関数はトップレベル。クロージャは `mkclosure` で明示。
- 遅延評価の明示化: サンクは `mkthunk`、評価は `force`。
- 型消去: 型は実行時表現 (`ptr` / `i64` / `f64` / `i32` / `i8` / `unit` …) だけ残す。
- データ表現の決定: 構築子番号、フィールド順(ポインタ優先)、unboxed フィールド。
- 所有権: 変数ごとに `owned` / `borrowed`、`dup` / `drop` / `reuse` を明示。

### 2.1 構文 (テキスト形式)

テストのため、MIR はテキストで読み書きできる(`cirka-mir::parse` / `cirka-mir::print`)。
M1 では Haskell フロントエンドなしに、このテキストを手書きしてバックエンドを検証する。

```
type List { Nil = 0 {}, Cons = 1 { head: ptr, tail: ptr } }

fn map(f: ptr @owned, xs: ptr @owned) -> ptr {
entry:
  switch xs {
    List.Nil  => nil_case,
    List.Cons => cons_case,
  }
nil_case:
  drop f
  ret xs                              // Nil は静的オブジェクト
cons_case:
  let h  = proj xs List.Cons.head
  let t  = proj xs List.Cons.tail
  dup h
  dup t
  let tok = drop_reuse xs             // RC==1 なら xs のメモリを再利用
  dup f
  let y  = apply f(h)
  let ys = call map(f, t)
  let r  = alloc List.Cons(y, ys) reuse tok
  ret r
}
```

### 2.2 命令

| 命令 | 意味 |
|------|------|
| `let x = lit` / `prim op(a, b)` | 定数 / プリミティブ演算 (整数・浮動小数・比較・ビット演算・ポインタ) |
| `let x = alloc K(args) [reuse tok]` | 構築子オブジェクトの確保 (再利用トークンがあればそれを使う) |
| `let x = proj y K.field` | フィールド読み出し (所有権は移らない: 必要なら `dup`) |
| `let x = call f(args)` | 既知関数の呼び出し |
| `let (x, y, …) = call f(args)` | 複数の結果を返す既知関数の呼び出し (FEAT-0065)。結果はすべて所有 |
| `let x = apply c(args)` | 未知関数(クロージャ)の適用 |
| `let x = mkclosure f(captured)` / `mkthunk f(captured)` | クロージャ / サンク生成 |
| `let x = force y` | WHNF への評価 (`y` が評価済みと分かっていれば最適化で消える) |
| `dup x` / `drop x` | RC +1 / -1 (0 なら解放) |
| `let tok = drop_reuse x` | RC==1 なら x のフィールドを drop してメモリを再利用トークンに、そうでなければ RC-1 して null トークン |
| `let x = extern f(args)` | C 関数の呼び出し (C ABI)。宣言 `extern fn f(i64) -> i64 as c(i32) -> i32` の C シグネチャに従い変換する |
| `set y K.field = x` | 破壊的更新 (所有値のみ。検証器が確認) |
| `prim thunk_init(t, k, x)` | 値の `letrec` (knot-tying) で、確保した直後のサンク `t` の `k` 番目の捕捉変数 (前はすべてポインタ) のプレースホルダを `x` (消費) で置き換える (FEAT-0126) |
| `prim cycle_candidate(x)` | `x` (借用) を循環回収器の根に記録する。モジュールが `collect_cycles` でなければ何もしない (04-memory-model.md §5) |
| `prim bytes_get_i64_unchecked(a, i)` など | 境界検査のない読み書き (`bytes_get`・`bytes_set`・`array_get`・`array_set` とその 8 バイト・共有版のそれぞれに `_unchecked`)。添字が範囲内だと分かった所にだけ `bounds.rs` が置く (FEAT-0069)。インタプリタは範囲外を内部エラーにし、`--runtime=debug` のコード生成は検査を残す |
| `prim is_value(x)` | `x` (借用) が値なら 1。サンク・評価中のサンク・間接参照なら 0 (`force x` が `x` 自身を返すかどうか)。評価しない。遅延の配列の引数の長さを読む前に確かめる (FEAT-0069) |

関数の結果の型は 1 つ (`-> ptr`) か、2 つ以上の組 (`-> (ptr, i64)`) である。複数の結果を返す関数は `ret (x, y, …)` で返り、
LLVM では構造体 (`{ ptr, i64 }`) を返す (x86-64 では 2 つまでレジスタで返る)。`tailcall` は呼び出し元と同じ結果の型の関数にだけ使える。
複数の結果は既知関数の呼び出しにだけあり、クロージャ・サンク・C 関数は 1 つの結果だけを返す。

終端命令: `ret x` / `ret (x, y, …)` / `jump bb(args)` / `switch x { K => bb, ... default => bb }` / `tailcall f(args)` / `panic "msg"`。

### 2.3 MIR 所有権検証器

各基本ブロックの各点で「所有している変数の集合」をデータフロー解析し、次を検査する:

- owned 変数は、すべての経路でちょうど1回消費される(ret・関数への owned 引数・構築子フィールドへの格納・drop のいずれか)。
- 消費済み・未所有の変数を使っていない(`proj` は所有していれば可、結果は借用)。
- borrowed パラメータを消費していない(消費するなら先に `dup`)。
- LType 由来の変数に `dup` が現れない。`set` は所有かつ一意な値にのみ。
- 再利用トークンは同サイズの `alloc` で高々1回使う。

### 2.4 MIR インタプリタ

`cirka-mir::interp` は MIR を直接実行する。オブジェクトの確保/解放を記録し、

- 解放済みオブジェクトへのアクセス、二重解放を検出して失敗する。
- 終了時の生存オブジェクト数(リーク)を報告する。
- 実行テストではコード生成版と出力・確保/解放回数を比較する(差分があればバックエンドのバグ)。

## 3. Core → MIR 変換の段階

1. `let` (遅延) をサンクに、`let!` を正格な評価に (aCHC は正格性解析の結果で `let` を `let!` に置き換え済み、CirkaLang は `Lazy` 以外すべて `let!`)。
2. A正規形化(すべての部分式に名前を付ける)。
3. 自由変数解析 → クロージャ変換 → ラムダ持ち上げ。
   値を含む再帰グループ (`letrec xs = 1 : xs`) は、各メンバーをサンクにし、グループのメンバーを捕捉の先頭に
   プレースホルダ (静的な空の BYTES) として確保してから `thunk_init` で結び、`cycle_candidate` で循環回収器の根に記録する
   (FEAT-0126。以前は C0200 で拒否していた)。関数だけのグループは従来どおり共有環境のラムダ持ち上げ。
4. `case` の決定木を `switch` と基本ブロックへ。
5. 型消去と表現の決定。
6. 自動 `Drop`/`Release` 呼び出しの配置(型検査器が記録した位置)。
7. **Perceus**: 借用推論 → dup/drop 挿入 → drop 特殊化 → 再利用解析 → 冗長な dup/drop の融合。
   借用推論は Lean 4 と同じく dup/drop を含まない MIR 上で先に行い、その結果の引数の所有権に従って dup/drop を挿入する。
   最後に **一意な配列のループの特殊化** (FEAT-0067、`crates/cirka-mir/src/uniq.rs`): 配列の引数を一意性検査してから
   自己末尾呼び出しに渡すループに、その引数が一意だと仮定した関数 `f$u` (引数の `force` と一意性検査を除いたもの) を加え、
   検査済みの値を渡す末尾呼び出しを `f$u` へ向ける。配列が共有されうる経路では `f` へ戻る。
   検査を前に移すのではないので、元のプログラムが写さない配列は写さない。
   続いて **ループの境界検査の入口への移動** (FEAT-0069、`crates/cirka-mir/src/bounds.rs`): 自己末尾呼び出しのループについて、
   整数の引数と配列の引数の長さの間の差分制約 (`i >= 0`、`i <= j`、`hi < len(a)`、`len(a) >= 35` など) の候補から、
   自己末尾呼び出しで保たれ (Houdini 法)、検査を証明するものを選んで前提条件 `P` とする。`P` のもとで必ず成り立つ検査を
   `*_unchecked` に変えた写し `f$b` (自己末尾呼び出しは `f$b` へ) を加え、`f` は入口で `P` を確かめて成り立てば `f$b` へ移る。
   成り立たなければ元のとおり検査しながら回る (`f` の自己末尾呼び出しは `f` の入口へ戻り、`P` をまた確かめる)。
   `force` を通して使う (遅延の) 配列の引数は、長さを読む前に `is_value` で値か確かめる (評価はしない)。
   前提条件なしで成り立つ検査 (ループ自身が `0 <= i < len(a)` を比べる) は `f` の中で直接除く。
   本体 (非巡回の制御フロー) は、経路の条件 (比較と `switch`) と通過した検査で絞りながら、差分制約の行列 (DBM) と
   `k * x + c` の形の値で解析する。整数の演算は桁あふれしないと分かるときだけ一次式として扱う。
   除いた検査は `P` が成り立つ反復では必ず通るので、どの検査がいつ panic するかは変わらない。
   最後に **特殊化した関数への直接の入口** (FEAT-0070、`uniq.rs`): `f$u` を作った関数 `f` の本体を冷たい関数 `f$slow` (`cold fn`) へ移し、
   `f` には入口の検査だけを残す。`f$u` が仮定する引数について `is_unique` (本体が `force` する引数は `is_value` も) を確かめ、
   成り立てば `f$u` へ、成り立たなければ `f$slow` へ末尾呼び出しする。評価も書き込みもしないので意味は変わらない
   (値で `rc == 1` なら、元の経路の `force` と一意性検査は引数自身を返す)。
   冷たい経路は `f$u` と `f$u$b` の写し `f$slow$u`、`f$slow$u$b` を持ち、`f$slow`・`f$b`・写しの末尾呼び出しは写しと `f$slow` へ向ける (FEAT-0073)。
   写しは `cold` にしない。共有やサンクの配列で始まったループはそこで回るので、ほかの関数と同じように最適化される必要がある (FEAT-0076)。
   `f$slow` に入ったループは冷たい経路の中で終わる。写しの本体は `f$u` と同じなので反復の速さは変わらない。ホットな `f$u`・`f$u$b` を呼ぶのは `f` と自分たちだけになり、
   LLVM は `f` の呼び出しの定数をループの中へ伝えられる (回数の決まったループを完全に展開できる)。
   `f$u` の仮定は「一意」だけではない (FEAT-0075)。`force` して次の反復へ渡す引数は「値である」(共有でもよい) を仮定し、入口では `is_value` だけを確かめて、`f$u` では `force` を除く。
   読むだけの引数しかないループも特殊化する。`force` の結果は遅い経路の結果と `phi` で合流するので、LLVM は反復をまたいでこの検査を消せない。
   境界検査の移動の後に行うので、一意な配列の経路では `P` の検査は `f$u` での 1 回だけになる。本体を別の関数にするのは、
   配列のコピーやサンクの評価の呼び出しのために保存するレジスタの push/pop を、呼び出しのないホットパスが払わないようにするため。
   事実は **呼び出しをまたぐ** (FEAT-0076)。`kept_results` は関数ごとに「結果 `j` は引数 `k` をその場でだけ使って返したもの」を求める (`Kept`、呼び出しグラフの不動点、
   自己呼び出しは証明している事実を仮定する帰納法)。この事実は **値が渡されたとき** だけ成り立つ。サンクを渡すと、呼び出し先が `force` して共有された値を返すことがある。
   解析は、そのような呼び出しの結果を同じ配列として追う。`f$u` では呼び出しの結果についての検査も消える (`checked` は呼び出しをまたいで保たれる)。
   事実が呼び出しを通る引数は、入口で `is_value` も確かめる。
   配列を特殊化された関数へ渡すだけのループも特殊化の候補になり、呼び出し先から順に処理する。`f$u` の中では、引数が相手の仮定をすべて満たす呼び出しを `g$u` への直接の呼び出しに変える
   (`g$u` が値を仮定するなら `f$u` も仮定する)。自分自身への非末尾呼び出しも同様。効果のない仮定 (除くものも直接の呼び出しもない引数) は捨てる。
   検査を持たないループは古い本体から `f$u` へ移る手段がないので、一度も検査されていない配列を渡す反復では古い本体が入口の検査を繰り返す (`f$again`、
   成り立てば `f$slow$u` へ)。冷たい経路 (`f$slow`、`f$b`、`f$again`、写し) の呼び出しは特殊化された関数すべてについて冷たいものへ向ける。`g$u` の呼び出し元が増えると LLVM がインライン化しなくなるため (FEAT-0073 と同じ考え方を直接の呼び出しへ広げたもの)。
8. 検証器を実行。
