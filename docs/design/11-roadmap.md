チケット一覧は [../tasks/tasks.md](../tasks/tasks.md)。依存関係の正本は各チケットの「依存」欄。

- 開発中の版表示は `v0.0.N-dev`。

## 6. 進め方 (並行性)

```
共通:      M0 ─► M1 ─► M2 ─► M3 ─┬───────────────────────────────────────────►  SX (必要に応じて)
                                 │
aCHC:                            ├─► H1 ─► H2 ─► H3 ─► H4 (評価レポート) ──────┐
                                 │                                             ▼
CirkaLang:  (0200 仕様は M0 と並行)└─► v0.0.1 ─► v0.0.2 ─► v0.0.3 ─► v0.0.4 ─► … ─► v0.0.7 ─► P2 (v0.1.0)
```

- 共通基盤 M0–M2 を最優先で進める (両試作の前提であり、GC なし・性能という最重要リスクの検証)。
- フロントエンドの前半 (aCHC 0100–0102、CirkaLang 0200–0203) は M1/M2 と並行して進めてよい (共通基盤に依存しないため)。
- **作業が競合したときの優先順位**: 共通基盤 > CirkaLang v0.0.1–v0.0.3 (性能・メモリ安全) > aCHC H1–H3 > CirkaLang v0.0.4 (証明) > それ以外。
- aCHC はスコープを守り、互換性を広げる作業 (対象外の項目) は行わない。

## 7. リスクと早期検証

| リスク | 早期検証 |
|--------|----------|
| RC のオーバーヘッドで性能が出ない | M1 の FEAT-0016 (手書き MIR vs Rust)、M2 の再利用解析、CirkaLang v0.0.1 / v0.0.3 のベンチ |
| 依存型の型検査器の工数 | v0.0.1 は依存型の機能を最小限にし (Vect 程度)、型検査器の骨格 (双方向・NbE・単一化) を先に固める |
| 二つの試作で工数が分散する | 共通基盤を最大化し、aCHC のスコープを縮小 (ADR-025)。優先順位 (§6) を守る |
| 遅延評価 + RC が遅い / リークする | aCHC の H2 (正格性解析)、H3 (循環検出) で計測し、評価レポートに記録 |
| 証明が書きにくい | v0.0.4 で部分集合型の SMT 自動証明を優先し、手動証明は最後の手段にする |
| Vulkan など実用 C ライブラリの FFI が難しい | FEAT-0047 (ABI) と FEAT-0048 (bindgen) を v0.0.6 の前に完成させる |
