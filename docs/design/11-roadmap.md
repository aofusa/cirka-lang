# 11. ロードマップ

ADR-003 に従い、**「GCなし・所有権・ネイティブ速度」の基盤 (MIR + ランタイム + LLVM) を先に作り、
その上に Haskell フロントエンドを載せる**。各マイルストーンには終了条件があり、満たしてから次へ進む
(並行して進めてよいチケットは依存関係で判断する)。

チケット番号は以下の番号帯を使う。一覧は [../tasks/tasks.md](../tasks/tasks.md)。

| マイルストーン | 番号帯 | 目的 | 終了条件 |
|----------------|--------|------|----------|
| **M0 基盤整備** | 0001–0009 | ワークスペース・Docker・テストハーネス・CI・診断 | コンテナ内で `scripts/ci.sh` が通る |
| **M1 バックエンド基盤** | 0010–0019 | 手書き MIR をネイティブ実行。ランタイム・LLVM 生成・末尾呼び出し・クロージャ・サンク | 手書き MIR の binary-trees が動き、リーク 0、Rust の 2 倍以内 |
| **M2 Perceus** | 0020–0029 | dup/drop の自動挿入・借用推論・再利用解析 | dup/drop なしで書いた MIR から、手書きと同等の性能のコードが出る |
| **M3 Haskell 最小フロントエンド** | 0030–0039 | 字句・構文・名前解決・HM 型推論・脱糖・Core・Core→MIR・CLI | 型クラスなしの Haskell (`fact`, `map`, 遅延リスト) が `achc run` で動く |
| **M4 Haskell 実用化** | 0040–0049 | 型クラス・Prelude・正格性解析・IO・数値・レコード・モジュール・FFI(H2010)・差分テスト | 差分テスト集 (50本以上) が GHC と一致、リーク 0 |
| **M5 線形性・一意性・RAII** | 0050–0059 | LinearTypes・Unique/LType・Drop/Release・一意配列・借用・リージョン・循環検出・`.chs` | 一意配列による in-place 版ベンチが Rust の 1.5 倍以内。所有権エラーテスト一式 |
| **M6 FFI 拡張** | 0060–0069 | `extern` ブロック・所有権付きポインタ・構造体・コールバック・bindgen・数学/線形代数ラッパー試作 | libc の `FILE*` を RAII で安全に扱う例、libm を `import "C"` で呼ぶ例が動く |
| **M7 互換性と性能** | 0070–0079 | 例外のアンワインド・GHC testsuite・最適化・エスケープ解析・ベンチ・拡張追加・Hackage | compat 合格率の目標達成 (下記)、G3 の性能目標 |
| **M8 並行性** | 0080–0089 | `forkIO`・`MVar`・共有マーク(アトミック RC)・アロケータ改善 | 並行ベンチが動作しデータ競合なし (TSan) |
| **M9 検証機能** (別軸・優先度低) | 0090–0099 | 洗練型・契約・終了性・境界検査除去・軽量依存型・ケイパビリティ・セッション型 | `tests/verify` 一式が通り、証明による境界検査除去がベンチで効果を示す |
| **P2 CirkaLang** | 0100– | 第一段階の評価と第二段階の言語設計 | 評価レポートと CirkaLang 仕様草案 |

### 互換性の目標 (M7)

- GHC testsuite `should_run` のうち、サポート対象拡張だけを使うもの: 80% 以上合格
- nofib `imaginary` + `spectral`: 70% 以上合格
- `transformers`, `mtl`, `containers` がパッチ少量でビルドでき、それぞれのテストが通る

## リスクと早期検証

| リスク | 早期検証 |
