# 12. CirkaLang 言語設計 (プロトタイプ v0.0.x)

CirkaLang は第一段階の **試作B** として、aCHC と並行して作る (ADR-020)。プロトタイプは v0.0.1 から始め、
プロトタイプごとに v0.0.2, v0.0.3, … と版を上げる。プロトタイプ以降は v0.1.0、言語仕様が完全に固定されたら v1.0.0 とする (ADR-024)。

本書は全版に共通する方針と、各版で入れる機能の設計。各版の厳密な仕様は、その版の仕様チケット
(v0.0.1 は FEAT-0200) で `docs/design/cirkalang/spec-v0.0.N.md` として確定する。

## 1. 目標と性格

| 性質 | 由来 | CirkaLang での実現 |
|------|------|--------------------|
| GC なしのメモリ安全と性能 | Rust / Koka / Lean 4 | Perceus 精密 RC + 一意性 (Clean) + 所有権・借用・RAII。共通基盤 (04, 05) |
| 表現力 | Haskell | 純粋関数型、ADT、パターンマッチ、トレイト (型クラス)、高階関数、モナド |
| 証明 | Idris 2 / Lean 4 | QTT に基づく依存型、全域性検査、等式証明、部分集合型の SMT 自動証明 |
| 一意性による破壊的更新 | Clean | 宇宙 `LType`、`Unique a` |
| 実用性 | Rust / C | 正格評価、C FFI、libc ベースの std、スレッド、ソケット、syscall、Vulkan compute (GUI は遠隔環境で任意) |

## 2. aCHC との主な違い

| 項目 | aCHC (Haskell) | CirkaLang |
|------|----------------|-----------|
| 評価 | 遅延 | **正格** (`Lazy a` で明示的に遅延: ADR-022) |
| 型システム | HM + 型クラス (完全推論) | **QTT 依存型** + トレイト。トップレベルは型注釈必須 (局所的には推論) |
| 型注釈の記号 | `::` | `:` (Idris / Lean と同じ)。リストの cons は `::` |
| 多重度 | `a %1 -> b` | `(1 x : A) -> B` (Idris 2 と同じ)。`0` は消去 |
| 一意性 | 種 `LType` | 宇宙 `LType` (`Type ⊑ LType`) |
| 型クラス | Haskell 型クラス | **トレイト** (一貫性あり: 孤児実装の禁止) |
| 文字列 | `[Char]` | UTF-8 の `String` (所有) / `Str` (借用) |
| エラー | `error` (どこからでも) | 純粋コードは `Result`、`panic` は回復不能エラーのみ |
| 全域性 | なし | `total` / `covering` / `partial` を区別。型・証明に使う関数は `total` 必須 |
| 数値デフォルト | `Integer` | `Int` (64bit。オーバーフローは debug で検査、release でラップ) |

## 3. 構文の素描 (v0.0.1 の目安)

```
module Main

import Core.List

-- 代数的データ型 (型引数は暗黙に 0 多重度 = 消去)
data List (a : Type) where
  Nil  : List a
  (::) : a -> List a -> List a

-- トップレベルは型注釈必須。パターンマッチは等式で書く
map : (a -> b) -> List a -> List b
map f []        = []
map f (x :: xs) = f x :: map f xs

-- 多重度: 1 は線形 (ちょうど1回)、0 は消去 (実行時に存在しない)
swap : (1 p : (a, b)) -> (b, a)
swap (x, y) = (y, x)

-- 依存型: 長さ付きベクトル
data Vect : (0 n : Nat) -> (a : Type) -> Type where
  VNil  : Vect 0 a
  VCons : a -> Vect n a -> Vect (S n) a

append : Vect n a -> Vect m a -> Vect (n + m) a

main : IO ()
main = do
  let xs = map (* 2) [1, 2, 3]
  println (show xs)
```

- レイアウト規則は Haskell と同様 (`where` / `let` / `do` / `case`)。
- 暗黙引数 `{a : Type}` は自動で束縛し、多重度 0 (消去) とする。
- 詳細な文法は各版の仕様書で EBNF として確定する。

## 4. 型システム

### 4.1 コア: QTT による依存型 (ADR-023)

- 内部表現 **TT**: 依存関数型 `(π x : A) -> B` (π ∈ {0, 1, ω})、宇宙、データ型、case tree、`let`。
- **双方向型検査** + メタ変数の単一化 + NbE (評価による正規化) で定義的等価性を判定する (Idris 2 の elaborator を参考)。
- 多重度の検査は QTT の使用量計算 (aCHC の 03 §2 と同じ半環 0/1/ω)。**0 の項は実行時に消去** されるため、型・証明は実行時コストゼロ。
- トップレベル定義は型注釈必須。局所変数・ラムダ・暗黙引数は推論する。
- 型の中で使う関数は `total` (全域) でなければならない (型検査の停止性と証明の健全性のため)。

### 4.2 宇宙と一意性

```
Type   : 共有可能な値の型 (多重度 ω で束縛できる)
LType  : 線形専用の値の型 (多重度 1 / 0 でしか束縛できない)。Type ⊑ LType
```

- 規則 U-Bind (03 §2.2 と同じ): `x :ω A` なら `A : Type`。
- `Unique : Type -> LType`。`freeze : (1 _ : Unique a) -> a`、`unique : a -> Unique a` (RC==1 なら O(1))。
- データ型の宇宙はフィールドの宇宙の上限 (一意性の伝播)。`data Socket : LType where ...` と明示もできる。
- 型変数は既定で `Type`。`{a : LType}` と書けば線形専用型でも具体化できる。

### 4.3 トレイト

```
trait Eq (a : Type) where
  (==) : a -> a -> Bool

impl Eq Int where
  x == y = primEqInt x y

-- 法則を証明として持たせることもできる (v0.0.4 以降、任意)
trait Monoid (a : Type) where
  empty : a
  (<+>) : a -> a -> a
  0 assoc : (x, y, z : a) -> (x <+> y) <+> z = x <+> (y <+> z)
```

- 辞書渡しで実装し、全体プログラムコンパイルで **特殊化 (単相化)** する (ADR-010)。性能上は Rust のトレイトと同等を目指す。
- 一貫性: 実装はトレイトか型の定義モジュールにのみ置ける (孤児実装の禁止)。
- 法則のフィールドは多重度 0 なので実行時の辞書には含まれない。

### 4.4 所有権・RAII・借用

- `Drop` (純粋な終了処理) / `Release` (IO の終了処理) の自動挿入は aCHC (03 §3) と同じ考え方で、正格評価なのでより単純にできる (v0.0.2、spec-v0.0.2.md §5.5、ADR-062)。
  aCHC との違い: 分岐の一部でだけ使う `Release` だけの値も、使わない枝のアクションの終わりで解放できる。型変数の `Drop a` / `Release a` を文脈から取れる。
  線形な値を保持する部分適用・アクションを線形に扱い (ADR-060)、結果が線形なアクションは `IO1` で表す (ADR-061)。
- 借用 (v0.0.3、spec-v0.0.3.md §2、ADR-071):
  - スコープ付き借用 `borrow x (\r, a => …)` で、`r` で添字付けた借用モナド `Borrow a r` / `BorrowIO a r` の中で参照 `Ref a r` を通して読み書きする
    (aCHC の 02 §5 と同じ考え方)。`Ref` / `MutRef` の区別は操作 (`using` / `update`) で表すので 1 種類にした。
  - 実行時は所有者を受け渡す状態の関数で、Core の状態トークンの最適化 (06-ir.md §1.6) によりクロージャも参照数の操作も残らない。
  - 糖衣 `borrow x as a in e` でリージョンを書かずに済む (省略規則の試作)。Rust 風の `&x` / `&mut x` は採らなかった (ADR-071)。
- リージョン (v0.0.3、spec-v0.0.3.md §3、ADR-073): `withRegion` の中で値をアリーナのセルに置き、参照数を持たないハンドル (`In r a` / `RefIn r a`) で指す。循環を含むグラフをリーク 0 で表せる。

### 4.5 証明と検証 (v0.0.4、詳細は [13-verification.md](13-verification.md))

- 全域性: 網羅性 + 終了性 (構造的再帰・size-change・尺度注釈)。
- 等式型 `x = y`、`Refl`、`rewrite`、`with` 抽象。
- **部分集合型** `{x : A | p}` = 「値 `x` と、多重度 0 の証明 `p x`」。証明義務は **SMT (Z3) で自動的に解き**、解けなければ手動証明を書く。
- 契約 `requires` / `ensures` / `invariant` は部分集合型への糖衣。
- 証明できた事実で境界検査などを除去する (ADR-019)。

### 4.6 効果 (v0.0.7)

- v0.0.6 までは `IO` モナド。
- v0.0.7 で **ケイパビリティ** (能力トークン) と **Koka 風の行多相な効果型** を試作する。ハンドラは evidence passing、末尾再開形は関数呼び出しと同じコスト。

## 5. 評価と実行時

- 正格評価。`Lazy a` / `delay` / `force` で明示的に遅延 (共通基盤のサンクを使う)。
- 循環が生じうるのは `Lazy` の自己参照と可変参照 (`Ref`/`IORef` 相当) だけ。静的に警告し、リージョンを勧める。
  v0.0.3 (spec-v0.0.3.md §4、ADR-074): 局所の `let` は再帰せず可変の参照はリージョンだけなので、自己参照はトップレベルの値に限られ、W0310 で警告する。`&&` / `||` は短絡する。
- 例外: `Result` が基本。`panic` は最初 abort、共通基盤のアンワインド (FEAT-0040) 後は unwind し、landing pad で `Drop`/`Release` を実行する。
- メモリモデル・ランタイム・バックエンドは共通基盤 ([04](04-memory-model.md) / [05](05-runtime.md) / [07](07-backend.md))。

## 6. TT から共通 Core への変換 (消去)

1. 多重度 0 の束縛・引数・フィールド (型・証明・暗黙引数) を削除する。
2. 値に依存した型は Core では表せないため、Core 型 `Any` に落とし、必要な箇所に `cast` を入れる
   (Agda / Idris の型消去と同様)。Core Lint は `Any`/`cast` を考慮して検査する。
3. トレイトは辞書 (レコード) に、データ型は Core の ADT に、case tree は Core の `case` に変換する。
4. `let` はすべて正格 (`let!`)、`Lazy` だけサンクにする。
5. 以降は共通の Core 最適化・MIR・Perceus・LLVM。

### v0.0.1 の評価 (FEAT-0207)

- 性能: binary-trees は Rust の 1.60 倍、n-body は 52.9 倍 ([bench-report.md](bench-report.md))。原因は数値のボックス化と
  配列の欠如であり、v0.0.2 の一意な配列 (FEAT-0211) と v0.0.3 の worker/wrapper・unboxing (FEAT-0041) で対処する。
  CirkaLang は正格なので、正格な `Int`/`Float` の引数・戻り値は常に unboxing してよい (FEAT-0041 に記録)。
- 書き味: `&&` が短絡しないので境界検査が入れ子の `if` になる (v0.0.3 で短絡させた、FEAT-0222)。
  `Pair` などの型引数に LType を入れられない (宇宙多相か LType への一般化を v0.0.2 のトレイトとともに検討)。
  `show` がないので数値の出力が型ごとの関数になる (v0.0.2 のトレイト)。
- 所有権: 資源を持たない型の規則 (ADR-030) と、`let` をスコープとして数える規則により、
  `freeze u + 1` や `do` の中の `let 1` が自然に書けた。線形な構造の中の `List Int` も普通の関数に渡せる。
- 正格評価と `do`: `e; rest` を `e >> rest` にすると後続が先に評価されるため `e >>= \_ => rest` に変更した。
  v0.0.2 でモナド一般の `do` にするときも同じ脱糖を使う。

### v0.0.2 の評価 (FEAT-0215)

- 性能 ([bench-report.md](bench-report.md) の「CirkaLang v0.0.2」): 配列のソート・mandelbrot・spectral-norm は Rust と同等、binary-trees は Rust の 0.49 倍、
  文字列処理は 1.6〜2.0 倍、n-body は 10.3 倍。トレイトは全体特殊化で辞書が残らず、`UArray` の `Unbox` も消えた。
  残る差は (1) case の後の計算が結果を箱で受け取ること (結合点、FEAT-0080)、(2) レコードの `Float` フィールドの箱 (v0.0.3、FEAT-0041)。
- 書き味: トレイト・`Result` と `?`・`Std.*` で、ファイルと標準入出力を扱う CUI ツール (`bench/cli-grep`、`run/v002/tool_wc`) が CirkaLang だけで書けた。
  `import M as X` で標準ライブラリの同名の関数 (`length` `read` …) を並べて使える。
  `do` の中の `let` に複数行の `case` を書けない、`_ <-` で結果を捨てられない、組のパターン束縛 `(a, b) <-` がないことは不便で、v0.0.3 の構文の整理に回す (FEAT-0224 で `p <- e | q => h` を入れた。複数行の `case` は字下げで書ける)。
- 所有権: 線形な `File` / `Builder` / `Vec` と `Ur` の組み合わせは素直に書けた。`(File, Result IOError String)` を返す API は
  `case` が一段増えるので、借用 (v0.0.3、FEAT-0220) で `&File` を渡せる形にする。
  `Unique` を速さの約束に留めた (ADR-065) ことで、配列を受け取る高階関数・部分適用に制限がかからなかった。
- FFI: 包む型 (`CInt` など) とスカラーだけの規則で、libc の関数と `withCString` が型安全に呼べた。構造体・コールバックは FEAT-0047 (v0.0.6)。

### v0.0.3 の評価 (FEAT-0223)

- 性能 ([bench-report.md](bench-report.md) の「CirkaLang v0.0.3」): G3 (Rust の 1.5 倍以内) は 7 題材中 5 つで達成。n-body は借用と一意な `UArray` で
  10.3 倍から 1.46 倍になった。文字列処理 (string-split 1.60、cli-grep 1.91) は 1 行あたりの確保が残り、FEAT-0080 / FEAT-0082 で扱う。
- 借用: 状態のモナドとして表したことで、新しい型規則なしに持ち出しを禁止でき、実行時のコストもない (所有版と確保・RC 操作が同じ)。
  書き味は `do` で読み書きを並べられて素直だが、補助関数のシグネチャに `Ref (Unique (U.UArray Float)) r` のような長い型が並ぶ
  (型の別名がないため。第二段階で検討)。結果が `()` の計算の非末尾呼び出しの組の確保は FEAT-0081。
- リージョン: 循環するグラフを `RefIn` で書け、リーク 0 で解放された。ノードの型をリージョンで添字付ける必要があり、`Region` を別モジュールから取り込む手間がある。
- 遅延: `Lazy` と無限ストリームは問題なく書けた。局所の `let` が再帰しないので循環の検出はトップレベルの値だけで足りた。`&&` の短絡で境界検査が平らに書ける。
- `do`: `p <- e | q => h` で `Result` と線形な組の入れ子の `case` がなくなった。

### v0.0.4 の評価 (FEAT-0235)

- 性能に影響しないこと: 証明・部分集合型・契約は多重度 0 で消え、あるプログラムとないプログラムで MIR が一致する
  (`cirkalang_proofs_are_erased`、`cirkalang_contracts_modes`)。証明を使わない既存の 7 題材は v0.0.3 と同じ LLVM IR を生成した
  ([bench-report.md](bench-report.md) の「CirkaLang v0.0.4」)。
- 証明は性能を上げうる: 境界を契約で示した二分探索は、`search` の境界検査がなくなって `--contracts=off` より 4〜6% 速い。
  効果は検査がループの費用の大きな部分を占めるときに限られる (要素が箱の `Array` では読み込みの方が重い)。
- 検証の時間: 検証済みサンプル 3 本で 0.4〜1.0 s (検証なしは 0.2〜0.25 s)。Z3 の答えは記録され、変わらない義務は問い合わせない。
- 書き味:
  - ソート: 長さを型に持つ `Vect` で、長さを保つことは型検査だけで示せた。整列は、3 要素のソーティングネットワークの結果の型
    (`invariant a <= b && b <= c`) を Z3 が示した。任意の長さの整列には「挿入が整列を保つ」補題の帰納法が要り、サンプルには入れていない。
  - 配列: 再帰の引数に `requires 0 <= i` などを付けるだけで `A.index` の境界が示され、示せないときの反例も分かりやすい。
    実行時に作った配列の大きさは検証から見えないので、呼ぶ側で一度 `if` で確かめる必要があった (FEAT-0244)。
  - 構文解析: 位置が入力の中にあることを `ensures` (補助の述語 `within`) で保ち、相互再帰する関数を 1 つずつ示せた。
    このため、結果がレコードのときのフィールドの推論と、部分集合型の結果を持つ呼び出しを展開しない扱いを加えた
    (以前は相互再帰の展開で検証が終わらなかった)。
  - `Int` のラップ: 数学の整数のつもりで書いた性質 (`n + 1 > n`、`fib n >= 0`) は `9223372036854775807` などの反例で落ちる。
    範囲の条件を書く手間は増えるが、検査の除去を安全にするには必要で、境界の証明 (二分探索の `lo + (hi - lo) / 2` など) はそのまま通った。
- 見つかった問題: 検証が `Int` のラップを無視しており、検査の除去と組み合わさるとメモリ安全が破れていた (BUG-0018、ADR-082)。
  トレイトのメソッドを使う不変条件の ICE (BUG-0017)、メタ変数の表のずれによる ICE (BUG-0019)。いずれも修正し、回帰テストを加えた。
- 既知の制限は `CHANGELOG.md` の v0.0.4 (高階の位置の部分集合型、`LType` の部分集合型、型の中のトレイトのメソッド、非線形の義務など)。

- 版の順序は優先順位 (性能・メモリ安全 → 証明 → 実用性の拡大) に従う。評価の結果で内容を入れ替えてよいが、版番号はリリース順に付ける。
- 各版のリリースチケットで、ベンチ結果・評価メモ・既知の制限を記録し、`CHANGELOG.md` を更新してタグ `cirkalang-v0.0.N` を打つ。
- v0.0.6 では Docker 内で Vulkan のコンピュートシェーダだけを扱う。ウィンドウを使う GUI は遠隔の macOS / Windows で任意に検証する (CX、FEAT-0290、[15-gpu-and-remote.md](15-gpu-and-remote.md))。
- CirkaLang で評価した機能は aCHC の後期に取り込む: v0.0.4 の後に依存型・検証 (H5, H6)、v0.0.7 の後に効果・能力・セッション型 (H7) ([14-achc-advanced.md](14-achc-advanced.md))。
- v0.0.7 の後、aCHC の評価 (FEAT-0132, 0164) と合わせて v0.1.0 の言語仕様を作る (FEAT-0300)。

## 9. 第二段階 (v0.1.0 〜 v1.0.0)

プロトタイプで得た評価をもとに、次を決めて作り込む。

- 言語仕様の確定と文法の整理 (プロトタイプ間で揺れた構文の統一)。
- aCHC の評価から: Haskell の何を残し何を捨てるか (遅延の扱い、型クラスとトレイトの差、`do` 記法など)。
- 借用の最終形 (スコープ付き借用か、ライフタイム推論付きの構文か)。
- 効果システムを標準にするか (`IO` との関係)。
- 標準ライブラリ: core / base / std / 外部パッケージ ([09-libraries.md](09-libraries.md))、パッケージマネージャ。
- 分離コンパイルとビルドの高速化、診断の品質、ツール (フォーマッタ・LSP)。
- v1.0.0: 仕様を固定し、以後は互換性を保つ。

## 10. aCHC からの移行

- aCHC で書いた `.chs` から CirkaLang への機械的な変換ツールは、構文の差分が小さければ第二段階で検討する。
- Haskell ライブラリとの相互運用は、aCHC でコンパイルしたコードを C ABI 経由で呼ぶ形が候補 (共通ランタイム上なので比較的容易)。

## 11. ソース内のテスト (v0.0.2、ADR-048)

Rust の `#[test]` と `#[cfg(test)] mod tests` のように、プログラムの本体とテストを **一つのソースファイルに同居** させる (FEAT-0216)。

```
module Text.Digits

digits : Int -> List Int
digits n = if n < 10 then [n] else append (digits (n / 10)) [n % 10]

private square : Int -> Int
square x = x * x

test "digits は 10 進の各桁を返す" =
  assertEqInt (length (digits 1203)) 4

-- テスト用の補助定義はテストのビルドにだけ存在する
tests where
  sample : List Int
  sample = [1, 2, 3]

  test "非公開の関数も試せる" = do
    assertEqInt (square 7) 49
    assert (length sample == 3) "sample"
```

- `test "名前" = 式` はトップレベルの宣言で、式の型は `IO ()`。`test` は文字列リテラルが続くときだけキーワードになる (文脈キーワード。
  `test` という名前の関数は引き続き書ける)。名前はモジュールの中で一意 (重複は E1112)。
- `tests where { 宣言 }` のブロックには、型注釈・定義・データ型・`test` を書ける。ブロックの中の名前はテストのビルドにだけ存在し、
  ブロックの外のテストでない宣言から使うと E1113。
- テストは同じモジュールの非公開の宣言を使える (Rust と同じ)。
- **ゼロコスト**: `cirka build` / `cirka run` は構文解析の直後に `test` と `tests` ブロックを捨てる。生成コード・コンパイル時間に影響しない。
  `cirka check` はテストも型検査する (使われないテストが壊れたままにならないように)。
- `cirka test [--filter=文字列] パッケージ|ファイル` は、パッケージ (またはファイル) から import でたどれるすべてのモジュールのテストを集めて
  一つの実行ファイルを作り、**テストごとに別のプロセスで** 実行する (panic=abort の間もほかのテストに影響しない)。
  `main` は不要で、テスト用の `main` を生成する (`--list` でテストの一覧を出し、引数 `N` で N 番目のテストを走らせる)。
  Prelude が見つからないとテスト用の `main` を作れない (E1114)。既定のランタイムはリークを検査できる debug。
- 失敗: panic (`assert` の失敗を含む)・0 以外の終了コード・リーク (`CIRKA_LEAK_CHECK=1` で実行する)。panic や `exit` で終わった時点で
  生きているオブジェクトはリークとして扱わない (05-runtime.md)。
  出力は `test Text.Digits "digits は 10 進の各桁を返す" ... ok` の形と、最後の集計。失敗があれば `cirka test` の終了コードは 1。
- Prelude に `assert : Bool -> String -> IO ()` と `assertEqInt : Int -> Int -> IO ()` を置く (失敗すると panic)。トレイト (FEAT-0210) の後に
  `assertEq : (Eq a, Show a) => a -> a -> IO ()` を加える。
- aCHC の `.hs` には入れない (Haskell の意味を変えない)。`.chs` への取り込みは後期に検討する。
