# 12. CirkaLang 言語設計 (プロトタイプ v0.0.x)

CirkaLang は第一段階の **試作B** として、aCHC と並行して作る (ADR-020)。プロトタイプは v0.0.1 から始め、
プロトタイプごとに v0.0.2, v0.0.3, … と版を上げる。プロトタイプ以降は v0.1.0、言語仕様が完全に固定されたら v1.0.0 とする (ADR-024)。

本書は全版に共通する方針と、各版で入れる機能の設計。各版の厳密な仕様は、その版の仕様チケット
(v0.0.1 は FEAT-0200) で `docs/design/cirkalang/spec-v0.0.N.md` として確定する。

## 1. 目標と性格

| 性質 | 由来 | CirkaLang での実現 |
|------|------|--------------------|
| GC なしのメモリ安全と性能 | Rust / Koka / Lean 4 | Perceus 精密 RC + 一意性 (Clean) + 所有権・借用・RAII。共通基盤 (04, 05) |
| 表現力 | Haskell | 純粋関数型、ADT、パターンマッチ、トレイト (型クラス)、高階関数、モナド |
| 証明 | Idris 2 / Lean 4 | QTT に基づく依存型、全域性検査、等式証明、部分集合型の SMT 自動証明 |
| 一意性による破壊的更新 | Clean | 宇宙 `LType`、`Unique a` |
| 実用性 | Rust / C | 正格評価、C FFI、libc ベースの std、スレッド、ソケット、syscall、Vulkan |

## 2. aCHC との主な違い

| 項目 | aCHC (Haskell) | CirkaLang |
|------|----------------|-----------|
| 評価 | 遅延 | **正格** (`Lazy a` で明示的に遅延: ADR-022) |
| 型システム | HM + 型クラス (完全推論) | **QTT 依存型** + トレイト。トップレベルは型注釈必須 (局所的には推論) |
| 型注釈の記号 | `::` | `:` (Idris / Lean と同じ)。リストの cons は `::` |
| 多重度 | `a %1 -> b` | `(1 x : A) -> B` (Idris 2 と同じ)。`0` は消去 |
| 一意性 | 種 `LType` | 宇宙 `LType` (`Type ⊑ LType`) |
| 型クラス | Haskell 型クラス | **トレイト** (一貫性あり: 孤児実装の禁止) |
| 文字列 | `[Char]` | UTF-8 の `String` (所有) / `Str` (借用) |
| エラー | `error` (どこからでも) | 純粋コードは `Result`、`panic` は回復不能エラーのみ |
| 全域性 | なし | `total` / `covering` / `partial` を区別。型・証明に使う関数は `total` 必須 |
| 数値デフォルト | `Integer` | `Int` (64bit。オーバーフローは debug で検査、release でラップ) |

## 3. 構文の素描 (v0.0.1 の目安)

```
module Main

import Core.List

-- 代数的データ型 (型引数は暗黙に 0 多重度 = 消去)
data List (a : Type) where
  Nil  : List a
  (::) : a -> List a -> List a

-- トップレベルは型注釈必須。パターンマッチは等式で書く
map : (a -> b) -> List a -> List b
map f []        = []
map f (x :: xs) = f x :: map f xs

-- 多重度: 1 は線形 (ちょうど1回)、0 は消去 (実行時に存在しない)
swap : (1 p : (a, b)) -> (b, a)
swap (x, y) = (y, x)

-- 依存型: 長さ付きベクトル
data Vect : (0 n : Nat) -> (a : Type) -> Type where
  VNil  : Vect 0 a
  VCons : a -> Vect n a -> Vect (S n) a

append : Vect n a -> Vect m a -> Vect (n + m) a

main : IO ()
main = do
  let xs = map (* 2) [1, 2, 3]
  println (show xs)
```

- レイアウト規則は Haskell と同様 (`where` / `let` / `do` / `case`)。
- 暗黙引数 `{a : Type}` は自動で束縛し、多重度 0 (消去) とする。
- 詳細な文法は各版の仕様書で EBNF として確定する。

## 4. 型システム

### 4.1 コア: QTT による依存型 (ADR-023)

- 内部表現 **TT**: 依存関数型 `(π x : A) -> B` (π ∈ {0, 1, ω})、宇宙、データ型、case tree、`let`。
- **双方向型検査** + メタ変数の単一化 + NbE (評価による正規化) で定義的等価性を判定する (Idris 2 の elaborator を参考)。
- 多重度の検査は QTT の使用量計算 (aCHC の 03 §2 と同じ半環 0/1/ω)。**0 の項は実行時に消去** されるため、型・証明は実行時コストゼロ。
- トップレベル定義は型注釈必須。局所変数・ラムダ・暗黙引数は推論する。
- 型の中で使う関数は `total` (全域) でなければならない (型検査の停止性と証明の健全性のため)。

### 4.2 宇宙と一意性

```
Type   : 共有可能な値の型 (多重度 ω で束縛できる)
LType  : 線形専用の値の型 (多重度 1 / 0 でしか束縛できない)。Type ⊑ LType
```

- 規則 U-Bind (03 §2.2 と同じ): `x :ω A` なら `A : Type`。
- `Unique : Type -> LType`。`freeze : (1 _ : Unique a) -> a`、`unique : a -> Unique a` (RC==1 なら O(1))。
- データ型の宇宙はフィールドの宇宙の上限 (一意性の伝播)。`data Socket : LType where ...` と明示もできる。
- 型変数は既定で `Type`。`{a : LType}` と書けば線形専用型でも具体化できる。

### 4.3 トレイト

```
trait Eq (a : Type) where
  (==) : a -> a -> Bool

impl Eq Int where
  x == y = primEqInt x y

-- 法則を証明として持たせることもできる (v0.0.4 以降、任意)
trait Monoid (a : Type) where
  empty : a
  (<+>) : a -> a -> a
  0 assoc : (x, y, z : a) -> (x <+> y) <+> z = x <+> (y <+> z)
```

- 辞書渡しで実装し、全体プログラムコンパイルで **特殊化 (単相化)** する (ADR-010)。性能上は Rust のトレイトと同等を目指す。
- 一貫性: 実装はトレイトか型の定義モジュールにのみ置ける (孤児実装の禁止)。
- 法則のフィールドは多重度 0 なので実行時の辞書には含まれない。

### 4.4 所有権・RAII・借用

- `Drop` (純粋・メモリのみ) / `Release` (IO 内の副作用) と自動挿入規則は aCHC と同じ (03 §3)。正格評価なので挿入位置の説明は aCHC より単純。
- 借用 (v0.0.3):
  - 基本はスコープ付き借用 `Ref r a` / `MutRef r a` と、`r` で添字付けた借用モナド (aCHC の 02 §5 と同じ考え方)。
  - その上に、Rust 風の借用構文 `&x` / `&mut x` と省略規則 (関数内で完結する借用はスコープ変数を書かなくてよい) を試作し、書き味を評価する。
- リージョン (v0.0.3): アリーナ上の確保と一括解放。グラフ構造に使う。

### 4.5 証明と検証 (v0.0.4、詳細は [13-verification.md](13-verification.md))

- 全域性: 網羅性 + 終了性 (構造的再帰・size-change・尺度注釈)。
- 等式型 `x = y`、`Refl`、`rewrite`、`with` 抽象。
- **部分集合型** `{x : A | p}` = 「値 `x` と、多重度 0 の証明 `p x`」。証明義務は **SMT (Z3) で自動的に解き**、解けなければ手動証明を書く。
- 契約 `requires` / `ensures` / `invariant` は部分集合型への糖衣。
- 証明できた事実で境界検査などを除去する (ADR-019)。

### 4.6 効果 (v0.0.7)

- v0.0.6 までは `IO` モナド。
- v0.0.7 で **ケイパビリティ** (能力トークン) と **Koka 風の行多相な効果型** を試作する。ハンドラは evidence passing、末尾再開形は関数呼び出しと同じコスト。

## 5. 評価と実行時

- 正格評価。`Lazy a` / `delay` / `force` で明示的に遅延 (共通基盤のサンクを使う)。
- 循環が生じうるのは `Lazy` の自己参照と可変参照 (`Ref`/`IORef` 相当) だけ。静的に警告し、リージョンを勧める。
- 例外: `Result` が基本。`panic` は最初 abort、共通基盤のアンワインド (FEAT-0040) 後は unwind し、landing pad で `Drop`/`Release` を実行する。
- メモリモデル・ランタイム・バックエンドは共通基盤 ([04](04-memory-model.md) / [05](05-runtime.md) / [07](07-backend.md))。

## 6. TT から共通 Core への変換 (消去)

1. 多重度 0 の束縛・引数・フィールド (型・証明・暗黙引数) を削除する。
2. 値に依存した型は Core では表せないため、Core 型 `Any` に落とし、必要な箇所に `cast` を入れる
   (Agda / Idris の型消去と同様)。Core Lint は `Any`/`cast` を考慮して検査する。
3. トレイトは辞書 (レコード) に、データ型は Core の ADT に、case tree は Core の `case` に変換する。
4. `let` はすべて正格 (`let!`)、`Lazy` だけサンクにする。
5. 以降は共通の Core 最適化・MIR・Perceus・LLVM。

| 版 | テーマ | 主な内容 | 評価項目 |
|----|--------|----------|----------|
| **v0.0.1** | 最小の正格言語・所有権・ネイティブ | 構文、QTT エラボレータ、消去、共通 Core への変換、プリミティブ、`Unique`/`Drop` の最小限 | binary-trees / n-body が Rust 比でどうか |

- 各版のリリースチケットで、ベンチ結果・評価メモ・既知の制限を記録し、`CHANGELOG.md` を更新してタグ `cirkalang-v0.0.N` を打つ。
- v0.0.7 の後、aCHC の評価 (FEAT-0132) と合わせて v0.1.0 の言語仕様を作る (FEAT-0300)。

## 9. 第二段階 (v0.1.0 〜 v1.0.0)

プロトタイプで得た評価をもとに、次を決めて作り込む。

- 言語仕様の確定と文法の整理 (プロトタイプ間で揺れた構文の統一)。
- aCHC の評価から: Haskell の何を残し何を捨てるか (遅延の扱い、型クラスとトレイトの差、`do` 記法など)。
- 借用の最終形 (スコープ付き借用か、ライフタイム推論付きの構文か)。
- 効果システムを標準にするか (`IO` との関係)。
- 標準ライブラリ: core / base / std / 外部パッケージ ([09-libraries.md](09-libraries.md))、パッケージマネージャ。
- 分離コンパイルとビルドの高速化、診断の品質、ツール (フォーマッタ・LSP)。
- v1.0.0: 仕様を固定し、以後は互換性を保つ。

## 10. aCHC からの移行

- aCHC で書いた `.chs` から CirkaLang への機械的な変換ツールは、構文の差分が小さければ第二段階で検討する。
- Haskell ライブラリとの相互運用は、aCHC でコンパイルしたコードを C ABI 経由で呼ぶ形が候補 (共通ランタイム上なので比較的容易)。
