# CirkaLang v0.0.1 言語仕様

- 版: v0.0.1 (プロトタイプ。版間の互換性は保証しない)
- チケット: FEAT-0200 (仕様)、FEAT-0201〜0207 (実装・リリース)
- 位置づけ: [12-cirkalang.md](../12-cirkalang.md) の「v0.0.1: 最小の正格言語・所有権・ネイティブ」を確定したもの。

v0.0.1 の目的は **正格・QTT 依存型・所有権の最小核を共通基盤 (Core → MIR → Perceus → LLVM) の上で動かし、
binary-trees / n-body を Rust と比較できるようにすること** である。証明 (全域性・等式・SMT) やトレイトは後の版で入れる。

## 1. ソースとモジュール

- ソースは UTF-8 のテキストで、拡張子は `.cirka`。
- 1 ファイル = 1 モジュール。モジュール `A.B` はソースルート直下の `A/B.cirka` に置く。
  ソースルートは「入力ファイルのあるディレクトリ」(パッケージでは `src/`) と、コアライブラリ `lib/cirkalang/core/` の 2 つ。
- ファイル先頭の `module A.B` は省略でき、省略時はファイル名 (入力ファイルは `Main`) とする。書いた場合はパスと一致しなければならない。
- `import A.B` はモジュール `A.B` の公開名をすべて取り込む。名前の衝突は使ったときにだけ曖昧さの診断になり、
  修飾名 `A.B.x` で区別できる。循環 import は診断。
- コアライブラリの `Prelude` は暗黙に import される。
- トップレベル宣言は既定で公開。先頭に `private` を付けるとそのモジュール内だけで見える。
- エントリポイントは入力ファイルのモジュールの `main : IO ()`。

## 2. 字句

| 種類 | 規則 |
|------|------|
| 空白・改行 | 区切り。改行と字下げはレイアウト規則 (§2.1) に使う。タブは 8 桁ごとの位置に進める (使わないことを推奨) |
| コメント | `--` から行末 (ただし `-->` のように記号が続くものは演算子)。`{-` 〜 `-}` (入れ子可) |
| 小文字識別子 | `[a-z_][A-Za-z0-9_']*` (単独の `_` は除く) |
| 大文字識別子 | `[A-Z][A-Za-z0-9_']*` (型・コンストラクタ・モジュール名) |
| 修飾名 | `A.B.x` / `A.B.C` / `A.B.+` (`.` の前後に空白を置かない) |
| 演算子 | `[!#$%&*+./<=>?@\\^|\-~:]+` のうち予約記号でないもの。`:` で始まる演算子はコンストラクタ |
| 予約記号 | `:` `=` `=>` `->` `\` `|` `<-` `@` `.` (単独)、`(` `)` `[` `]` `{` `}` `,` `;` `` ` `` |
| 予約語 | `module` `import` `data` `where` `let` `in` `case` `of` `if` `then` `else` `do` `private` `infix` `infixl` `infixr` `prim` (と将来用の `total` `partial` `covering` `trait` `impl` `mutual`) |
| 整数リテラル | `123`、`1_000`、`0xFF`、`0b1010`。型は文脈で `Int` / `UInt` / `Nat` / `Float` (§5.5) |
| 浮動小数リテラル | `1.5`、`2e10`、`1.0e-3` (小数点の両側に数字が必要)。型 `Float` |
| 文字リテラル | `'a'`、`'\n'` `'\t'` `'\r'` `'\0'` `'\\'` `'\''` `'\x41'` `'\u{3042}'` |
| 文字列リテラル | `"..."`。エスケープは文字リテラルと同じ (+ `\"`) |
| ホール | `?name` (型検査で目標の型を表示して止まる) |

### 2.1 レイアウト規則

`where` `let` `do` `of` の直後に `{` がなければ **暗黙のブロック** を開く。

1. 次のトークンの桁 `n` が囲むブロックの桁より大きければ、桁 `n` のブロックを開く。そうでなければ空のブロック `{}` とする。
2. 行頭のトークンの桁 `c` について、`c` が最内ブロックの桁より小さい間ブロックを閉じ、等しければ `;` を補う。
3. `in` は最内の暗黙の `let` ブロックを閉じる。
4. 閉じ括弧 `)` `]` `}`・`,`・`then` `else` `of` は、対応する開き括弧 (または `if` `case`) より後に開いた暗黙のブロックを閉じる。
5. ファイルの末尾ですべてのブロックを閉じる。

トップレベルは桁 1 のブロックである (トップレベルの宣言は桁 1 から書く)。明示的な `{ ; }` も書ける。

## 3. 構文 (EBNF)

```ebnf
module    ::= [ "module" modname ] { import } { topdecl }
import    ::= "import" modname
modname   ::= UIDENT { "." UIDENT }

topdecl   ::= [ "private" ] decl
decl      ::= fixity | sig | clause | data | primdecl
fixity    ::= ( "infixl" | "infixr" | "infix" ) INT op { "," op }
sig       ::= name { "," name } ":" expr
clause    ::= name { apat } "=" expr                   -- 前置の定義
            | apat op apat "=" expr                   -- 中置演算子の定義
primdecl  ::= "prim" name ":" expr                     -- コアライブラリ専用 (§5.6)
name      ::= LIDENT | "(" op ")"

data      ::= "data" UIDENT { dbinder } [ ":" expr ] "where" "{" { consig ";" } "}"   -- GADT 形式
            | "data" UIDENT { LIDENT } "=" conalt { "|" conalt }                   -- 短縮形式
dbinder   ::= "(" [ mult ] LIDENT { LIDENT } ":" expr ")"
consig    ::= conname { "," conname } ":" expr
conalt    ::= conname { atype }
            | atype conop atype                           -- 例: a :: List a
conname   ::= UIDENT | "(" conop ")"

expr      ::= "\" lbinder { "," lbinder } "=>" expr        -- ラムダ
            | "let" "{" { letbind ";" } "}" "in" expr
            | "case" expr "of" "{" { alt ";" } "}"
            | "if" expr "then" expr "else" expr
            | "do" "{" { stmt ";" } "}"
            | pi
            | opexpr [ ":" expr ]?                        -- 注釈は括弧の中だけ: "(" expr ":" expr ")"
pi        ::= binder "->" expr                             -- 依存関数型
            | opexpr "->" expr                            -- 非依存関数型 (右結合)
binder    ::= "(" [ mult ] LIDENT { "," LIDENT } ":" expr ")"
            | "{" [ mult ] LIDENT { "," LIDENT } [ ":" expr ] "}"    -- 暗黙引数
mult      ::= "0" | "1"                                   -- 省略時は ω (暗黙引数と型の引数は 0、§4.2)
lbinder   ::= LIDENT | "_" | "(" [ mult ] LIDENT ":" expr ")"
letbind   ::= LIDENT [ ":" expr ] "=" expr
            | LIDENT apat { apat } "=" expr               -- let f x y = e は let f = \x, y => e
alt       ::= pat "=>" expr
stmt      ::= LIDENT "<-" expr | "let" "{" { letbind ";" } "}" | expr

opexpr    ::= [ "-" ] app { op app }                       -- 優先順位は fixity 宣言 (§3.1)
app       ::= atom { atom }
atom      ::= LIDENT | UIDENT | qualname | literal | "?" LIDENT | "_"
            | "Type" | "LType"
            | "(" ")" | "(" expr ")" | "(" expr ":" expr ")"
            | "(" expr "," expr { "," expr } ")"          -- タプル (Pair の入れ子)
            | "(" op ")" | "(" op app ")" | "(" app op ")" -- 演算子とセクション
            | "[" [ expr { "," expr } ] "]"                -- リスト
            | "`" name "`"                                 -- 関数の中置 (op として扱う)
atype     ::= atom                                         -- 短縮形式のフィールド型 (括弧で囲めば任意の型)

pat       ::= apat { op apat }                             -- 中置コンストラクタ (x :: xs)
            | conname { apat }
apat      ::= LIDENT | "_" | UIDENT | literal | "-" INT
            | "(" pat ")" | "(" pat "," pat { "," pat } ")" | "(" ")"
            | "[" [ pat { "," pat } ] "]"
```

### 3.1 演算子の優先順位

`infixl n op` / `infixr n op` / `infix n op` (0 ≤ n ≤ 9) で宣言する。宣言はモジュールを越えて有効で、宣言のない演算子は `infixl 9`。
関数適用は演算子より強い。前置の `-` は `negate` で、優先順位 6 の左結合演算子と同じ強さ。
Prelude の宣言:

| 優先順位 | 演算子 |
|----------|--------|
| 9 (右) | `.` (関数合成。前後に空白が必要) |
| 7 (左) | `*` `/` `%` `*.` `/.` |
| 6 (左) | `+` `-` `+.` `-.` `++` |
| 5 (右) | `::` |
| 4 (無) | `==` `/=` `<` `<=` `>` `>=` `==.` `<.` `<=.` `>.` `>=.` |
| 3 (右) | `&&` |
| 2 (右) | `||` |
| 1 (左) | `>>=` `>>` |
| 0 (右) | `$` |

`->` は型の矢印で、どの演算子よりも弱く右結合。

## 4. 型システム

### 4.1 内部表現 TT

エラボレータは表層の構文を **TT** (依存型付きの内部言語) に変換して検査する。TT の項:

```
t, A, B ::= x | c (大域名・コンストラクタ・データ型) | Type | LType
          | (π x : A) -> B | \(π x : A) => t | t u | let π x : A = t in u
          | case t as x return B of { C ys => u; ... ; _ => u }
          | literal | prim op | ?m (メタ変数)
π       ::= 0 | 1 | ω
```

- 定義的等価性は **NbE** (評価による正規化) で判定する。大域定義の展開 (δ)・β・`case` の ι・`let` の ζ・リテラルのプリミティブ演算を行う。
  η 規則は関数型に対してのみ行う。
- 型検査は **双方向** (検査 ⇐ / 推論 ⇒)。暗黙引数・`_` はメタ変数になり、パターン単一化で解く。解けないメタ変数は診断 (E1210)。
- 型検査中の評価は燃料 (既定 1,000,000 ステップ) で打ち切り、超えたら診断 (E1220)。v0.0.1 は全域性を検査しないので、型の中での停止しない計算はこれで止める。

### 4.2 多重度 (QTT)

多重度は半環 {0, 1, ω} (`0+π = π`、`1+1 = ω`、`0·π = 0`、`1·π = π`、`ω·ω = ω`)。

- 関数型 `(π x : A) -> B`: 引数を実行時に π 回使う。0 は **消去** (実行時に存在しない)。
- 既定: 明示引数は ω。暗黙引数 `{x : A}` と、型が宇宙 (`Type` / `LType` / `… -> Type`) である引数は 0。
- 使用量の計算: 変数の出現は 1。`f a` で `f : (π x : A) -> B` なら `a` の使用量を π 倍する。型の位置 (多重度 0 の引数・注釈・型) の出現は 0 と数える。
  ただし **資源を持たない型** (§4.4 の下に定義) の引数は、π = ω でも 1 倍とする (正格評価で 1 回だけ評価され、結果は線形資源を含みえない。ADR-030)。
  引数の型が未解決のメタ変数を含む (`List ?a` など) ときは、引数を検査してメタ変数を解いた後で判定する。
  コンストラクタの引数は、構築した値の使用量で数える (フィールドが ω でも、値が 1 回使われるなら 1)。
- 束縛子 `π x` は本体での使用量 `ρ` について `ρ = π` (π が 0 か 1 のとき) / 任意 (π = ω のとき) を満たさなければならない。
  ただし `π = 1` で `ρ = 0` のときは **Weaken-Drop** (§4.4) を適用できれば許す。
- 分岐 (`case` / `if`) の各枝の使用量が異なる線形変数は、少ない枝に Weaken-Drop を適用できる場合だけ許す。
- ラムダが捕捉する変数の使用量は、そのラムダの使用量倍になる (ω で使われる関数に線形変数を閉じ込められない)。
- `let x = e in b` の多重度は省略時に推論する: `e` の型が LType なら 1、そうでなければ ω。`let 1 x = …` / `let 0 x = …` と明示もできる。
  `e` が線形変数を使うなら `x` は 1 でなければならない (`e` の型が資源を持たない型なら ω でよい)。

### 4.3 宇宙と一意性

```
Type  : Type        -- v0.0.1 は Type-in-Type (論理としては不健全。証明を入れる v0.0.4 で階層化する)
LType : Type
Type ⊑ LType        -- Type の型は LType が期待される場所で使える
```

- **U-Bind**: 多重度 ω の束縛 (ω の引数・ω の `let`・ω で使われる値のフィールド) の型は `Type` でなければならない。LType の値を ω で束縛すると E0301。
- 型変数は既定で `Type`。`{a : LType}` と書けば LType の型でも具体化できる。
- データ型の宇宙: GADT 形式では宣言 (`: … -> Type` または `: … -> LType`) に従い、`Type` と宣言した型が LType のフィールドを持てば E1203。
  短縮形式ではフィールドに LType の型があれば LType、なければ Type と推論する。
- 組み込みの一意型 `Unique : Type -> LType`:
  - `unique : a -> Unique a` — 値を一意として包む (v0.0.1 は表現上は恒等。RC==1 を保証する複製は配列と同時に v0.0.2 で入れる)
  - `freeze : (1 u : Unique a) -> a` — 共有可能な値に戻す

### 4.4 所有権 (Weaken-Drop)

v0.0.1 の型はすべてメモリだけを持つので、次の型は組み込みの `Drop` を持つ (使わずに捨ててよい。解放は Perceus が行う):

- 宇宙 `Type` のすべての型、`Unique a`
- `Drop` を持つ型のフィールドだけからなる LType のデータ型

GADT 形式で `LType` と宣言し、かつコンストラクタを持たないか、`Drop` を持たないフィールドを含むデータ型は `Drop` を持たない。
そのような値は必ずパターンマッチ (または引数として渡すこと) で消費しなければならない (E0302)。利用者定義の `Drop` / `Release` はトレイトとともに v0.0.2 で入れる。

所有権の診断:

| コード | 意味 | 直し方の案内 |
|--------|------|--------------|
| E0301 | LType の値を多重度 ω で束縛・使用した | 引数を `(1 x : A)` にする / `freeze` で共有可能にする |
| E0302 | 線形値を消費していない (Drop なし) | パターンマッチで分解する / 関数に渡す |
| E0303 | 線形値を 2 回以上使用した | 1 回だけ使う / `freeze` する |
| E0304 | 多重度 0 (消去) の変数を実行時に使った | 引数の多重度を ω か 1 にする |
| E0305 | 線形変数を ω で使われるクロージャに捕捉した | クロージャを線形に使う |
| E0306 | 線形変数の使い方が分岐ごとに異なる (Drop なし) | すべての分岐で消費する |

**資源を持たない型**: プリミティブの `Int` `UInt` `Float` `Char` `String`、および宇宙 `Type` のデータ型で、すべてのコンストラクタの
実行時のフィールドが資源を持たない型であるもの (再帰的に。`List Int` は資源を持たないが、`List (Int -> Int)` や型変数は持ちうる)。
関数・`IO`・型変数・LType の型は資源を持ちうるとみなす。

### 4.5 データ型とパターンマッチ

```
data List (a : Type) where
  Nil  : List a
  (::) : a -> List a -> List a

data Vect : (0 n : Nat) -> (a : Type) -> Type where
  VNil  : Vect 0 a
  VCons : a -> Vect n a -> Vect (S n) a

data Maybe a = Nothing | Just a      -- 短縮形式
```

- コンストラクタの型は、データ型を返す関数型でなければならない (E1201)。返す型の引数のうち `dbinder` で束縛したもの (パラメータ) はそのまま、
  それ以外 (添字) は任意の項でよい。
- 型シグネチャ・コンストラクタのシグネチャに現れる **未束縛の小文字識別子** は、先頭に暗黙引数 `{x : _}` (多重度 0) として自動で束縛する。
- 等式による定義は **case tree** に変換する。パターンは上から順に照合し、最初に一致した等式を使う。
- **網羅性**: 照合されない値が残ると E1230 (v0.0.1 は部分関数を書けない。`panic` で明示する)。到達しない等式は警告 W1231。
- **依存パターンマッチ**: `x : D ps is` を分解するとき、各コンストラクタの返す型の添字と `is` を単一化する。
  - 一方が変数ならその変数をもう一方で置き換える (分岐の中で型が精密になる)。
  - 両方がコンストラクタなら引数ごとに単一化し、コンストラクタが異なればその分岐は **到達不能** として省略できる。
  - それ以外 (計算の途中で止まった項同士など) で定義的に等しくないときは E1232。
- 多重度: 多重度 π の値を分解すると、コンストラクタの多重度 ρ のフィールドは多重度 `π·ρ` で束縛される (ただし π = 1 かつ ρ = ω なら 1)。
  多重度 0 のフィールドは消去される。

## 5. 評価と実行時

### 5.1 正格評価

- 値呼び: 関数適用は、関数・引数の順 (引数は左から右) に評価してから呼ぶ。多重度 0 の引数は評価しない (存在しない)。
- `let x = e in b` は `e` を評価してから `b`。コンストラクタのフィールドはすべて正格。
- `if` / `case` は選ばれた分岐だけを評価する。`&&` `||` は Prelude の関数だが、v0.0.1 では両辺を評価する (短絡評価は `Lazy` とともに v0.0.3)。
- 遅延評価 (`Lazy a`) は v0.0.3。v0.0.1 の再帰的な値束縛はない (トップレベルの値は最初に使われたときに一度だけ評価される)。

### 5.2 IO

- `IO a` は組み込みの型。`pure : a -> IO a`、`(>>=) : IO a -> (a -> IO b) -> IO b`、`(>>) : IO a -> IO b -> IO b`。
- `do` ブロックは `>>=` / `>>` に脱糖する (v0.0.1 は `IO` 専用。モナド一般はトレイトとともに v0.0.2)。
  `x <- e; rest` は `e >>= \x => do rest`、`e; rest` は `e >>= \_ => do rest` (正格評価なので、`e >> do rest` だと後続の引数が `e` の実行前に評価されてしまう。後続をラムダの下に置いて遅延させる)、`let x = e; rest` は `let x = e in do rest`。
- `main : IO ()` を実行し、正常終了なら終了コード 0。`exit : Int -> IO a` で任意の終了コードで終わる。

### 5.3 パニック

`panic : String -> a` はメッセージを標準エラーに出して異常終了する (終了コード 1。共通ランタイムの `cirka_panic`)。0 除算・`Nat` の負への減算 (`minus` は 0 で止まるので起きない) なども同じ。
v0.0.1 は abort であり、アンワインドは共通基盤の FEAT-0040 以降。

### 5.4 プリミティブ型

| 型 | 内容 | Core での表現 |
|----|------|---------------|
| `Int` | 64bit 符号付き整数。演算はラップする (オーバーフロー検査は v0.0.3) | `data Int = I# Int#` |
| `UInt` | 64bit 符号なし整数 (加減乗・比較・ビット演算。除算は v0.0.2) | `data UInt = W# Int#` |
| `Float` | IEEE 754 binary64 | `data Float = F# Double#` |
| `Char` | Unicode スカラー値 | `data Char = C# Int#` |
| `String` | 不変の UTF-8 バイト列 | `Bytes` |
| `IO a` | 入出力の動作 | `Unit# -> a` |
| `Unique a` | 一意な `a` | `a` の表現 |

`Bool`・`Unit` (`()`)・`Nat`・`Maybe`・`List`・`Pair` (タプル) は Prelude の普通のデータ型である。

### 5.5 リテラルの型

整数リテラルは期待される型が `Int` / `UInt` / `Nat` / `Float` ならその型、期待される型がない (推論する) ときは `Int`。
`Nat` のリテラルは `S (S … Z)` に展開する (10,000 まで。型の添字に使う)。

### 5.6 プリミティブ宣言

`prim name : T` はコアライブラリ (`lib/cirkalang/core`) の中だけで書け、実装をコンパイラが与える関数を宣言する。
v0.0.1 のプリミティブ (名前と意味は Core の primop / ランタイム関数に対応する) は FEAT-0206 で `lib/cirkalang/core/Prelude.cirka` に列挙する。

## 6. 共通 Core への変換 (消去)

1. 型検査後の TT を正規化した型情報とともに Core に変換する。多重度 0 の束縛・引数・フィールド・ラムダはすべて消える。
2. 型: 多重度 0 で型を受け取る引数は Core の `forall` / 型適用になる。データ型の Core のパラメータは、TT のパラメータのうち型 (宇宙) であるものだけで、
   値の添字 (`Vect` の `n`) は消える。正規化しても Core の型で表せない型 (値に依存して計算される型) は `Any` にし、
   Core の型が食い違う箇所に `cast` を入れる。
3. TT の `let` は Core の `let!`、関数適用の引数・コンストラクタのフィールドは先に `let!` で評価してから渡す (正格評価を Core の遅延評価の上で表す)。
   データ型のコンストラクタのフィールドは Core で正格フィールドにする。
4. Core の束縛の多重度と種は v0.0.1 ではすべて ω / `Type` とする。線形性は TT で検査済みであり、v0.0.1 では LType の値も暗黙の `Drop` で
   使わずに捨てられる (§4.4) ため、Core Lint の線形検査 (未使用の線形変数を誤りとする) とは整合しない。
   利用者定義の `Drop` が入る v0.0.2 で、Drop の明示的な挿入とともに Core の多重度 1 を復活させる。
5. プリミティブ (§5.6) は Core のトップレベル関数として生成する (ボックス化した値を `case` で開いて primop を呼ぶ)。文字列の連結・比較・
   数値の文字列化・整数の読み込みは、変換器が持つ Core の補助関数 (`cirka$…`) で実装する。
6. 生成した Core は Core Lint を通らなければならない (通らなければコンパイラの内部エラー)。以降は共通の Core 最適化・MIR・Perceus・LLVM。

## 8. 例

```
module Main

data Tree = Leaf | Node Tree Tree

make : Int -> Tree
make 0 = Node Leaf Leaf
make d = Node (make (d - 1)) (make (d - 1))

check : Tree -> Int
check Leaf = 0
check (Node l r) = 1 + check l + check r

append : Vect n a -> Vect m a -> Vect (n + m) a
append VNil ys = ys
append (VCons x xs) ys = VCons x (append xs ys)

swap : (1 p : (a, b)) -> (b, a)
swap (x, y) = (y, x)

main : IO ()
main = do
  printInt (check (make 10))
  let v = append (VCons 1 VNil) (VCons 2 (VCons 3 VNil))
  printInt (vlength v)
```
