# CirkaLang v0.0.4 言語仕様

- 版: v0.0.4 (プロトタイプ。版間の互換性は保証しない)
- チケット: FEAT-0230 (全域性)、FEAT-0231 (等式と証明)、FEAT-0232 (部分集合型と SMT)、FEAT-0233 (契約)、FEAT-0234 (検査除去)、FEAT-0235 (リリース)
- 位置づけ: [12-cirkalang.md](../12-cirkalang.md) の「v0.0.4: 証明と検証」と [13-verification.md](../13-verification.md) を確定したもの。

v0.0.4 の目的は、**プログラムが仕様を満たすことを型と証明で示せる** ようにし、しかも **証明が生成コードの性能を落とさない** (多重度 0 で消える) ことを確かめることである。
この文書には [spec-v0.0.3.md](spec-v0.0.3.md) からの差分だけを書く。書いていないことは v0.0.3 のとおり。
各節は対応するチケットの完了時に書き足す。

## 1. 全域性 (FEAT-0230)

### 1.1 宣言

```
total
length : List a -> Int
length [] = 0
length (_ :: xs) = 1 + length xs

partial
head : List a -> a
head (x :: _) = x
```

- 関数の型シグネチャの前 (同じ行か前の行) に `total` / `covering` / `partial` を書ける。書かなければ `covering`。
  - **`covering`**: パターンが網羅的 (v0.0.1 からの規則。欠けていれば E1230)。停止性は問わない。サーバの主ループのように止まらない関数はこれで書く。
  - **`total`**: 網羅的で、**どの引数でも停止し、`panic` しない**。使う関数もすべて全域でなければならない。
  - **`partial`**: パターンが網羅的でなくてよい。欠けた場合に来ると `panic` する (メッセージは `関数名: missing case `例``)。
- 全域性は **推論される**: `total` と書いていない関数も、全域かどうかを (必要になったときに) 判定し、`total` な関数から呼べる。
  `total` は「全域であることを確かめ、そうでなければエラーにする」宣言である。
- `panic` を使う関数、`partial` と宣言した関数、それらを使う関数は全域でない。
  プリミティブ (`panic` を除く) と `extern` の関数は全域とみなす (FFI の境界は信頼する)。`IO` の動作は値として全域であり、実行したときに止まるかは問わない。
- トレイトのメソッドの呼び出しは、インスタンスが分かれば **そのインスタンスのメソッド** を呼ぶものとして扱う (`xs == ys` を `List Int` で使えば、リストの `==` の全域性が問われる)。
  辞書を引数で受け取る関数の中のメソッド呼び出しは全域とみなし、具体的なインスタンスを渡す側でそのインスタンスの全域性を問う。
  既定のメソッドや辞書を受け取る関数に既知のインスタンスを渡す呼び出しは、その場でインスタンスを入れて調べる (既定のメソッドどうしが呼び合う無限ループも見つかる)。

### 1.2 終了性

関数の停止は、次の **size-change 原理** で示す。

- 関数の本体の `case` で値を分解すると、そのフィールドは元の値より **構造的に小さい** (帰納的なデータ型の値の大きさ)。
  分解した値を同じ構成子で組み直した値 (`ack (S m) n` の `S m`) は元の値と **等しい**。
- 関数 (互いに再帰する関数の組を含む) の再帰呼び出しごとに、各引数が呼び出し元の各引数より「小さい / 等しい / 不明」かを記録した呼び出しグラフを作る。
  グラフを合成した閉包の中の、関数から自身へのべき等なグラフがすべて、どれかの引数で真に小さくなっていれば停止する。
- これで引数を入れ替える再帰 (`f (S x) y = f y x`)、相互再帰、アッカーマン関数などが示せる。
- **正でないデータ型** (`data Bad = MkBad (Bad -> Int)` のように、自身が関数の引数の位置に現れる型) は構造的な順序が整礎でないので、
  その構成子を使う関数は全域でない。
- 関数を引数に渡す (`map f xs` の `f` が再帰している) 再帰は、呼び出しの引数の大きさが分からないので示せない。

### 1.3 尺度

構造的に小さくならない再帰は、**尺度** (整礎な大きさ) で示す。

```
total
gcd : Int -> Int -> Int
gcd a 0 = abs a
gcd a b = gcd b (a % b) decreasing abs b

total
countdown : Int -> Int
countdown n = if n <= 0 then 0 else countdown (n - 1)     -- 尺度は自動 (n)
```

- 節の右辺の後に `decreasing e` を書く。`e` は `Int` か `Nat` の式で、その節で **引数に直接束縛された変数** (上の `b`) を使える。尺度は関数に 1 つ (2 つ目は E1005)。
- 意味: 関数が自身を呼ぶどの場所でも、そこまでの道筋で分かっていること (`case` で合った構成子・リテラル、`if` の条件) のもとで、
  **呼び出しの引数での `e` < 仮引数での `e`** であり、`Int` の尺度では **仮引数での `e` ≥ 0** である。
  この証明義務を Z3 で決める (`CIRKA_Z3`、タイムアウトは `CIRKA_VERIFY_TIMEOUT` ミリ秒)。決めた結果は `_build/<名前>/verify/` に記録して再利用する。
- `decreasing` がなく size-change 原理で示せない、自身だけを呼ぶ再帰では、**`Int` / `Nat` の引数を 1 つずつ尺度として試す** (Z3 があるとき)。`countdown` はこれで示せる。
- 尺度が成り立たないときは E0502 に **反例** (変数の値) を添える。Z3 がなければ、尺度が要る関数は全域と示せない (E0502、Z3 がない旨を表示)。
- 尺度の検査では `Int` を数学の整数として扱う (64 ビットの桁あふれは考えない)。
- 尺度は直接の再帰 (自身の呼び出し) に使う。相互再帰は size-change 原理で示す。トレイトのメソッドには尺度を書けない (E1004)。
- 尺度は検査だけに使い、実行時には何も残らない。

### 1.4 型の中の関数

- 型シグネチャ・データ型・構成子・プリミティブの型の中で使う関数は全域でなければならない (E0505)。
  型の中の式は型検査で評価されるので、止まらない関数や `panic` する関数は型検査を止めたり、意味のない型を作ったりする。
- 証明として使う関数 (FEAT-0231 の等式の証明) も全域でなければならない (同節で定める)。

### 1.5 診断

| コード | 内容 |
|--------|------|
| E0502 | 終了性を示せない。再帰で小さくなる引数がない、または尺度が減らない (反例を表示)。尺度の注釈を促す |
| E0504 | `total` と宣言した関数が全域でない (`panic`、`partial` な関数、全域でない関数、正でない型を使う)。理由を呼び出しの連鎖で示す |
| E0505 | 型の中で全域でない関数を使った |

`partial` な関数ではない `covering` の関数で場合が欠けていると、従来どおり E1230 (`partial` と宣言する案内を添える)。

## 2. 等式と証明 (FEAT-0231)

```
total
appendNilRight : (xs : List a) -> append xs [] = xs
appendNilRight [] = Refl
appendNilRight (x :: xs) = rewrite appendNilRight xs in Refl
```

### 2.1 命題等価

- `x = y` は Prelude の型 `Equal x y` の略記である。

  ```
  data Equal : {a : Type} -> (0 x : a) -> (0 y : a) -> Type where
    Refl : Equal x x
  ```

- `=` は演算子 (`+`、`::`、`==` など) より弱く、`->` より強く結合する (`plus n Z + 0 = n -> n = n` は `((plus n Z + 0) = n) -> (n = n)`)。
  結合性はなく、`a = b = c` は書けない。`let x : T = e` の注釈の中では `=` は区切りであり、注釈の型に等式を書くときは括弧で囲む。
- `Refl : x = x` が唯一の構成子である。型検査は両辺を評価して比べるので、`plus (S Z) (S Z) = S (S Z)` は `Refl` で示せる。
- Prelude の全域な関数: `sym : x = y -> y = x`、`trans : x = y -> y = z -> x = z`、`cong : (f : a -> b) -> x = y -> f x = f y`、`absurd : Void -> a`、`soTrue : So b -> b = True`。
- Prelude の型: `data Void` (構成子なし)、`data Dec p = Yes p | No (p -> Void)` (決定可能な命題)、`data So : Bool -> Type where Oh : So True` (真であることの証明)。

### 2.2 `rewrite`

- `rewrite p in e`: `p : x = y` のとき、ゴール (期待される型) に現れる `x` をすべて `y` に置き換えた型で `e` を検査する。
- ゴールは、定義を **case で止まらない限り** 1 段ずつ展開した形で探す (`rev (x :: xs)` は `append (rev xs) [x]` として見る)。`x` も同じ形にして比べる。
- 期待される型が必要なので、`rewrite` は検査の位置 (型の分かる場所) でだけ使える。
- Prelude のプリミティブ `primRewrite : {a : Type} -> (0 p : a -> LType) -> (0 x : a) -> (0 y : a) -> (0 eq : x = y) -> (1 v : p y) -> p x` に展開され (線形の値も書き換えられる)、
  実行時には `e` そのものになる (証明 `p` は消える)。

### 2.3 `with`

```
emptyOrNot : (xs : List a) -> Either (isEmpty xs = True) (isEmpty xs = False)
emptyOrNot xs = with isEmpty xs of
  True => Left Refl
  False => Right Refl
```

- `with e of alts` は `case e of alts` と同じく `e` で分岐するが、**ゴールに現れる `e` を各選択肢のパターンに置き換えた型** で選択肢を検査する。
  上の例では、`True` の選択肢のゴールは `Either (True = True) (True = False)` になる。
- `e` は共有可能な値でなければならない (線形の値は E1252。`case` を使う)。

### 2.4 証明の全域性と消去

- 結果の型が等式か `Void` である関数を **証明** と呼ぶ。証明は全域でなければならない (E0506)。
  証明は多重度 0 で使われ実行時に消えるので、止まらない関数や `panic` する関数を証明として認めると、偽の命題が「示せて」しまう。
- 証明・`So` などの多重度 0 の引数、`rewrite` は実行時に何も残さない。
  `tests/cirkalang/run/v004/proof_erased.cirka` (証明あり) と `proof_none.cirka` (証明なし) は `-O2` で同一の MIR になることをテストで確かめる。
  このため Core の最適化は、構成子の分かっている値の型変換 (`cast`) を構成子の分かった値として扱い、遅延のままにできる (ADR-078)。

### 2.5 `core` のライブラリ

| モジュール | 内容 |
|------------|------|
| `Data.Nat` | `mult`、`minus`、`natFromInt`、`plusZeroRight`、`plusSuccRight`、`plusComm`、`plusAssoc`、`succInjective`、`zeroNotSucc`、`decEq`、`LTE` (`lteRefl`、`lteSucc`、`isLTE`) |
| `Data.Fin` | `Fin n` (`FZ` / `FS`、`n` 未満の自然数)、`finToNat`、`finToInt`、`last`、`finZAbsurd`、`natToFin` |
| `Data.Vect` | `Vect n a` (`VNil` / `VCons`)、`length`、`lengthCorrect`、`head`、`tail`、`index` (`Fin n` で範囲外がない)、`replaceAt`、`append`、`map`、`zipWith`、`foldl`、`replicate`、`toList`、`fromList`、`reverse` |

ライブラリの関数は Z3 なしで全域性を示せるように書く (尺度が要る `natFromInt` は `covering`)。

### 2.6 診断

| コード | 内容 |
|--------|------|
| E0506 | 証明 (結果が等式か `Void` の関数) が全域でない |
| E1250 | `rewrite` の証明が等式でない |
| E1251 | `rewrite` で置き換える式がゴールに現れない (ゴールを表示) |
| E1252 | `with` で線形の値を調べた |

### 2.7 制限

- 型の中のトレイトのメソッド・多相なリテラル (`So (d /= 0)`) は、インスタンスが決まるまで評価されないため、等式の両辺で簡約されないことがある。単相の関数を使う。
- 型の水準の関数の名前は小文字で始める (大文字の名前は構成子・型として解決される)。
