# 04. メモリモデル (共通基盤)

aCHC と CirkaLang で共通のメモリモデル。違いは評価戦略だけで、aCHC は遅延 (サンクが多い)、CirkaLang は正格 (`Lazy a` のみサンク)。

トレーシングGCを使わずに、Haskell の自由な共有と遅延評価、そして Rust 並みの資源管理を両立させる。

## 1. 値の分類

| 分類 | 判定 | 置き場所 | 解放 |
|------|------|----------|------|
| 非ボックス値 | `Int#`, `Double#` 等、および正格性解析で unbox された値 | レジスタ/スタック | 不要 |
| 静的値 | トップレベルの定数・引数なし構築子 (`Nothing`, `[]`) | `.rodata`/`.data` | 不要 (RC=0 不死) |
| 所有値 | 型が LType (`Unique a`, 資源型) | ヒープ (またはスタック) | 消費点で解放/再利用。RC 操作なし |
| 共有値 | 型が Type の boxed 値 | ヒープ | Perceus 精密 RC |
| リージョン値 | `allocIn` で確保 | アリーナ | リージョン終了時に一括 |
| エスケープしない値 | エスケープ解析で判明 (FEAT-0042) | スタック | スコープ終了 |

## 2. 共有値: Perceus 精密参照カウント

Koka / Lean 4 で実績のある方式を採用する。

### 2.1 dup/drop の挿入 (MIR 上)

- 変数は **所有 (owned)** 参照として扱い、各変数は「最後の使用」で所有権を手放す。
- 2回以上使う変数は、最後以外の使用の前に `dup x`(RC+1)。
- 使われない分岐では、分岐の先頭で `drop x`(RC-1、0 なら解放)。
- 構築子でマッチした後、フィールドを使う場合はフィールドを `dup` してから親を `drop`(親が解放されるなら打ち消し合う: **drop 特殊化**)。

結果として、オブジェクトは **到達不能になった瞬間に解放される**(GC のような遅延がない)。

### 2.2 借用推論 (borrowed parameters)

関数引数が関数内で消費も保存もされない場合、その引数を **借用引数** とし、呼び出し側が所有権を保持する。
これにより `dup`/`drop` のペアを大幅に削減する(Lean 4 の borrow inference)。
推論は関数呼び出しグラフ上の不動点計算。エクスポートされない関数のみ対象とし、外部 ABI は常に owned。
推論は dup/drop の挿入より前に行う (Lean 4 と同じ順序)。`main`・グローバルの初期化関数・クロージャ関数の捕捉されない引数は常に owned。
所有値の引数を末尾呼び出しで渡す先の引数は owned にする (借用引数に渡すと呼び出し後に drop が必要になり、末尾呼び出しが失われるため)。

不動点の後、借用のまま残った引数のうち **借用しても得のないもの** を owned に戻す (FEAT-0083、ADR-085。Koka の既定は owned)。
すべての呼び出しが「所有値の最後の使用」か「分解するだけの所有値から取り出したフィールド (呼び出しの後は使わない)」を渡すなら、
借用で減る `dup` はなく、呼び出し側は呼び出しの後に値を解放する 2 度目の走査をするだけになる。owned にすれば呼び出された側が読みながら解放する
(binary-trees の `check`: 借用のままだと木を読む走査と解放する走査が別になり 1.25 s → owned で 1.12 s)。
呼び出し元の引数で、この規則で owned になるものも所有値とみなす (自分の引数のフィールドを渡す再帰呼び出し。候補から外れるものを除いていく最大不動点)。
サンクの関数の引数 (捕捉変数) は、評価が一度きりで評価がサンクから移動する (§4) ので、手放されるものとみなす。
文字列リテラル (静的オブジェクト) を渡す呼び出しがあれば借用のまま (借用なら費用がなく、owned だと呼び出された側が毎回静的オブジェクトの `drop` を検査する。string-split では文字列の連結・検索の関数が owned になり命令数が 8% 増えた)。
直接の呼び出しのない関数・クロージャ関数・固定の関数は対象外。

### 2.3 再利用解析 (reuse / FBIP)

`case xs of (y:ys) -> ... (f y : g ys)` のように、マッチしたセルと同じサイズのセルを確保する場合、
`drop xs` を `drop_reuse xs`(RC==1 なら解放せずメモリを再利用トークンとして返す)に置き換え、
新しいセルの確保に使う。純粋関数型のまま `map` などが **in-place 更新** になる(Functional But In-Place)。
LType の値は RC==1 が静的に保証されるので、再利用は実行時チェックなしで行う。

実装 (FEAT-0022, `cirka-mir::reuse`):

- dup/drop 挿入では、どこかで消費される射影 (フィールド) を射影の直後に `dup` して独立した所有値にする (Koka の順序)。
  これで親はマッチ直後に死に、`drop_reuse` の時点で子の RC が 1 のまま保たれる (再帰呼び出し先でも再利用できる)。
- 再利用: 同じブロック内で、構築子が既知の `drop x` の後に同じサイズの (引数ありの) `alloc` があれば対にする。
- 融合: 同じブロック内の `dup x` と後続の `drop x` を、間で x が消費されなければ打ち消す (射影は隣接時のみ)。
- フィールドの `dup` を親の `drop` / `drop_reuse` の直前まで下げ、バックエンドで drop 特殊化する ([07-backend.md](07-backend.md) §2)。

### 2.4 スレッド間共有

- 既定では RC は **非アトミック**。
- 値が別スレッドから見えるようになる時点 (`forkIO` の捕捉、`MVar` への格納) で、その値から到達可能な全オブジェクトを
  **共有マーク**(RC を負数に)し、以後アトミック操作を使う(Lean 4 方式)。単一スレッドのプログラムはアトミック命令のコストを払わない。

### 2.5 解放の実装

- 長いリストを再帰的に解放するとスタックが溢れるため、解放は **明示的なワークリスト** で反復的に行う
  (解放対象オブジェクトのフィールド領域を連結リストに流用し、追加メモリなし)。
- 型ごとの解放関数は不要: オブジェクトヘッダに「ポインタフィールド数」を持ち、汎用の解放ルーチンで扱う([05-runtime.md](05-runtime.md))。

## 3. 所有値 (LType)

- 生成: 通常どおりヒープに確保(RC フィールドは 1 のまま使わない)。
- 消費: パターンマッチで分解したら、そのセルは即座に解放または再利用(静的に決定)。
- `freeze`: 何もしない(RC=1 から共有値として数え始める)。⇒ O(1)。
- `Drop`/`Release`: 型検査器が挿入位置を決定([03-type-system.md](03-type-system.md) §3)。
- MIR では所有値の変数に `dup` が現れないことを検証器で確認する。

## 4. 遅延評価とサンク

- サンクは「コードポインタ + 捕捉変数」を持つヒープオブジェクトで、**RC 管理される共有値**。
- `force` 時:
  1. サンクを **ブラックホール** にする(再入したら `<<loop>>` エラー)。
  2. コードを実行して値を得る。サンクは一度しか評価されないので、コードが所有権を取る (owned の) 捕捉変数は
     dup せずにサンクから **移動** する (欄を null にする)。借用 (borrowed) の捕捉変数はそのまま渡す (ADR-040)。
  3. 残った捕捉変数を drop し、サンクを **間接参照 (IND)** に書き換える(値が小さい非ボックス値なら値を直接埋め込む)。
- 移動により、サンクに捕捉された一意な値 (`Unique (Array e)` など) は評価中も RC==1 のままで、in-place 更新が
  コピーにならない (FEAT-0123)。
- IND は dup/drop の際に辿って短絡する。RC==1 の IND は、参照元が値を直接指すように置換して解放する。
- サンクを減らす施策: 正格性解析と strictify・λ持ち上げ・辞書の特殊化 (FEAT-0112、06-ir.md §1.5)、`Strict`/`StrictData`・bang パターン、LType の正格規則、`seq`/`$!`。
  - bang パターンの `let !p = e` / `where !p = e` は、`p` の全体を `let!` で先に評価する。
  - `StrictData`: 印のないフィールドは正格。`~T` で遅延にできる。
  - `Strict`: `StrictData` に加え、関数・ラムダの引数、`case` の選択肢、局所の `let`/`where` の束縛 (トップレベルは除く) が、`~` の印がなければ正格 (最上位のパターンだけ。GHC と同じ)。
- サンクの評価回数は `CIRKA_STATS=1` の `forced=` で数える。
- **LType の値はサンクに捕捉されない**(型規則で保証)ため、線形資源の解放タイミングは決定的。

## 5. 循環

純粋で不変なデータは、正格評価では循環を作れない。循環が生じるのは次の3つだけ:

| 原因 | 例 | 対処 |
|------|----|------|
| 再帰関数のクロージャ | `let go n = ... go (n-1) ...` | 再帰グループ内の自己参照は **数えない参照** として扱う(関数グループはひとつの環境を共有し、環境から自分自身への参照を RC 対象外にする)。リークしない |
| 再帰的な値束縛 (knot-tying) | `let xs = 1 : xs` | 静的に検出して警告 W0401。`--cycles=collect` を使うよう案内 (トップレベルの値は CAF で不死なので循環してもリークしない。`cirka-base` の `fix` は共有しない定義 `fix f = f (fix f)`) |
| 可変参照 | `IORef` が自分を含む構造を指す | 静的検出は困難。`IORef` を「循環候補」として記録し、`--cycles=collect` 時のみ回収 |

CirkaLang は正格なので再帰的な値束縛は `Lazy` を介した場合しか書けず、循環の原因は `Lazy` の自己参照と可変参照に限られる (FEAT-0222)。

`--cycles` (aCHC。`achc.toml` の `[compiler] cycles`、コマンドラインが優先) の既定は `warn`(リークは安全。Rust の `Rc` と同じ立場)。
`error` は W0401 をエラーにし、`collect` は警告を出さずに実行時に回収する。

`--cycles=collect`: **試行削除 (trial deletion, Bacon–Rajan)** による局所的な循環回収器を有効にする。
対象は「循環候補」(再帰的値束縛で作られたサンク・`IORef`/`MVar`)のみで、RC が 0 にならず減少したときに候補バッファに入れ、
一定量たまったらその部分グラフだけを走査する。プログラム全体を走査するトレーシングGCではない。

実装 (FEAT-0126、ADR-043):

- **根の記録**: RC の減少のたびに調べる (Bacon–Rajan の purple) 代わりに、循環を作りうるオブジェクトを **作った時点で** 根の
  バッファに入れる (値の `letrec` のサンクは MIR の `cycle_candidate`、`MUTVAR` は `cirka_mutvar_new`)。バッファは根ごとに参照を 1 つ持つ
  ので、根が回収の前に解放されてダングリングになることはない。drop の高速経路は変わらない (`--cycles=collect` でないプログラムの
  コストは 0、有効なときも記録の呼び出しだけ)。
- **回収**: 根が 1024 個 (前回の生存数の 2 倍と大きい方) たまったときと終了時に、試行削除を行う:
  バッファの参照を外す → 根から到達できる部分グラフの内部参照を RC から引く (gray) → RC が正のものとそこから到達できるものは
  外部から参照されている (black、RC を戻す) → 残り (white) を解放する。生き残った根はバッファに残る (後で死んだときに回収するため)。
  終了時は回収のあとで残った根の参照を外す (リーク検査の前)。
- 色は回収中だけヘッダの `kind` の上位 2 ビットに置く。静的 (RC 0)・共有 (RC < 0) のオブジェクトは対象外。走査は明示的なスタックで行う
  (長いリストでもスタックを使わない)。
- 回収は根の記録の中で同期的に走る。そのとき実行中のコードが持つ参照はすべて RC に数えられている (Perceus。借用は所有者の参照が数える)
  ので、使用中のオブジェクトは black になる。評価中のサンク (BLACKHOLE) の移動済みの捕捉は null で、走査で飛ばす。
- MIR インタプリタも同じアルゴリズムで回収する (実行テストのリーク検査が両方で通る)。

## 6. リージョン

- アリーナはページ単位のバンプアロケータ。`withRegion` 終了時に全ページを返す。
- アリーナが配るのは **セル** (8 バイトのスロット) で、セルはヒープ値への参照を 1 つ持つ (dup)。セルの集まりがリージョンの
  「外部参照リスト」で、終了時にまとめて drop する。
- セルは **整数 (アドレス) で指す** (`In r a` / `RefIn r a` の表現)。RC の対象外なので、値どうしがセルを通して任意の形 (循環を含む)
  で参照し合っても RC の循環にならず、リージョンの終了でまとめて解放される。参照外しは `RIO r` の中だけ (型で保証) なので、
  リージョンの外に残った古いアドレスは使われない (使われなければ無害)。
- リージョンは `FOREIGN` オブジェクト (RC 対象) で、ポインタがアリーナの状態、解放関数がアリーナの後始末。`withRegion` が
  終了時に後始末し (`cirka_region_free`)、されなかった場合も最後の参照がなくなったときに後始末される。後始末はページを先に
  切り離すので、セルの drop がリージョン自身を解放しても二重には行わない。
- 実装 (FEAT-0049 / FEAT-0127、ADR-044): ランタイムの `region.rs` (4 KiB のページに 510 セル)、MIR インタプリタは
  セルを `FOREIGN` オブジェクトのフィールドとして模倣する。MIR の命令は追加せず、`extern` で呼ぶ。

## 7. スタック

- Haskell のコードは深い非末尾再帰を行う(`foldr` 等)。メインスレッドは大きなスタック(既定 512MiB、`CIRKA_STACK_SIZE`)の
  専用スレッドで実行し、末尾にガードページを置く。オーバーフロー時は `stack overflow` を表示して終了コード 2。
- 末尾呼び出しは常に保証 ([07-backend.md](07-backend.md))。

## 8. 安全性の検証手段

| 手段 | 検出対象 |
|------|----------|
| MIR 所有権検証器 | dup/drop の不整合 (静的) |
| debug ランタイム | オブジェクトごとのマジック値・RC 整合性・二重解放の即時検出、終了時のリーク一覧 (`CIRKA_LEAK_CHECK=1`) |
| `CIRKA_ALLOC=system` + valgrind / ASan | 解放後使用・範囲外アクセス |
| MIR インタプリタ | 確保/解放回数を数え、コード生成結果と比較 |
