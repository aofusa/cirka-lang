# 16. 性能方針: ゼロコスト抽象化と最適化

FEAT-0132 のレビューで決めた方針 (ADR-047)。フロントエンドの表現力 (柔軟な型・借用・証明) と安全性を保ったまま、
**生成コードの性能では GHC -O2 と Rust の両方を上回る** ことを目指す。

## 1. 目標

| 時期 | 目標 |
|------|------|
| 第一段階の通過点 | G3: CirkaLang と aCHC の `.chs` は主要ベンチで Rust の 1.5 倍以内 (v0.0.3)。素の `.hs` は GHC -O2 と同等 |
| 第二段階 (v0.1.0 〜) | CirkaLang と `.chs` は主要ベンチで **Rust (release) 以上の速さ**、素の `.hs` は **GHC -O2 以上の速さ** |

- 各版のリリースと評価レポートで、ベンチの Rust / GHC との比を記録する。目標に届かないベンチは、差の原因を調べてチケットにする
  (原因を特定しないまま「最適化器の成熟度」で済ませない)。
- 安全性は性能のために妥協しない。安全でない操作で速くするのではなく、**安全であることの証拠 (型・所有権・証明) を最適化に使って速くする**。

### 1.1 Rust を上回る根拠

Rust は安全性の一部を実行時の検査で担保し、最適化はクレート単位で行う。CirkaLang は次の情報を静的に持つので、Rust より多くの最適化ができる。

| 情報 | Rust | CirkaLang | 効く最適化 |
|------|------|-----------|------------|
| 純粋性 | 関数の副作用は一般に不明 | 型で分かる (`IO` 以外は純粋) | 共通部分式除去・ループ不変式の移動・呼び出しの並べ替えと削除 |
| 別名の不在 | `&mut` のみ | 一意性・線形性・借用から推論 (すべての一意な値) | `noalias`、破壊的更新、ベクトル化 |
| 値の範囲・添字の正しさ | 境界検査が実行時に残る (除くには `unsafe`) | 洗練型と証明で静的に保証 | 境界検査・オーバーフロー検査・ゼロ除算検査の除去、`!range` |
| プログラム全体 | クレート単位 (LTO は任意) | 全体プログラムで特殊化 | 特殊化・インライン化・ランタイムの高速経路のインライン化 |
| 確保の再利用 | 手で書く | Perceus の再利用 (FBIP) が自動 | 確保・解放の削除 |
| 中間データ | イテレータを手で組む | 融合をコンパイラが行う | 中間リスト・配列の削除 |

## 2. ゼロコスト抽象化の規則

**抽象を使って書いたコードと、それを手で展開したコードは、同じ機械語になる。** 抽象のために実行時のコストを払わない。

| 抽象 | 実行時に消える仕組み | 状態 |
|------|----------------------|------|
| 型・証明・多重度 0 の引数 | TT → Core の消去 | 済 (FEAT-0204) |
| newtype・`Borrow`・`IO` | `cast` (表現が同一)。状態トークンの worker (ADR-046) | 済 (BUG-0011) |
| 型クラス・トレイト | 全体プログラムでの特殊化 (ADR-032/033) | aCHC は済。CirkaLang は FEAT-0210 |
| 高階関数・クロージャ | インライン化・特殊化・λ 持ち上げ | 済 (FEAT-0041, 0056)。残るものは FEAT-0061 |
| 借用 | 実行時の表現なし (ポインタだけ、RC 操作なし) | aCHC は済 (FEAT-0021)。CirkaLang は FEAT-0220 |
| 一意性・線形性 | 破壊的更新、`noalias` | 更新は済 (FEAT-0022)。`noalias` は FEAT-0058 |
| タプル・`Maybe`/`Option`・`Result` の返り値 | worker/wrapper (CPR)、IO の結果の unboxing、複数の値の返却 | 済 (FEAT-0056, 0064, 0065)。IO の結果は FEAT-0057 |
| 多相な配列 | 要素型ごとの単相化 (箱なしの格納) | FEAT-0059 |
| リスト・イテレータの連鎖 | 融合 | FEAT-0055 |
| 洗練型・契約 | 証明済みの検査を除去 | FEAT-0234 |
| 効果・能力 | 証拠渡しの後にインライン化 | v0.0.7 (FEAT-0261) で設計 |

**ゼロコストの回帰テスト**: 抽象版と手書き版の組を `tests/` に置き、確保回数 (`CIRKA_STATS`、`-- max-allocs`) と最適化後の IR の大きさが
一致することを確かめる (FEAT-0061 でハーネスに追加する)。ゼロコストでなくなる変更はテストで検出する。

## 3. 中間表現に載せる最適化のヒント

フロントエンドが検査済みの事実を、Core・MIR に注釈として残し、LLVM の属性・メタデータまで運ぶ。

| 事実 | 出所 | Core / MIR での表現 | LLVM での利用 |
|------|------|---------------------|---------------|
| 参照は null でなく、ヘッダの分は読める | すべてのヒープ参照 | 型 (`ptr` の値) | `nonnull` `dereferenceable(8)` `align 8` |
| 借用 (書き込まず・脱出しない) | 借用推論・借用の型 | MIR の borrowed 引数 | `readonly` `nocapture` |
| 一意 (他に参照がない) | 一意性・線形性・再利用解析 | MIR の一意な値 | `noalias` |
| オブジェクトのヘッダとフィールドは別名にならない | ランタイムの表現 | 確保・load/store の種類 | `!tbaa` |
| 構築後のフィールドは変わらない (破壊的更新を除く) | 純粋性 | フィールドの load | `!invariant.load` (一意な更新のない値) |
| タグ・整数の値域 | データ型の構築子数、洗練型 | `switch` の対象・洗練型の述語 | `!range`、`llvm.assume` (タグへの `!range` は mandelbrot を遅くしたので使わない: FEAT-0058) |
| 分岐の頻度 | panic の経路、RC の遅い経路 | `panic`・ランタイム呼び出し | `cold`、分岐の重み (`!prof`) |
| 例外を投げない・必ず返る | panic=abort の間のすべての関数、`total` | 関数の属性 | `nounwind`、`willreturn` (全域なもの) |
| 境界内の添字 | 証明・洗練型 | 検査の除去 | 境界検査なしの load/store (ベクトル化が効く) |

- ヒントは **検査済みの事実からだけ** 作る。誤ったヒントは未定義動作になるので、MIR 検証器がヒントと MIR の整合を確かめ、
  `--runtime=debug` では `llvm.assume` を実行時の検査に置き換える。
- ヒントは共通基盤の注釈として定義する。フロントエンド固有の概念 (aCHC の `LType`、CirkaLang の洗練型) は、注釈に変換してから渡す
  (不変の設計原則 6)。

## 4. 最適化の一覧

| 層 | 最適化 | 状態 |
|----|--------|------|
| Core | 簡約・インライン化・case-of-case・既知の構築子 | 済 (FEAT-0033, 0041) |
| Core | 型クラスの特殊化・辞書の浮上 | 済 (FEAT-0041, BUG-0011) |
| Core | 正格性解析・worker/wrapper・値渡しの引数の unboxing | 済 (FEAT-0041, 0056) |
| Core | IO の状態トークン | 済 (BUG-0011、ADR-046) |
| Core | IO の結果の unboxing | FEAT-0057 |
| Core | インライン化した読み出しの組の除去 (`let!` の連鎖を通す case の移動)、float-in の拡張 | 済 (FEAT-0064) |
| Core / MIR / LLVM | 複数の値の返却 (組・`Ur` の結果の CPR) | 済 (FEAT-0065) |
| Core / MIR / LLVM | 単一選択肢の `case` の `let!` からの移動、評価済みで渡される引数の force の省略、自己末尾呼び出しのループ化 | 済 (FEAT-0066) |
| Core | リスト融合 | FEAT-0055 |
| Core | 配列要素の単相化 (`UElem`) | FEAT-0059 |
| Core | 静的な関数引数での特殊化 (関数を受け取る再帰関数の写し。高階関数の箱を消す) | 済 (FEAT-0061) |
| Core | 共通部分式除去・ループ不変式の移動・構築子による特殊化 (SpecConstr)・ゼロコストの回帰テスト | FEAT-0061 |
| MIR | Perceus・借用推論・drop 特殊化・再利用 (FBIP) | 済 (FEAT-0020〜0022) |
| MIR | エスケープ解析とスタック割り当て | FEAT-0042 |
| LLVM | 属性・メタデータ (§3): `nounwind`・`!tbaa`・確保の `noalias`・panic の `cold` | 済 (FEAT-0058) |
| Core / LLVM | 数値ループ: libm の組み込み関数、一意性検査の高速経路のインライン化、要素の TBAA、冗長な一意性検査の除去 | 済 (FEAT-0063) |
| MIR | 一意な配列のループの特殊化 (検査済みの配列を渡す自己末尾呼び出しを、一意性検査を除いた関数へ向ける) | 済 (FEAT-0067) |
| Core / ランタイム | 配列の作成: 遅い段階の worker/wrapper (`$w` の再分割)、`newArray` の初期化の省略、`calloc` | 済 (FEAT-0068) |
| MIR / LLVM | 一意性・再利用トークンの型を MIR に持たせ、引数に `nonnull`・`noalias`・`readonly` を付ける | FEAT-0062 |
| LLVM | ランタイムの高速経路のインライン化 (ランタイムを bitcode でも出力し LTO) | FEAT-0060 |
| ランタイム | アロケータの改善 | FEAT-0051 |
| 検証 | 証明に基づく実行時検査の除去 | FEAT-0234 |

新しい最適化は、効くベンチと計測値をチケットに記録してから入れる。
